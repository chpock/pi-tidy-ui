# Architecture

Pi Toolview changes interactive terminal presentation, not tool execution or conversation data. Pi loads `src/index.ts` directly as a TypeScript extension. Runtime host libraries are wildcard peer dependencies; development copies are pinned to Pi/pi-tui 1.0.0. They are not bundled or privately imported.

For user-facing behavior and controls, start with the [README](../README.md). Exact presentation rules belong to the eight linked specifications below; this document describes their common implementation boundaries.

## Modules and dependencies

| Module | Responsibility |
| --- | --- |
| `src/index.ts` | The sole live-host adapter, presentation selection, compact summaries, transcript separation, normalized tool/editor mouse forwarding, invalidation, animation and extension lifecycle |
| `src/summary-args.ts` | Pure bounded argument previews, edit/write path-only formatting, field priority, Unicode/control handling and display-only secret masking |
| `src/bash-card.ts` | Bash command/comments, bounded collapsed output preview, available expanded output, metadata-derived footer and exact timeout-tail display convention |
| `src/file-card.ts` | Shared edit/write saved-source validation/classification, highlighting, context projection, numbered plain/unified/split content and validation-only measurement |
| `src/user-card.ts` | Reframing native Markdown output and terminal navigation zones without reparsing user text |
| `src/queued-card.ts` | Plain queued-message cards, badge/hint paint and first-to-last adaptive row selection |
| `src/plain-text.ts` | Shared Bash/queued-text control sanitization and grapheme/terminal-column wrapping |
| `src/editor-card.ts` | Pure native-editor row projection with Editor padding as exterior margins, fixed inner gaps, cursor preservation and unframed autocomplete alignment |
| `src/editor-status.ts` | Pure below-editor metadata/cwd/branch fitting and half-block painting; no operation lifecycle or I/O |
| `src/terminal-colors.ts` | Independent fixed-theme metadata resolution, terminal-default ownership, generation-checked reports and latest local concrete RGB; no repeating timer or native theme mutation |
| `src/footer.ts` | Pure session-usage aggregation, bounded ten-report inverse CH gauge, context/source-flag formatting, whole-status packing and one latest footer layout; no private host access or I/O |
| `src/git-branch.ts` | Event-driven asynchronous Git discovery/branch snapshot and metadata watches; no UI or editor ownership |
| `src/card-frame.ts` | Pure geometry, caller-supplied frame paint and panel hit bounds |
| `src/card-theme.ts` | Active-theme tool-panel paint |
| `src/render-cache.ts` | Weak rendered-layout accounting; component state owns retained values, without budget/recency eviction |

The adapter passes presentation data, active-theme callbacks and effective Pi Output padding to transcript presenters. Public effective settings supply every transcript presenter's exterior padding; native user-component padding independently supplies only the native Markdown width/strip geometry. The existing Container observer scopes one primitive settings snapshot to each normal transcript pass and clears it in `finally`, avoiding settings cloning per tool/predecessor without another hook or timer. Direct component/mouse visits read the live setting. Padding belongs in the latest tool-layout signature and file measurement/click geometry; it is independent of Editor padding and footer ownership. Framed presenters share the frame; the session footer uses separate full-width rows. The frame does not know about tool names, execution, expansion or private host classes. Only the adapter owns component hooks and weak per-component state. There is no second extension, dynamic presenter registry, external common package or duplicate input adapter.

## Host integration and lifecycle

1. On `session_start` in TUI mode, a temporary empty public widget factory supplies Pi's stable TUI reference. The widget is removed immediately and contributes no rows.
2. The adapter validates the shared host `Container` and the inspected tool/user/editor component contracts, then visits the existing tree. Observing `Container.addChild` also covers future calls and prebuilt history subtrees. Owned `removeChild`/`clear` wrappers release removed subtrees' custom rows immediately and stop detached compact animation, without deleting native component contents.
3. Tool prototypes receive rendering and normalized mouse wrappers. Native `updateArgs`, `updateResult`, `setExpanded`, `invalidate` and the UI notification `markExecutionStarted` continue to execute; wrappers manage custom layout/animation state. Ordinary user-message prototypes receive rendering and `rebuild`/`setOutputPad`/`invalidate` wrappers. Plain stock `CustomEditor` receives presentation/border and normalized mouse wrappers. Owned `Container.render`/`Spacer.render` observers consume normal upper-widget height and native-status visibility without extra renders. The same Container observer projects a verified native pending-message prefix into queued cards; public terminal height supplies its soft display budget, without changing queue ownership. The existing normal-document boundary also scopes Output padding and one spinner phase sample; a successful return postpones the shared animation fallback. A guarded public `embedWorkingStatus` accessor plus same-default public rebinding asks Pi to use its native activity container; the redundant synchronous self-transfer is suppressed to retain the complete draft. Keyboard input remains native, with no editor factory replacement.
4. A public `setFooter` factory mounts session statistics and shared extension statuses only with the recognized, still-owned stock input. Ownership eligibility survives temporary native selectors, but foreign editor factories/method owners keep or restore the native footer. Restoration is coalesced after measurement; explicit on with an eligible editor reinstalls the footer, never automatic foreign-footer takeover. Public disposal records a later owner; restoring our slot cannot erase it. Numeric/context snapshots are keyed by session/model/leaf and semantic events, not by repeated history scans. Off/on/reload handle both presentations.
5. Global off and shutdown also release owned terminal defaults and remove their zero-row observer/exit listener. Presentation off, failure and shutdown stop Toolview's compact execution clock, remove its status widget, release transcript and footer layouts and restore owned descriptors; the native activity indicator remains Pi-owned. Restoration checks that Toolview still owns each hook and does not overwrite a later extension's replacement. On re-enablement, existing and future components are covered again. Reload creates a fresh runtime.

This integration deliberately depends on inspected private component shapes, while obtaining host classes/functions through public imports. It does not import an internal component class from a second package location. Incompatible required contracts or rendering exceptions disable Toolview with a warning and restore native rendering. Optional pending-card/upper-widget shape guards instead leave the affected block native; supported-host positive-activation tests must detect contract drift.

The stable TUI reference survives native fullscreen/regular renderer replacement. Public method/child access is sufficient for component integration; terminal synchronization additionally reads one guarded boolean renderer field for native appearance tracking, without wrapping its setter or any query/scheme API; no receiver-capture probe, raw input observer, private `handleViewportInput` wrapper or input-hook migration is used. Pi retains focus, selection and terminal mouse processing. Toolview handles normalized tool clicks and forwards stock-editor normalized mouse coordinates after translating its frame geometry; user cards add no mouse handler. Regular mode uses terminal-owned mouse handling, so expansion there uses native keyboard controls.

Persistent prototype wrappers are constructed in prototype-only factory scopes, not in an installer scope containing a component parameter. Otherwise a shared V8 closure context can retain the first installer even when all explicit component maps are weak. Ownership tests must collect the first installer while the adapter remains active, including an executing installer while another call keeps the clock running.

## Presentation selection

Selection is based on the current lifecycle and safeguards, not output size:

| Presentation | Default routing |
| --- | --- |
| Compact summary | Collapsed text-only tools other than native-card defaults; also incomplete/partial/failed `edit`/`write` calls |
| Bash frame | Exact `bash` with displayable command/context, collapsed or expanded |
| Edit diff frame | Final successful exact `edit` with a path and supported persisted diff metadata |
| Edit inline title/native fallback | Successful `edit` without diff metadata / with malformed or unsupported metadata |
| Write frame | Final successful exact `write`: saved changes or submitted source, classified by available metadata; malformed metadata stays native |
| Native tool presentation | `powershell`, ordinary expanded calls, images, intentional hiding and explicit native opt-outs |
| User frame | Compatible ordinary native user messages, using the original Markdown renderer |
| Queued frame | Recognized native Steering/Follow-up previews in the pending slot above the editor, never prematurely in history |
| Main editor frame and below-editor status widget | Exactly recognized stock editor with no competing public factory, using its existing editing engine |

Exact-name `--toolview-card` adds native-card policy; naming `bash`, `edit` or `write` opts out of its custom presentation. `--toolview-compact` wins over that policy, but not over expansion, images or native hiding. The file-success condition is shared by render, spacing, mouse and animation teardown: partial errors are still running summaries, final errors are wholly error-colored summaries, and only final non-errors can enter the file presenter.

### Native visibility

A self-shell renderer can intentionally return zero rows even with `hideComponent=false`. Unknown, custom, mixed or replaced renderers therefore retain original rendering at the actual viewport width when visibility must be established. Tool names or schemas alone cannot prove visibility.

One narrow Pi 1.0.0 exception avoids discarded native edit rows. Every visit verifies the `ToolExecutionComponent` contract, the exact stock call/result function pair obtained from public `createEditToolDefinition`, and a current plain call `Box` with stock `render`, `clear` and `addChild` methods. Pi's stock factory can reuse an earlier custom Box, so function identity alone is insufficient. No visibility proof is cached and no native state is changed. Explicit native presentation, expansion, images/hidden guards and malformed fallback still render natively.

## Data and rendering boundaries

- Compact summaries format supplied arguments independently of third-party schemas. The exact `edit`/`write` path-only rule, field priorities, bounded grapheme/container previews, top-level secret masking and control sanitization are display-only; there is no generic payload suppression. Native expansion and saved/model data are not abbreviated or redacted.
- Bash consumes already-returned text and persisted numeric exit/error metadata, never reads output files or reconstructs upstream truncation. Its two approved semantic display exceptions remove at most one exact separated terminal block before wrapping/cutoff: a duplicate of its own metadata-derived final exit footer, or `[command timed out]` followed by `[exit code: 124]` on a final numeric-code-124 result. The latter replaces the generic footer with `[exit code: 124; error: command timed out]`, entirely in the error role and outside the preview budget. Code 124 alone is not a timeout signal. This is a deliberately narrow presentation convention, not producer detection or reliable cause classification: AFT does not persist the timeout reason, and a command printing the same pair is indistinguishable. Partial/interior/unseparated/mismatching text and raw model/session data stay unchanged; see the [Bash contract](bash-card-spec.md).
- Edit consumes persisted `details.patch`/`details.diff`, never input proposals or a file reread. It highlights old/new supplied source independently with Pi's public file-language resolver and highlighter before projecting context. It preserves multiline token state and hunk boundaries. OpenCode supplies the format reference, not an identical syntax engine or screenshot guarantee.
- Write uses compatible saved diff shapes without producer identification; additions-only become plain Created source, additions/context use Edited diff, any removals use Replaced diff, absent/no-change diff uses Wrote submitted content. Created includes existing empty files. Explicit truncation shows submitted content with a warning, not guessed complete changes or final post-format bytes. See the [write contract](write-card-spec.md).
- User cards call the original renderer at the frame's content width plus twice the native horizontal padding, remove only known geometric padding, and relocate OSC 133 zones. Markdown transformations, token styles, links and source text are retained. Native image-protocol rows and impossible tiny-width glyphs fall back at the real width.
- Queued cards read only a guarded own string data field on exact public `TruncatedText` instances, since Pi exposes neither a queue-content getter nor the source via the native one-line render. The already-owned pending-slot Container observer recognizes the complete native message/hint prefix, preserves item order and later components, and feeds frames to the original Container renderer through call-local, exactly restored public child-render overrides without replacing children or touching queues. That native rendering path must run to refresh Pi's mouse geometry and strong child-reference snapshot; bypassing it can retain an old natively rendered queue even after later native clears. Full plain text is retained per native item; a `max(10, floor(terminal.rows / 3))` whole-block budget reduces text first-to-last with caps 5→1, keeping complete metadata and every card even on overflow. The native shortcut is shown once in the last card, not intercepted. Badge background equals the user stripe; parentheses are dim and their content muted. Screen height is public, but final allocated dock height is not: host clipping remains possible. See the [queued-card contract](card-frame-spec.md#queued-message-cards).
- Main editor presentation keeps the same instance and native edit/paste/undo/history engine. Public native padding determines exterior margins for the entire input panel; inner gaps stay one column. The weak rendered state supplies the same geometry snapshot to the metadata/edge widget, so normal native settings renders update both without re-registering widgets. Input projection does not change transcript geometry or control the separately installed [session footer](footer-spec.md). Stock border hooks delimit native text and autocomplete. Pi renders the same activity indicator in its separate native container above the editor and owns all messages/kinds/styles/animation/lifecycle. Same-default rebinding preserves editor identity/state/focus, uses no replacement factory and restores the temporary setter immediately. A public `belowEditor` widget displays current model-name/provider-ID/thinking plus Idle only at idle, a right-aligned cwd/branch block and a half-height bottom edge. The registered widget returns zero rows while public `isShowingAutocomplete()` reports an active native list, then resumes both rows on ordinary renders; no polling or menu lifecycle interception is added. No native status fragment is copied or parsed. Immutable/unknown public placement fields or incompatible main-slot contracts leave input native; SDK positive-activation tests detect drift. One editor-owned unpainted row separates a nonzero-height upper-widget group from the panel; absent/zero-row/lower-only widgets add none. Public managed-child shape, stock spacer output, ownership and measurement width guard the decision, with weak numeric observations and a call-local spacer packet, not widget output/owner retention or private registry/allocation access. Unsupported shapes omit the optional separator; actual SDK/CLI compatibility gates require it to activate on the supported host. Normalized mouse x/y and width/height match native wrapped-input/menu geometry after the zero/one-row prefix; the hardware/IME marker stays native. See the [editor contract](card-frame-spec.md#main-input-editor).
- The Git source asks the Git executable about `ctx.cwd`, strips reported repository-local environment redirects, accepts only named `refs/heads/` results and watches Git-discovered metadata (including available reftable directories), rearming watches at rediscovery instead of trusting same-path inode identity. It maintains one generation-checked snapshot, cancels obsolete child jobs and closes watches at ownership/lifecycle boundaries. Normal completed-operation and filesystem events coalesce refreshes; render only reads/schedules this source, never synchronously runs Git. Directory parsing/abbreviation/coloring is pure and separate from repository validation. No footer provider is captured/replaced, no `.git`/HEAD-format guessing or periodic refresh is introduced. Watch failures degrade to semantic refresh; negative ancestor creation is not promised instantaneous discovery. One-shot event debounce and child deadlines are not persistent animation clocks.
- Session-footer totals retain all native raw usage-bearing records behind false-by-default source flags, rather than only the active branch. The existing aggregation also derives the latest ten primary assistant cache reports, with separate samples for equal percentages and no streaming/redraw additions or auxiliary-usage mixing. Saved raw records restore history without new persistence. Public context/settings supply estimates, maximum, percentage and a disabled-only auto-compaction warning; auth is read only when cost is enabled. Cache graph/CH precede context and its optional auto-off annotation, giving cache information priority under tail clipping. Our entire statistics block and opaque right-aligned producer statuses each stay one row, with ellipsis only beyond a full row and whole-status transfers onto later rows; no native string parsing or usage execution changes. Native activity is not part of this footer. Disposed/replaced footers release their latest numeric/context/layout snapshot, outside transcript accounting groups. See the [footer contract](footer-spec.md).
- Terminal-default synchronization reads only the active theme's raw metadata, outside render, using public sourcePath/name-path information. A guarded read of `terminalColorSchemeNotificationsEnabled` catches native auto mode hidden by project settings or already active at first late load; missing/wrong-type state suspends only this feature. A zero-row public observer follows native invalidation, synchronously releases on eligibility loss and queues fixed-theme reads/application. Native query/subscription/callback behavior is untouched. One latest requested/reported concrete projection repairs RGB calculations without changing Pi's Theme or semantic methods; local off stops application/metadata reads but retains finite profile sampling for cards after release. No repeating timer, extra theme watcher, source-body cache or transcript-retention policy is added. Source errors preserve the last valid complete targets. Reports/exit callbacks are separate weak-only factory closures, including a module-level rejection handler so a pending promise cannot retain the controller through a shared lexical context. See the [terminal-color contract](terminal-colors-spec.md).
- The frame owns geometry and restores enclosing panel paint after child ANSI background/full resets. It never truncates a caller's body or paints exterior margins.

Toolview does not replace tool definitions or execution, rewrite results/session entries, add model requests, change Pi's global themes, reread tool/source files to prepare cards or restyle HTML exports/standalone user shell messages. The terminal-color feature reads active theme metadata and changes the shared terminal's defaults. Native host updates and edit preflight still execute unchanged; their work must not be attributed to Toolview file reads or suppressed to improve counters.

## Cache, separation and animation

Weak tool/user/queued-component state owns one latest layout/signature/accounting group, never a width history. Rendered values are not kept in a global strong recency list: the two `RenderCache` instances track only numbers, presentation kind and weak entry references for `ordinary` (summaries, user/queued cards, headings/native file fallback) and `cards` (Bash/edit/write frames). Neither group has an admission, byte or count limit. Fixed-kind `byKind` statistics attribute memory without retaining owner/tool/source registries. On native removal/clear, the adapter drops affected entries even if removed components are still held elsewhere. Otherwise weak component-state collection releases their rows; `FinalizationRegistry` cleans only dead numeric/weak accounting, not the data. Requested snapshots also prune already-collected entries. Clear/off/failure/shutdown release all entries and weak state. Main input does not join these caches: its rows remain transient and its weak state retains only paint/mouse geometry, numeric status visibility and restorable flag descriptors, not drafts, indicator objects or owner references. The footer already owns one latest row layout and supplies its own on-demand estimate.

Queued entries retain each native item's full prepared card plus up to five ellipsized ending rows; height-only renders select existing strings and allocate the combined output array without wrapping or painting bodies. The pending group holds no second queue or strong owner list. Native rebuild/clear/removal and collection use the same release path; diagnostics identify these ordinary entries as `byKind.queued`.

Body retention excludes outside transcript separators. The adapter records parent/index edges, repairs stale positions lazily, and finds the previous visible sibling. It uses existing row counts or cheap classification: Bash does not format output for spacing; file-card measurement reads an exact retained layout or validates metadata without highlighting/painting/admitting another body. Native/unknown predecessors may still need rendering. Separator and executing-spinner composition can allocate row arrays; unchanged completed summaries without a separator return retained arrays directly.

### Host-driven spinner and fallback

Compact animation separates **which glyph to show** from **whether Toolview needs to request a frame**. Native `Working` already drives whole-document frames, normally every 80 ms; adding an independent periodic timer needlessly schedules more history traversals. The glyph is instead selected from elapsed monotonic time in 100 ms phases, using one adapter-wide epoch and one call-local time sample per normal document pass. Direct component visits use live time. Thus ordinary Pi frames animate every participant without a Toolview tick, and parallel prefixes cannot split phases within a slow pass.

One unreferenced `setTimeout` provides a 100 ms fallback after the last successful document visit. The existing owned public `Container.render` observer rearms it once on successful return. A timeout wake prunes weak running participants, requests one ordinary frame without invalidation, and waits for another successful document visit before rearming. This pending state avoids floods when Pi delays/stops rendering; using a timeout relative to each visit also avoids a fixed interval skipping alternate Toolview-only frames. A generation rejects obsolete callbacks after rearm/stop. Animation callbacks are constructed outside any component-containing installer scope.

**The observation is intentionally a document-layout signal, not terminal-presentation detection.** Supported Pi has no public after-present hook: direct document diagnostics can postpone the fallback too, and downstream rendering/output can still fail or be delayed. Neither private `Working`/Loader timers nor private renderer timestamps/`doRender` are read or wrapped. Toolview does not wrap `requestRender`, write an animation glyph directly to the terminal, throttle host frames or change native activity ownership/lifecycle. Exact 100 ms physical cadence and absence of all host render work are not claimed.

The small weak participant set and recorded attachment edges are pruned on successful document visits as well as timeout wakes: with regular `Working` frames, the timeout may never fire. Argument streaming starts no animation resource; final results, expansion, hidden/native/zero-width transitions, disappearance, owned removal/clear, off, failure and restoration end participation. The last participant clears the deadline and pending/epoch state. Retained logical rows contain no animation phase and are reused in both host-driven and fallback frames. There is no idle cache-maintenance timer. Detailed acceptance rules and real-CLI controls are in the [execution-spinner contract](render-cache-spec.md#execution-spinner).

Cold layouts and actual width/theme changes prepare full required content by design. Warm hits avoid custom formatting/highlighting/wrapping, not all host work: Pi still traverses and assembles its transcript, unknown self renderers retain visibility checks, and native update/preflight/selection work remains. An unchanged live presentation is never discarded because another component needs space. Memory can grow with the live transcript; estimates describe retained transcript/queued/footer rows, not a fixed memory bound, native caches, signature/source data, transient allocations or whole-process heap. No O(1)-frame or constant-memory claim is made.

The supported/tested host is Pi 1.0.0, not an unconditional promise for future versions or arbitrary extensions replacing the same private hooks. Tests and the offline driver are development-only. Generated captures, measurements and review reports belong in gitignored `.test-artifacts/`, not in the maintained documentation.
