# Syntax highlighting

This contract describes the current unified v3 implementation, including the Follow Pi semantic-palette and five-bit font changes. Source-bound local evidence is split between the integrated palette/font-contract acceptance in `.test-artifacts/follow-pi-implementation/verification.md` and the later role-derived palette correction in `.test-artifacts/follow-pi-role-derived/verification.md`; public delivery/platform gates remain in the [refactoring plan](unified-highlighting-plan.md#10-current-readiness). These are local source receipts, not publication receipts. The current operator target is running directly from the Git checkout with its colocated helper; no published pi-tidy-ui/Occipital pair is required for that use. This is not a claim that historical published v2 binaries support v3 or that current source passed remote CI/all platforms. The [earlier implementation plan](syntax-highlighting-plan.md) retains historical v2 evidence and independent delivery decisions.

## Surfaces and source text

- Native classification applies only to pi-tidy-ui's Bash command and successful edit/write source bodies, including Markdown files. Bash output is not classified. Ordinary summaries, user-message Markdown, the editor and native delegated cards remain outside this highlighter and its card palette.
- Bash argument updates prepare the latest command outside `render`. Pi's `setArgsComplete` finalizes the input independently of tool execution: a still-running Bash process does not require an unfinished syntax lease. Persisted completed calls use one-shot classification.
- A final live formation error retires native work and attempts lease closure outside `render`, without pretending that arguments completed or a tool executed. One already validated, budgeted display basis remains while its card owner lives; cancelled late replies cannot replace it and warm frames cannot reopen the retired work. A new restored terminal card, including an interrupted call, admits one finite native classification of its available saved text; source finiteness does not mean complete Bash arguments or tool execution. Public current-assistant tool-call IDs identify live ownership without history scans or retained messages, including abort before a useful frame; unknown embedding origin stays conservative. Warm/repeated/geometry-only visits reuse that static result. Positive execution/persisted `toolResult` evidence takes precedence over reconstructed incomplete flags. Partial error output and execution errors do not abandon the source.
- Edit/write use validated supplied source/diff data. Old/new sides are separate logical sources; a missing diff region starts a new parser context. No file reread or invented continuity across omitted context is permitted.
- Parsing sees logical source before tab expansion and terminal normalization. Painting projects structured ranges onto existing display text, with unchanged glyphs, wrapping, gutters, context, tint, padding and mouse bounds. Existing ANSI style isolation remains authoritative.
- Classification does not modify tool arguments/results, execute tools, send model requests or alter saved conversation entries.

## Rendering and fallback

Preparation, encoding, requests and classification occur outside terminal rendering. Rendering borrows already validated ranges or an exact prepared fallback; it never waits for a daemon. Keyed coalesced source notices carry work authority independently of display effects. A Bash card is invalidated only when its compatible display stamp changes, without traversing transcript history. Waiting/no-coverage preparation and equal-text finalization with identical styles do not rebuild or request a redraw.

The canonical `SourceController.workStatus` determines whether Pi classification is allowed. Queued, running or uncertain source work blocks a duplicate Pi parser within the same installed adapter. Style responses, cancellation, timeouts and provider absence do not prove that source parsing never started or has physically finished.

| Situation | Presentation |
|---|---|
| Validated semantic ranges and ready styles | Use the ready card's coherent palette and style table |
| Another code profile selected, not ready or refused | Keep the last validated native display; it is not classification proof for the requested profile |
| Growing/corrected Bash command with a compatible display basis | Reuse colors of the matching scalar prefix, including provisional styles; display every current character |
| Native work not started or unavailable, Bash | Whole command in the ready palette's command-neutral role (`toolTitle` in Follow Pi); **never call Pi's highlighter** |
| Native work not started or unavailable, file source | Reuse compatible exact display. With a ready native palette, missing syntax is native-neutral, not Pi-colored. Without any usable native palette, explicitly use whole-card Follow Pi, with one permitted exact Pi classification |
| Source/style work pending | Compatible historical Bash prefix or exact file fallback; otherwise complete text in the ready palette's neutral color. Styles never authorize a duplicate parser |
| Source/result cannot be retained or admitted | Complete text, with only any valid reusable classification |

The [Bash streaming contract](bash-streaming-contract.md) supersedes the former complete-line-only Bash display rule. Historical colors are presentation data, not proof of current parsing, current parser state or permission for a second classifier. Scalar-prefix verification runs outside render when the prepared command or validated basis changes. Its cached eligible-byte proof is guarded by source revision and basis geometry identity; rendering and width/theme changes reuse it without rescanning text. New glyphs after the mismatch use the ready command-neutral role, with the explicit whole-grapheme first-scalar exception. No source normalization, range copying, verification walk or work scheduling is added to a warm body hit. File exact-fallback and parser incrementality rules are unchanged.

Completed Pi fallback ANSI is converted once into accounted flat ranges and immutable styles; the stored representation does not keep a second ANSI copy. It preserves public foregrounds and bold/faint/italic/underline/strikethrough, including SGR `22` clearing only bold/faint, SGR `29` clearing strike, and SGR `0` clearing all five attributes. Both inputs use one literal-style painter with explicit RGB/indexed/terminal-default colors and attribute resets. Per-token backgrounds are suppressed: the ready card palette owns code/diff-row surfaces.

There is no millisecond budget, cold/warm timing gate, cooldown, sampling heuristic or per-frame classifier retry. A synchronous Pi fallback remains synchronous; moving it outside `render` does not make it an asynchronous parser. Exact source/palette reuse prevents ordinary repeated fallback work.

Pi fallback, semantic snapshots, contexts, styles and prepared geometry share the existing bounded logical-data authority. Charges follow actual storage lifetime, including captures and borrowed data after removal; existing cache cleanup returns geometry quota without another GC handler. Contexts are vocabulary-qualified. Styles are shared by live context and rule identity, and released with their owners; one ready display is retained, not a history of rendered themes.

### Palette and geometry independence

Follow Pi samples the real public Pi Theme outside render, keyed by its cached `theme.colors` and binding revision rather than the stable proxy object. Declarative Pi rules use the same Rust resolver as native themes; unchanged rules rebind locally without SOURCE/STYLE work. The [Follow Pi plan](follow-pi-palette-plan.md) records the semantic inventory and role-specific palette contract: 23 exact direct public bindings plus four logical delimiter slots. A missing marker color is derived from that marker's own related Pi role: heading markers from `mdHeading`, inline-code delimiters from `mdCode`, and link/image/reference delimiters from `mdLink`. The title, code, and link text keep their exact authored colors and typography; link punctuation clears only underline. These three families have independent visibility policies. String delimiters intentionally remain the exact `syntaxString` color; list markers keep `mdListBullet`, blockquotes `mdQuoteBorder`, and fenced-code borders `mdCodeBlockBorder`—none borrows heading/list color from another role. Commands use function, JSON keys/HTML attributes variable, and HTML tags/language constants keyword roles; parameters/options/special variables deliberately remain in the variable family. Emphasis inherits its enclosing foreground; invalid/deprecated scopes use error/warning color without changing tool status.

Derived colors are selected during palette preparation from the canonical emitted parent color, using bounded OKLCH lightness candidates and the final truecolor/256-color encoder. The heading marker has a stronger minimum separation (OKLab ΔE 0.12, target 0.22, maximum 0.30) because it is tiny beside its title; inline-code delimiters use 0.07/0.09/0.12 and link punctuation 0.07/0.10/0.14, with additional peer-separation checks. Every candidate must retain at least 4.5:1 contrast on each already-frozen applicable card surface. Diff surfaces are derived first from direct authored inks and never refit to accommodate optional shades. If a required parent, neighbor or surface is unknown, terminal-default, authored-indexed, or faint-styled, the encoded distinction collapses, or no safe candidate remains, that role uses its exact parent binding; no guessed RGB or unrelated color substitution. Faint is a font/display attribute rather than a separate ink, so it is preserved by exact-parent fallback and is not approximated into a derivation input. Original typography is retained. Numeric distances are regression guards, not universal proof of perceptibility; whole-source normal-size and actual terminal-cell checks remain required. Neutral themes gain no invented hue, and primary Pi colors are never corrected locally.

Actual Markdown strike uses the independent bit16 via trusted `markup.strikethrough`; separately scoped markers clear only that bit. The common painter normalizes/closes all five attributes with SGR `22;23;24;29`. Nested bold/italic/link/code scopes stay independent and source text is unchanged. Native typography never gains Follow Pi strike: native full masks explicitly clear it. Native themes supply or derive every card-interior color: code, panel, titles, output, reminders, footers, numbers, signs and diff surfaces. They never borrow missing colors from Pi. Exterior margins and the stripe background remain terminal-default. Native indexed/default colors are preserved, not fabricated RGB or a universal contrast guarantee.

One accepted publication couples a card's palette with all its source styles, including both edit panes. Keep the old ready presentation until the new one is complete; a stale, rejected or exceptional candidate cannot partially replace it. An unchanged neutral preparation, waiting notification or completion-only acknowledgment changes authority without changing paint. Borrowed visits expire on replacement/removal, and failed outer visits release provisional layout/paint candidates before publication.

Text is prepared on installation and semantic updates, before the first frame. Color-free measured geometry owns reusable glyph widths, tabs and grapheme coordinates. Theme changes reuse measurement/reflow; width changes reflow locally without source/style requests or repeated width measurement, even after Pi's unrelated width-cache traffic. One flat painter combines prepared rows with ready indexed styles. Rendering does not sample a theme, normalize/classify/encode source or admit RPC work. Height-only clipping and unchanged warm frames reuse prepared data and borrowed row arrays without walking all retained glyph dependencies. Full dependency validation remains at construction/publication boundaries; a warm hit does not bypass ownership or mutation checks.

Argument appends reuse stable prefix measurements and prepare only the affected final grapheme plus the new suffix. Completing an incomplete UTF-16 scalar may also join the preceding grapheme; that boundary is remeasured before adoption. Numeric capacity grows amortized rather than copying the whole glyph vector on each append. Suspended readers keep old storage charged until callback exit. Display measurement tolerates an incomplete surrogate as a replacement scalar without changing the original tool text or relaxing classifier admission. Oversized replacement glyphs occupy their complete declared cell width; variable padding is constructed only after funding.

Collapsed Bash output and reminders prepare at most eleven logical rows per section, enough for each existing ten-visual-row preview plus its overflow witness. Repeated result updates do not measure hidden remainder. Expanding prepares all missing rows through the same lifecycle before render; collapsing releases hidden measurements. Complete source/result strings remain available, and command geometry is not rebuilt for output-only updates.

Theme changes renew useful weak tickets but do not change parser identity, reopen leases or discard successful parsing. Missing style contexts are resolved outside render; retained styles support rollback/revisited themes without another request. Desired native rules reconcile before testing DATA capacity; a prepared card's Follow Pi restoration may also reconcile local bindings and cached styles without DATA credit. Both kinds of local cached rollback must remain independent from two unrelated unsettled requests. Missing SOURCE/STYLE work still passes the shared physical admission authority. The two-owner LIFO scheduler coalesces previews and publishes different cards independently. Ready file syntax must match its actual text version, not merely the latest requested version. Equal-text finalization preserves geometry/paint identity while settling native obligations.

Compatible recovery reuses complete parsed scopes and current ready styles, even while native credits are busy; missing styles may be resolved without source replay. Changed assets/vocabulary and incomplete parser state retain explicit source-recovery behavior. Interruption stops continuation/new SOURCE requests to Occipital, not acceptance of correct already-requested STYLE results for the text currently displayed. Such a valid result may advance the retained presentation after interruption without another SOURCE request or lease revival. Interrupted calls also retain theme recoloring and local reflow. New STYLE work over retained paint must enumerate and capture that same view; this consistency requirement must not reject an already-captured valid pending result merely to preserve an older display identity. Explicit pause, including zero usable width, instead prevents new SOURCE/STYLE admission and publication of already-dispatched STYLE into that card until a new useful visit resumes it. Physical work still settles, and valid styles may enter the accounted cache for reuse on resume; pause does not release unsettled credit by assumption. Removed/collected owners cannot resume or publish. Native Off, genuine pressure eviction and owner removal retain their named release semantics. Off retires native groups but prepares an eligible custom neutral/Pi-role card rather than reverting Bash to the host's raw argument representation; it never enables Pi classification for Bash.

Cold restore treats an exact Pi file capture as provisional when Occipital becomes available. Every useful, unpaused registered file owner without retained semantic SOURCE can receive its first native SOURCE through the existing bounded LIFO registry, subject to canonical execution authority and physical/byte admission. A newer Bash or file owner determines priority, not whether older files may upgrade. Keep each card's fallback until all its semantic segments/styles are ready; no click is needed to admit the upgrade. Complete retained scopes are reused on warm visits and compatible recovery, not reparsed. Paused, frozen, removed and refused owners retain their existing lifecycle/admission semantics; this does not introduce an unconditional transcript sweep or retry loop.

While Occipital is unavailable or a request cannot be admitted, Pi fallback has less scope detail and does not promise the new delimiter shades or Markdown strike. Pi loads some grammars after its initial history paint. An early Pi fallback for such a language may remain uncolored in the exact cache even after the grammar loads, until the source, palette or presentation owner changes. This visual limitation is explicitly accepted: no readiness polling, private Pi hook or classification-cache reset on general screen invalidation is added. It does not remove text or affect native-daemon classification.

## Long lines and grammar limits

Occipital uses Syntect 5.3.0 with two-face 0.5.2 assets. These are syntax grammars, not a language server: identifier/declaration distinctions depend on the available grammar scopes and are not semantic symbol resolution or identical OpenCode highlighting.

The existing UTF-8-safe **64 KiB per-line window** remains an internal parser guard. The whole-source coverage policy below is stricter: do not reset a 64 KiB allowance for every line. The classifier receives only its admitted logical prefix, without a fabricated newline; display/tool/session text is never truncated. Unclassified remainder uses the ready palette's neutral role, subject to the existing indivisible-grapheme display rule.

For ordinary appends, completed lines are reused and only the provisional tail/new suffix is parsed. A nonappend correction, expired lease or lost daemon state permits an explicitly counted bounded full-source resynchronization. Syntect's regex call cannot be interrupted inside a line; cancellation/yielding occur between lines/phases. No hard real-time guarantee is claimed.

## Providers and lifecycle

An eligible interactive adapter starts asynchronous selection automatically. Print/JSON/RPC loading, an inactive extension or constructing the client does not start a helper. Development version `0.0.0` uses only the colocated build, with a missing-build warning/fallback as specified [below](#delivery-status-and-verification). Real-version packages select as follows:

1. Try a user-managed compatible Subconscious internal service using the public SDK/discovery contract. A connection file alone is not proof that Occipital is available.
2. If none is usable, resolve the extension-declared **exact** owned Occipital release for the actual OS/architecture/ABI. Verify the installed payload or exact cache bytes; otherwise acquire that declared artifact. Never substitute a newer cached version or query a latest release.
3. If neither provider is obtainable, keep the ordinary fallback described above. Native availability does not gate tool execution or input.

Initial startup and connection-loss recovery use the same availability-wait path. A useful Bash demand postponed while the enabled provider/effective profile is unavailable marks the existing weak card/source state. Readiness revisits all such demands, not only the latest card, with the owner's latest text. Metadata-only loss does not reevaluate an unchanged processed Bash revision or turn its prior refusal into an availability wait; a real source change can create new demand. No extra strong owner/text queue or conversation-history scan is used. Already-current native coloring is not reparsed, and the existing bounded latest-file native upgrade/retained Pi fallback policy is unchanged. Paused owners wait for a new useful visit; frozen live aborts, removed/collected owners and bookkeeping refusals are not revived by readiness.

One chronological `SourceController` work registry selects both preparation and native dispatch newest-first (LIFO). Cards register their existing weak tickets before heavy preparation; all native segments of an edit share that entry. Standalone sources register once on first admission. Updates/retries do not change registration order. Card preparation no longer has a separate sorted queue, and no numeric priority is passed between layers. A group awaiting fresh preparation cannot dispatch obsolete queued work. Busy/protected sources are skipped; accepted results publish independently, without an ordered-completion barrier. Already dispatched native jobs retain their physical reservations. It processes at most two owners per batch, using the existing job limit, and yields to the event loop before more work. The continuation holds only the weak controller; synchronous or asynchronously queued demand cannot schedule an unbounded preparation microtask chain. The host-turn barrier survives a momentarily empty pending set after dispatch; the one-shot stops without rescheduling if no work arrives. Existing controller/provider/global job and byte credits still govern native dispatch. A resumable cursor walks this same linked registry without copying/reversing the entire registry for each batch. Theme metadata advances one refresh revision in O(1); weak tickets check usefulness lazily. Native-credit exhaustion stops new-card/theme source preparation until real settlement; it does not defer live text changes or unrelated permitted fallback. Local-only pending work can pass native-blocked entries in the same registry; actual credit release reconsiders the skipped native work. File layout stamps track actual native/Pi display identity, not requested theme or work-state notices; resuming a temporarily unavailable projection replaces its plain cached layout without repeating classification. Profile-only supersession does not abort already dispatched work: let its bounded physical jobs settle, reject obsolete presentation, then dispatch the latest profile. Genuine lifecycle cancellation still reaches every pending generation of the same source incarnation. Canonical source owners receive validated terminal transport replies even after other local cancellations; malformed, lost and started/unknown outcomes retain their existing protective meaning. No polling, new payload queue or time budget; one large preparation is not preemptible.

The extension and Occipital versions/releases are independent. Compatible shared-service versions need not equal the standalone pin. Owned processes have one client owner and are closed/reaped on retirement; shared clients close only their own route/connection and never terminate the shared module or peers.

Confirmed owned-process loss allows at most **two consecutive automatic restarts**. Only a validated useful current native source result resets that chain; metadata, stale results and cache reads do not. Deliberate session re-enablement permits a fresh attempt after exhaustion.

Confirmed established shared loss permits bounded reconnect and owned takeover. Record whether shared service was usable at initial startup. Only an initially shared client that fails over gets one return window: one probe per **60 seconds for 600 seconds**, at most one active probe, no catch-up burst or extension from failed probes/source changes. A successful verified return retires and reaps only its owned helper before new shared source work. Initial standalone clients have no periodic shared probes. Off/disposal clears candidates and recovery timers.

Daemon state is disposable. Replies must match provider/source/profile generations and exact replacement coverage before publication. Lease expiry/state reset and stale responses cannot paint another source/version. A transport end does not by itself prove that a shared parser did not run.

### Ownership exception

Temporary hidden/expanded/unsupported presentation and native highlighting off retain the same adapter's canonical work evidence. Complete adapter removal/reinstallation, including master off/on or reload, disposes its consumer and may allocate fresh source keys. An occasional repeated highlight while old work remains unsettled is explicitly accepted there; no cross-adapter owner registry or delayed installation is introduced. Normal cleanup, weak collection and rejection of late old-owner colors still apply.

Pi's synchronous transfer of the same components between fullscreen and regular renderers is not adapter replacement: preserve source keys, parsed scopes, ready palette/styles and measured geometry. This includes the final `fullscreenExitOutput: "transcript"` redraw. Renderer clear pauses work immediately; a weak microtask attachment check disposes only subtrees that remain detached. Ready unchanged demand does not repeat SOURCE/STYLE, classification or measurement on reattachment; changed text and equal-text finalization retain their own authority updates. Ordinary removal and adapter unload retain immediate cleanup.

Cancelling or disposing an unconfirmed list restores its entry choice. Each visit has its own rollback point; late replies cannot reapply an abandoned preview. Coloring uses the existing coalesced, newest-first two-owner batches, so large histories update gradually. Selected/effective differences are explained only when needed.
- **Refresh theme list:** explicitly reloads the active daemon catalogue. Listing/status is not a reload. No watcher, update polling, daemon restart, file upload or provider selector.
- **Status & troubleshooting → Highlighting service details:** cached provider/lifecycle, daemon/protocol/standalone versions, selected/effective theme and bounded last issue. No source text, discovery or new source work.
- **Use Occipital highlighting:** native-only preference, restored across reload and master off/on. Disable closes owned resources without stopping a shared module. The preference is saved alongside the confirmed code theme and terminal-default preference; appearance and diagnostic capture are process-local.

Opening/status/cancelling cannot enable a disabled provider. Follow Pi remains selectable without a live catalogue. Preference preparation has an explicit completion boundary. Closing confirmed pending work is not rollback, but retired runtime/syntax owners cannot publish late actions. Feedback is UI-only, never a conversation/model message.

`syntaxTheme` remains `{ "kind": "pi" }` or `{ "kind": "occipital", "id": "<catalogue ID>" }` in `join(getAgentDir(), "extensions", "pi-tidy-ui", "config.json")`. Missing configuration defaults to Follow Pi and enabled switches without writing. Invalid/unreadable files and failed/cancelled saves report bounded errors rather than rewriting them or claiming success. Updates preserve unrelated fields and share one serialized writer within the installed extension. Native directory events propagate the last published settings into running Pi instances; metadata-gated reads replace periodic polling/read/hash. Appearance and capture retain only two process-memory booleans across `/reload`, defaulting On in a new process. During an unconfirmed preview, external confirmation updates the Esc rollback choice without interrupting the preview; Enter confirms the local choice. See [settings policy](settings-menu-spec.md#changes-from-another-pi) for lifetime, invalid-file and concurrency rules. No database, migration or cross-process lock service is added.

An independent selected theme remains fixed across Pi theme changes. If unavailable on the current daemon, retain its saved ID, preserve a usable ready native display or use explicit whole-card Follow Pi fallback, and show one error for that unresolved episode. ### Daemon configuration

Occipital uses the OS user-configuration resolver plus `occipital/config.json`: XDG config/HOME fallback on Linux, Library/Application Support on macOS, and RoamingAppData on Windows. `--config FILE` supplies an explicit file. `themeDirectories` resolve relative to that file's directory. Missing fresh-install configuration permits bundled themes. Catalogue refresh is explicit and failed refresh retains the last complete catalogue; successful deletion is visible at next use.

These stores are separate: extension preferences choose an opaque theme ID; daemon configuration controls its catalogue. A client does not implicitly copy definitions between providers.

## Protocol and resources

The application protocol is **JSON v3**, capability `syntax-highlight/v3`, with exact resolver revision2 (contexts/palette/client-definition structural revisions remain1). Attributes/masks are0..31 with subset validation. Effective client-rules/native-rules/native-palette fingerprint domains are `/2`; original native theme-definition fingerprints remain unchanged. Both transports reject older/different resolver interpretations before candidate admission; a matching rebuilt helper is required. Its exact contract and cross-language vectors live in [`protocol/syntax-v3/`](https://github.com/chpock/pi-tidy-ui/blob/main/protocol/syntax-v3/README.md). There is no v2 decoder or second production painter.

- SOURCE operations carry text, grammar/source identity and incremental coverage, but no selected theme. Replies contain positive UTF-8-length/context pairs and reply-local front-coded scope contexts. A parsed empty context differs from unclassified coverage.
- `styles.resolve` carries vocabulary-qualified contexts plus a native definition fingerprint or bounded Follow Pi rule declarations, but no source text. Replies factor shared style expressions and provide the native whole-card palette. Both theme inputs use the same Rust selector/property resolver; JavaScript does not interpret scopes.
- The build-generated trusted vocabulary is tied to grammar assets. Unknown IDs/names are rejected before arbitrary scope interning; compatible provider recovery can style retained contexts without parsing again. Incompatible vocabulary/assets require an explicit cold-source transition, never reinterpretation of old IDs.
- Replies are self-contained. The client validates complete batch coverage, identities, scalar boundaries, negotiated limits and expanded storage before retained allocation. Its live-context/style sharing is an accounted optimization, not synchronized server dictionary state.
- Owned stdio keeps bounded big-endian length framing; shared calls use the public Subconscious SDK. Source and style work share physical jobs/byte credits and native fairness; metadata remains independent. A style response cannot close a parser lease, clear source uncertainty or reset a source-success crash budget.

Finite admitted sources remain one-shot. New contexts can require SOURCE then STYLE; retained contexts/styles and unchanged-rule Pi rebinding avoid that work. JSON decoding remains synchronous but DATA envelopes are bounded by the policy below; there is no chunk-feeding mode, worker/binary carrier or fast full-card rendering guarantee for enormous inputs.

## Highlighting volume policy

The policy is implemented at native admission, client decoding and classification-prefix selection. This section replaces the former 64 MiB source/DATA overload envelope for highlighting. It protects classification and its data exchange, not preparation, normalization, wrapping or painting of the complete card. Full-card size/preview/virtualization policy is a separate task.

| Boundary | Default | Unit and scope |
|---|---:|---|
| Native classified source | **64 KiB** | UTF-8 bytes of the prefix of one logical source; not per line or update |
| Native classified lines | **8,192** | Logical lines in that prefix; stop at the first byte or line boundary |
| Finite SOURCE batch | **64 KiB / 8,192 lines** | Sum over all sources, still at most eight sources; do not multiply the allowance by eight |
| Public Pi fallback source | **8 KiB** | UTF-8 prefix, using the same bounded selection and line-count rules; file sources only |
| DATA request or reply | **512 KiB** | Complete serialized application JSON body, including envelope, all sources/contexts, rules and palette; request and reply each have their own bound |
| Expanded context descriptions | **65,536** | Total numeric scope IDs after expanding front-coded contexts across the entire SOURCE/STYLE job, not encoded suffix words |
| Decoded result | **2 MiB** | Existing controlled-allocation policy charge of the complete decoded SOURCE/STYLE message, inside the existing data authority |

All limits are inclusive. Empty text has zero logical lines; count each LF plus one for a nonempty unterminated tail. A final LF does not invent another empty tail. Blank lines count. CR in CRLF does not introduce another line. Prefix selection respects complete Unicode scalar boundaries and counts UTF-8 bytes, not JavaScript UTF-16 units, terminal columns or JSON-escaped bytes. JSON escaping is independently included in the 512 KiB message check. Smaller negotiated existing limits remain authoritative. A provider advertising DATA `reply_bytes` above 512 KiB is not suitable for this consumer and is rejected before SOURCE/STYLE work: a local post-decode cap cannot protect Node from a shared SDK that has already parsed an oversized reply. Use the existing descriptor field, not a new protocol negotiation mode. A more generous input allowance alone does not require rejection because the client can send a smaller request; `line_bytes` remains the classified-per-line window, not a maximum accepted line-length constraint.

### Coverage, streaming and refusal

Select the prefix before allocating its UTF-8/JSON source payload or invoking either classifier. Scan only as far as needed to decide the prefix; do not encode an enormous full source merely to reject it. Preserve the complete latest display text separately from the actual classification source. Native `source_bytes`, committed offsets, ranges, revisions and completion refer to the prefix actually submitted, never to an invented parse of its neutral remainder.

The prefix budget belongs to the logical source, not to an append RPC: streaming does not grant another 64 KiB or 8,192 lines on every update. Once the admitted prefix is finite, settle/close its parser lease even if real Bash arguments continue to grow. Further changes solely after that boundary do not send more SOURCE/STYLE or re-encode the classified prefix. Corrections inside covered text use normal versioned replacement/recovery; they cannot keep obsolete file styles as current proof. Prefix completion does not mean Bash arguments completed or a tool executed. Historical Bash first-scalar/grapheme projection, frozen/paused ownership and unresolved-native fallback authority remain unchanged.

The raw daemon/client data boundary refuses an over-policy source or aggregate batch; it does not silently truncate wire text while acknowledging full coverage. The UI selects the useful prefix explicitly. Native production rejects excess context/result growth before excessive owned expansion/serialization; the client checks before typed context/range allocation and retained interning. A small wire dictionary can still exceed the expanded-context limit, and many empty context rows can exceed the decoded-charge limit without exceeding the word limit. The three result guards are intentionally independent. Wire-size refusal is based on actual encoded size, not a pessimistic source-size multiplier.

The transport passes the admitted size to the client in call-local, out-of-band ticket/byte metadata: stdio uses the actual JSON frame-body length, shared ingress uses its existing bounded canonical-JSON count. The semantic decoder checks that size against the current negotiated cap without repeating the full payload traversal, then still validates identity, shape, ranges, contexts and allocation limits. This metadata owns no response payload and is not a cache or a wire field. Raw unknown-object decoder calls without matching transport metadata retain the complete accessor-safe byte check.

A refusal retains the established current/last-ready or neutral presentation and physical-settlement semantics. It is not permission to run unlimited Pi fallback, reparse SOURCE because STYLE failed, or retry the same rejected work on every warm frame. Pi fallback has the smaller prefix allowance and still obeys canonical native-work permission; Bash never calls it. A ready native palette keeps the unclassified suffix native-neutral rather than mixing in Pi syntax. Classification limits do not truncate tool/session data or add a second painter.

### Why these values

The starting envelope was selected from the actual unreleased v3 consumer and exported public Pi `highlightCode`, on Linux x64 with Node 22.19.0 and 26.7.0 and Pi 1.0.0. Samples exercised ordinary code, dense token changes, many short/blank lines and nested scope dictionaries. They are observations on those inputs, not a portable maximum-latency or optimal-threshold proof.

- **64 KiB native prefix:** captured production SOURCE response replay, including UTF-8/JSON decoding, validation, typed ranges and funded adoption, took about **4–11 ms** for the selected 64 KiB shapes; selected 512 KiB shapes took about **25–42 ms**. A dense 64 KiB source produced **38,766 ranges** and **179,035–179,036 JSON bytes** (about 175 KiB). This preserves useful asynchronous native coverage without adopting the much larger tested input as an interactive default. The numbers exclude some preparation/STYLE/live-contention work and are not pure Rust CPU or an end-to-end UI latency claim.
- **8,192 lines as well as bytes:** 256 KiB of LF characters required **262,144 parser-line calls** and about **2.5 seconds**, despite a **586-byte reply**. A byte/frame-only cap misses that work. The tested 8,192-LF input took about **71 ms of native-plus-transport time**. The selected line limit bounds this dimension while keeping many ordinary short lines; it is not a promise of a sub-frame native response.
- **8 KiB Pi fallback:** this classifier runs synchronously in Pi's Node process. Dense 64 KiB input spent about **91–94 ms in the public call alone**. For the tested 8 KiB inputs, the first-call maximum was about **26 ms** and subsequent-call maximum about **15 ms**. Those are actual classifier calls, not cache hits; adapter conversion, imports and the whole UI are outside that clock. The smaller fallback envelope is a coverage/responsiveness compromise, not a claim that 8 KiB is cost-free or that Rust's larger envelope is safe for synchronous JS classification.
- **512 KiB DATA body:** leave room above measured replies for envelopes, several sources, contexts and styles while bounding JSON/encoding volume. A 64 KiB input is not a 64 KiB JSON response. The same guard covers STYLE requests and replies; it is not a separate huge palette channel. Existing source-free control caps remain **4 KiB request / 32 KiB reply**, not 512 KiB or 64 MiB.
- **65,536 expanded IDs:** compact front coding can hide substantial expansion: a tested **397-byte source** produced **18,395 expanded IDs** in a **5,683-byte JSON reply**. The chosen ceiling permits 256 KiB of Uint32 words, with engineering margin above those tested shapes, without mistaking compact JSON for cheap decoded work. The value was not established as the fastest possible STYLE ceiling for all themes/languages.
- **2 MiB decoded charge:** constrain row/record/index/style overhead in addition to scope-word storage. SOURCE accounting includes existing context-row/word policy units, typed ranges, source records and envelope overhead; STYLE includes expression/index/palette allowances. This is a per-message admission ceiling in the existing authority, not a second cache/pool, per-card retained-size cap or a measurement of V8/Rust allocator bytes.

No separately tunable range-count or nesting-depth policy is added merely to duplicate these bounds. Positive-byte ranges within 64 KiB already have a finite count; context/result guards cover distinct expansion costs. Existing exceptional engine-safety checks remain. No new wall-clock timeout, worker, queue, scheduler, hidden reclassification timer or arbitrary-language deadline is introduced.

### Existing authority and guarantees

The **1 GiB client logical-data authority**, shared **1 GiB controlled application ledger**, **two unsettled physical client DATA calls** and at most one append per source remain. Shared service limits remain sixteen outstanding DATA jobs across eight routes and 4,096 leases globally/512 per route. Leases expire after five minutes idle or one hour total age; no no-op heartbeat renewals. The native DATA wait deadline remains five minutes, not a claim that a regex can be interrupted. Source-free metadata stays independent; catalogue wait expiry does not destroy unrelated highlighting. The outer emergency framing ceiling remains separate from the much smaller DATA policy. Native admission failures must not leave uncharged persistent engine/binding capacity: surviving capacity is reconciled against the already admitted credit before reducing a failed job to its error envelope. The physical slot still belongs to that job through reply handoff or confirmed cleanup. Native lease/binding pruning merges the existing tables in monotonic incarnation order, avoiding a full slot search for every binding or an additional retained index.

Bounds on bytes/lines/expansion are not hard time or whole-process memory guarantees. A Syntect regex call and synchronous Pi `highlightCode` cannot be preempted by a JavaScript timer. Two valid replies may settle close together. A per-source coverage quota is not a cumulative CPU allowance for a whole event-loop turn or many independent Pi classifications; the existing useful-work scheduling remains separate. Parser heaps, Node/V8 transients and private SDK buffers are not application charges. In particular the public shared SDK can copy/decode before the application's validator; producer-side bounded replies matter, and a hostile unrelated peer is not made safe by post-decode validation. Public Rust SDK pre-handler body retention remains outside this application's admission claim. No hard RSS/OOM guarantee, infinite-input display protection or all-language latency promise follows from these values.

### Changing the thresholds

The production defaults are named together in `src/occipital/limits.ts` (`HIGHLIGHT_LIMITS`) and `crates/occipital/src/limits.rs`; `protocol/syntax-v3/highlighting-limits.json` is their shared numeric conformance fixture, not another runtime policy store. Keep the two small language-native tables and fixture in sync. No user-preference/menu/environment override or runtime file watcher is introduced. Increasing a coverage limit is not sufficient by itself: DATA size, expanded contexts, decoded charge and existing physical credits must still admit the corresponding work.

For a future change, record its rationale, update the conformance/boundary tests, and measure both supported Node runtimes with ordinary, dense, many-line and compact-expansion inputs. Check at-limit/one-over aggregate batches and cumulative append, scalar-safe cuts, unchanged saturated-tail counters, native/Pi neutral suffixes, refusal without duplicate fallback/warm retry, and cleanup of leases/physical credits/borrowed data. Build a source-bound daemon and run affected real owned/shared and Pi controls, not only pure helpers. Use new prepared inputs/evidence; do not relabel previous measurements as execution of changed constants. Report preparation/native-build overruns rather than dropping integration coverage. Public v3 delivery remains separately authorized.
