# Edit cards: saved rows, source regions and display projection

Edit/write share `src/file-card.ts` for persisted-format validation and logical data. This chapter owns accepted diff formats and edit behavior; [write cards](write-card-spec.md) owns write-specific classification. Neither reconstructs changes from proposed arguments or rereads a file.

## Internal flow

```text
persisted patch/diff + path
  -> validate complete supplied representation
  -> full logical rows (kind, text, old/next position, hunk or gap)
       |                                      |
       |                                      +-> visible context projection
       +-> continuous old/next source regions       + row/source coordinates
                  |                                           |
             SOURCE / STYLE                     measured glyphs / paired layout
                  +-----------------------------> complete ready card paint
```

`prepareFileCard` first classifies supplied data. The live prepared owner requests `logicalOnly=true`: source rows retain tabs and logical text, without eager tab-expanded strings or immediately joined source fragments. Validation/classification is outside the paint callback.

The full view and visible view are separate. `contextRows` walks contiguous unchanged runs within each supplied hunk, retaining the configured prefix/suffix beside changes and inserting an interior gap when a longer unchanged run is omitted. Original row objects preserve their full-view index; generated omission markers have no original source row. Leading/trailing generated gaps are removed without stripping literal source ellipses.

For each old/next side, source coordinates are built from **all supplied logical rows**, not just the visible projection. Rows absent on that side are skipped. An explicit gap or nonconsecutive position ends a continuous fragment; missing text is never synthesized. Each visible source row records its fragment key, UTF-16 start and UTF-8 byte start from that complete fragment. Later useful classification calls `fileSources` to join only those continuous logical fragments. Thus display-hidden opening comments/strings can influence visible syntax within the admitted prefix, while genuinely unavailable source resets parser state.

Example: if supplied new-file positions are 40, 41 and 45, rows 40–41 share one source and row 45 starts another. Hiding row 40 for display does not remove it from that supplied source; a gap between 41 and 45 cannot be bridged by pretending those missing lines are empty. Wrapped row numbers, source bytes and expanded-tab cells remain distinct coordinates.

The common scene pairs changed logical rows within hunks, reflows measured glyphs at the current pane widths and paints validated flat ranges. Width changes do not reparse saved metadata or remeasure glyphs. Theme changes replace paint without repeating source parsing or diff pairing. Exact source/paint publication and memory ownership are in [prepared cards](syntax/prepared-cards.md); [shared rendering](rendering.md) describes adoption and neighbor measurement.

This specification defines the interactive presentation of the exact tool name `edit`. Tool execution, arguments, result bodies and saved session data remain unchanged.

## Metadata and scope

`src/file-card.ts` validates saved metadata, prepares logical display/source regions and supplies validation-only measurement; it neither classifies syntax nor paints the card. `src/syntax/cards.ts` owns prepared text and ready paint, `src/syntax/work.ts` applies classification/fallback authority, and `src/syntax/card-layout.ts` supplies the shared layout/painter path. `src/index.ts` remains the sole host adapter. See the [common pipeline and ownership map](syntax-highlighting-spec.md#syntax-pipeline-and-ownership). Reuse the existing frame, mouse routing, lifecycle hooks and component-owned rendered-layout retention. Diff presentation introduces no source-file read, execution interception or dedicated render timer; native provider lifecycle is separate. Existing native renderer methods, including Pi's own asynchronous preflight preview, still execute unchanged.

Select the path with nullish precedence, `args.path ?? args.file_path ?? args.filePath`, then require a nonempty primitive string. An empty or wrong-type non-nullish earlier field blocks later aliases; this is not a search for the first usable string. Format absolute paths relative to the component's native `cwd`, without changing source arguments. The compact edit/write shortcut is different: it recognizes only a nonempty primitive `path`. Use persisted result metadata only:

1. `details.patch !== undefined` takes precedence and must be a string single-file unified patch. Null and other non-string values are unsupported, not absent; malformed/present unsupported values delegate to native instead of falling through to `diff`. Empty string is supported empty metadata. Write has a separate [explicit-truncation override](write-card-spec.md#saved-source-and-classification) before this selection.
2. Otherwise accept string `details.diff` as a unified patch or Pi/AFT's numbered diff.
3. Validate patch hunk counts and numbers; unsupported/malformed formats delegate to native rendering rather than inventing edits.

The host adapter selects presentation by lifecycle state. Before a final result (argument streaming, actual execution, or any partial result), use the compact `edit <path>` summary and its shared execution-only spinner when `path` is a nonempty string, without inspecting any other argument. Otherwise use generic argument formatting. Both follow the [compact preview budgets](tool-summary-spec.md#3-values-budgets-masking-and-sanitization), not the diff-card rules. A final `isError` uses the same summary with every visible segment in the active `error` role, never a stale/proposed diff or result-body preview; native expansion shows the complete available error. Only a final result without `isError` can enter the edit-card presenter. This policy is shared by rendering, predecessor spacing and mouse handling; final updates stop summary animation immediately.

Do not infer success from output or derive a proposed patch from input edits. Do not reread a file that might have changed since the tool completed. For successful results, empty supported diff metadata still gives a titled block; missing metadata retains the inline success title and unsupported metadata delegates to native. The adapter never inspects partial/failure diff metadata for custom presentation.

Image results and intentionally hidden native components remain native. Before custom rendering/spacing/input, the adapter may skip native row construction only for the verified Pi `ToolExecutionComponent` with the exact stock edit call/result function pair from public `createEditToolDefinition` and its current plain call `Box` using stock `render`/`clear`/`addChild`. The native factory can reuse an earlier custom Box even after switching renderers, so the function pair alone is insufficient. Proof is rechecked on every visit without traversing rows; an edit name, schema or execution identity is not proof. Missing getters/component, custom/mixed/replaced renderers, reused custom Boxes and other component implementations retain native width-dependent visibility checks. `--tidy-ui-card edit` explicitly restores native presentation; `--tidy-ui-compact edit` uses ordinary compact rules and takes precedence. Expanded edit calls remain native. Bash, user cards, [write cards](write-card-spec.md), other tools and noninteractive modes retain their existing policy.

### Accepted saved formats

**Numbered diff.** Each source row has one leading kind character (` `, `+` or `-`), optional spaces, a positive safe-integer line number, one mandatory space, then source text. A row of one or more spaces followed by exactly `...` marks an unavailable gap. Context numbers are old-file positions; the running addition/removal delta supplies their new-file positions. Invalid original or corrected positions reject the metadata. Source rows need not be contiguous: unavailable positions form separate logical syntax sources rather than guessed intervening text.

**Unified patch.** Hunk headers have `@@ -start[,count] +start[,count] @@` with an optional trailing label. An omitted count means one. Starts/counts and nonempty-range endpoints must be nonnegative safe integers; nonempty ranges start at one or greater. Context consumes both counts, removal only the old count, and addition only the new count. Counts must be exhausted before another hunk and at end of input. Skip the exact `\ No newline at end of file` annotation. Preamble/file-header rows before the first hunk are not display content; their filenames are not checked against the argument path. The parser validates supplied ranges, not file identity or current filesystem contents.

Empty string is accepted as empty metadata. Normalize CRLF and standalone CR to LF. Unified input tolerates one final newline; numbered input does not discard a final empty row and rejects a terminal newline. `patch` always selects the unified parser. For string `diff`, a matching unified hunk header selects unified parsing; otherwise use numbered parsing. Unsupported input stays native rather than being repaired or interpreted as proposed edits.

## Syntax-colored diff

The syntax language comes from the edited file's path, **not** from a language named `diff`. For example `.ts`, `.py`, `.json` and `.rs` use TypeScript, Python, JSON and Rust highlighting. Highlight removed and resulting source streams separately so removed strings/comments cannot incorrectly color new code. Prepare logical source before tab expansion/wrapping, reset parser context at unavailable gaps and borrow exact ready semantic ranges/styles or permitted flat Pi fallback. Completed Pi ANSI is converted once outside render, not reparsed during layout. Preserve code indentation, whitespace, joined Unicode graphemes and syntax spans. Unknown extensions remain unclassified in the selected palette's neutral code color, without guessed language classification; permitted whole-card Follow Pi fallback follows the syntax contract.

- Keep native syntax foregrounds for keywords, strings, numbers, comments, function/type names and other supported tokens in both removed and added code.
- Under Follow Pi, use `toolOutput` for ordinary code, `dim` for line numbers and `toolDiffAdded`/`toolDiffRemoved` for signs. An independent theme supplies or derives every corresponding card role from native data, never from Pi.
- Follow Pi keeps the neutral `toolPendingBg` panel and ordinary `borderMuted` stripe. Locally selected owned palettes provide their own panel/frame/diff palette. Derive subdued code and separate number/sign backgrounds from the effective palette, as specified below. Do not multiply by the bright sign foregrounds. Preserve syntax/sign foregrounds, unchanged rows and exterior frame paint; no global theme edits or OpenCode palette constants.
- Empty split counterparts, wrap-alignment blanks and the final internal right padding retain the effective neutral panel (`toolPendingBg` under Follow Pi), even after a changed cell closes its own background. The common prepared painter explicitly emits those neutral cells; its measured frame does not reopen paint after child resets; do not extend change tint into the exterior margin or alter pane widths.
- Title: muted `← Edited <path>` at the shared frame content origin, exactly like Bash's `# <description>`, without an additional inset. Inline titles use that same absolute content origin and reserve the current exterior right margin before wrapping; only the display label changes, not the tool name or status rules. Diff starts at that content origin without an extra inset: the shared frame supplies one neutral padding cell on each side. The gutter's own leading space/right-aligned number and code indentation remain part of the diff.
- Addition-only or removal-only diffs use full-width unified view at every component width. Decide from parsed source-row kinds across the entire supplied diff, not proposal arguments, file/header text, code punctuation, a single hunk or wrapped rows. Context/gap rows do not count as changes; context-only metadata also stays unified. Mixed diffs use unified view at component widths up to 120 and split above 120, even when additions and removals belong to different hunks. Classification happens only during body construction and requires no retained metadata, new cache key or file read. Split shows old/new context and pairs runs of removals/additions within each patch hunk, never across unrelated hunks. Independently wrap the panes and insert blank counterparts so the next logical pair stays aligned.
- Display all changed rows, without a Bash-like preview limit. `const DIFF_CONTEXT_LINES = 3` in `src/file-card.ts` limits unchanged logical source rows to at most three before and after each change block, within supplied hunk boundaries. Overlapping windows are merged without duplicates; zero hides all unchanged rows. This is a display-only cap: larger values cannot recover context absent from persisted metadata (Pi's default producer supplies four). Do not reread files or modify result/model/session bytes.
- Prepare all supplied logical regions before projecting display context. Within the admitted classification prefix, a display-hidden opening comment/string still determines visible syntax; unavailable regions reset parser context. The [highlighting volume policy](syntax/work.md#highlighting-volume-policy) limits each continuous old/new logical source to a cumulative 64 KiB UTF-8 / 8,192-line native prefix, with a smaller 8 KiB Pi fallback. The whole SOURCE batch also obeys its aggregate limit. Remaining text stays fully visible in the ready palette's neutral code color; it is not parsed by continuing after a skipped suffix. The internal per-line window does not grant another allowance on each line. Preserve original old/new positions and hunk IDs. Hunk headers/file headers/no-newline annotations are not rendered as source. Remove generated omitted-context rows only at the beginning/end of the projected diff; keep interior omission markers, including when reducing a long unchanged run, and never strip literal ellipsis from source code.
- Unified context uses new-file numbers; removals use old-file numbers and additions use new-file numbers. The numbered format's insertion/removal delta corrects context numbers. Unified patches supply their own hunk starts.
- Tiny widths prioritize code over decorations; omit gutters when no code column would fit. A wide grapheme impossible in a one-column content area uses a safe replacement cell; source/model/session bytes remain unchanged.
- Flattened diagnostics must be an array. Display only object members with exact `severity: "error"` and a string `message`, using the ready palette's `diagnostic` role below the diff: Pi `error` under Follow Pi, the selected owned palette's secondary/comment-derived text. A positive safe-integer `line` produces `Error [N]: message`; otherwise show `Error: message` without a location. Sanitize and flatten the message. Other severities, numeric LSP severities, range maps and extra fields are not interpreted; columns are not displayed. This is compatible AFT shape coverage, not producer identification, actual AFT execution or an LSP subscription. Pi's built-in edit has no such metadata.
- File tabs expand at four-column stops measured from the original logical-line origin; a soft wrap does not restart those stops. Bash instead uses eight-column display stops. Sanitized logical source retains tabs until measured layout, and source offsets never refer to expanded-tab cells.

## Interaction and retention

Skipping native row construction can leave native self-render height stale while custom output is active. Custom hit testing uses custom row counts and frame geometry; before delegating mouse handling to native, the adapter first renders the native component at the event width to refresh its geometry.

Completed successful framed edits use the existing selection-safe panel click bounds to reveal native content; completed failed summaries expand through ordinary compact-summary click routing. Exterior margins, pending calls, selection, wheel and secondary events are not new click targets. Ctrl+O remains Pi's own global toggle. No hover behavior.

Retain only the latest rendered rows and frame/native classification in weak component-owned state, without byte/count eviction. Native argument/result updates, expansion, invalidation, width, Output padding, theme and `cwd` changes rebuild the affected custom layout. Warm frames perform no additional custom syntax highlighting or wrapping. Explicit layout-cache clear, off, shutdown and reload release custom retention; lifecycle teardown restores only owned hooks. Same-owner renderer transfer follows the exception below.

Computational performance: prepare logical diff pairing once, retain color-free glyph measurements, and reflow using numeric coordinates. One painter walks ready flat ranges and rows monotonically; it does not parse/slice ANSI or search the whole source/group for each row/range. Palette changes reuse measurements, pairing and reflow; resize retains measurements and semantic/style results. Preserve every space, grapheme, token foreground and multiline state. Resolve owned-palette surfaces outside render once per palette generation, not per row/symbol. Stream source validation and diff emission; avoid argument-spread limits on large changed blocks. Final failures reject stale diff metadata before parsing it, and source without tabs needs no tab-expansion segmentation.

Successful framed diff layouts belong to the `cards` accounting group with Bash and successful write cards. Compact edit lifecycle states, metadata-free headings and native fallback rows belong to `ordinary`. A weak tool state owns just one current layout/group/entry; lifecycle/kind/width invalidation releases its old entry before replacement. Neither group imposes admission, count, byte or recency limits. Ordinary detached removal/nested clear or owner collection releases the component's presentation. Current-renderer clear preserves synchronous same-owner transfer under the [shared lifecycle rule](render-cache-spec.md#invalidation-and-ownership), rather than discarding ready data before the final transcript. No duplicate widths or extra height/visibility cache is introduced in presentation; logical source/colors use the separate shared bounded syntax pool; see the [cache contract](render-cache-spec.md).

Neighbor spacing and rejected mouse events read the already prepared file display. An exact retained scene supplies its row count; otherwise a framed mode needs only its multiline classification, while an inline heading temporarily reflows its existing measured text and immediately releases that reflow. This path neither reparses saved metadata nor constructs/highlights/paints an unretained source body. The standalone `measureFileCard` metadata helper is not the live spacing path; see [prepared-file measurement](rendering.md#neighbor-spacing-without-another-body-build). Pending/failed edits use ordinary summary heights instead. Malformed metadata still delegates to native. Return existing body rows directly when no outside separator is required. Unknown self-render visibility remains native; the verified stock edit pair needs no native visibility render in any custom lifecycle state or predecessor query. Explicit native presentation, expansion, images, hidden guards and malformed fallback still render natively. Completed compact summaries return retained rows directly when neither animation nor a separator requires composition. No extra height/visibility cache, owner references or invalidation rule is added. Width changes rebuild required presentation but reuse exact classification; a changed code theme resolves only missing styles/palette, never reparses retained source. The presentation cache retains only the latest rendered layout.

See [card validation](testing.md#cards-and-native-data) for metadata, physical-terminal and native live/replay controls.
