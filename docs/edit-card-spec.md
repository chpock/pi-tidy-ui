# Edit cards: saved rows, source regions and display projection

Edit/write use [producer adapters](tool-adapters.md) for persisted-format validation and share neutral logical rows, source regions and layout. Producer-specific metadata precedence stays in the adapter layer. This chapter owns accepted diff formats and edit behavior; [write cards](write-card-spec.md) owns write-specific classification. Neither reconstructs changes from proposed arguments or rereads a file.

## Internal flow

```text
persisted patch/diff + path
  -> validate complete supplied representation
  -> full logical rows (kind, text, old/next position, hunk or gap)
       |                                      |
       |                                      +-> visible context projection
       +-> continuous old/next source regions       + row/source coordinates
                  |                                           |
             SOURCE / STYLE                     measured glyphs / paired layout
                  +-----------------------------> complete ready card paint
```

The deferred adapter first classifies supplied data under the construction grant. The live prepared owner consumes logical source rows that retain tabs, without eager tab-expanded strings or immediately joined source fragments. Validation/classification is outside the paint callback.

The full view and visible view are separate. `contextRows` walks contiguous unchanged runs within each supplied hunk, retaining the configured prefix/suffix beside changes and inserting an interior gap when a longer unchanged run is omitted. Original row objects preserve their full-view index; generated omission markers have no original source row. Leading/trailing generated gaps are removed without stripping literal source ellipses.

For each old/next side, source coordinates are built from **all supplied logical rows**, not just the visible projection. Rows absent on that side are skipped. An explicit gap or nonconsecutive position ends a continuous fragment; missing text is never synthesized. Each visible source row records its fragment key, UTF-16 start and UTF-8 byte start from that complete fragment. Later useful classification calls `fileSources` to join only those continuous logical fragments. Thus display-hidden opening comments/strings can influence visible syntax within the admitted prefix, while genuinely unavailable source resets parser state.

Example: if supplied new-file positions are 40, 41 and 45, rows 40–41 share one source and row 45 starts another. Hiding row 40 for display does not remove it from that supplied source; a gap between 41 and 45 cannot be bridged by pretending those missing lines are empty. Wrapped row numbers, source bytes and expanded-tab cells remain distinct coordinates.

Full scenes pair changed logical rows within hunks, reflow measured glyphs at the current pane widths and paint validated flat ranges; mixed full diffs split above 120 columns. Bounded live previews always retain one unified pane, including at wide widths, and use the common overflow marker when their ten-row or wrapped-row budget omits content. The explanatory bounded-prefix note is present only when the prepared source actually omits rows; a fully retained short preview is not described as truncated. Width changes do not reparse saved metadata or remeasure glyphs. Theme changes replace paint without repeating source parsing or diff pairing. Exact source/paint publication and memory ownership are in [prepared cards](syntax/prepared-cards.md); [shared rendering](rendering.md) describes adoption and neighbor measurement.

This specification defines the interactive presentation of the exact tool name `edit`. Tool execution, arguments, result bodies and saved session data remain unchanged.

## Metadata and scope

Producer readers under `src/tool-adapters/` select and interpret producer-specific saved fields before passing a `FileCardInput` to shared `src/file-card.ts`, which validates the selected representation and prepares logical display/source rows; it neither classifies syntax nor paints the card. `src/syntax/cards.ts` owns prepared text and ready paint, `src/syntax/work.ts` applies classification/fallback authority, and `src/syntax/card-layout.ts` supplies the shared layout/painter path. `src/index.ts` remains the sole live-host adapter. See the [common pipeline and ownership map](syntax-highlighting-spec.md#syntax-pipeline-and-ownership). Reuse the existing frame, mouse routing, lifecycle hooks and component-owned rendered-layout retention. Diff presentation introduces no source-file read, execution interception or dedicated render timer; native provider lifecycle is separate. When native presentation is selected, Pi's renderer methods—including asynchronous edit preflight—remain unchanged. The public resolver defers only the exact stock callback pair; compatible third-party callbacks remain untouched and may run at their ordinary native visibility/fallback boundary.

Select the path with nullish precedence, `args.path ?? args.file_path ?? args.filePath`, then require a nonempty primitive string. An empty or wrong-type non-nullish earlier field blocks later aliases; this is not a search for the first usable string. Format absolute paths relative to the component's native `cwd`, then apply the [shared path-display rule](tool-summary-spec.md#filesystem-path-display): a parent ladder reaching the filesystem root becomes the resolved absolute path, while nearby relative names remain relative. Source arguments are unchanged. The compact edit/write shortcut is different: it recognizes only a nonempty primitive `path`. Use persisted result metadata only:

1. `details.patch !== undefined` takes precedence and must be a string single-file unified patch. Null and other non-string values are unsupported, not absent; never fall through to `diff`. Empty string is supported empty metadata. Write has a separate [explicit-truncation override](write-card-spec.md#saved-source-and-classification) before this selection.
2. Otherwise accept string `details.diff` as a unified patch or Pi/AFT's numbered diff.
3. Validate patch hunk counts and numbers. In bounded preview mode, unsupported or malformed metadata remains an owned unavailable summary stating that saved change details are unavailable; the preview does not imply a geometry refusal or invent an inline change view. Diagnostic policy follows the selected view: a preview may show one fixed notice that diagnostics exist without traversing messages, even when saved patch metadata cannot form rows; only the full view formats and measures saved diagnostics. The explicit full view delegates unsupported/malformed metadata to the existing native renderer rather than inventing edits, including native mouse handling.

The host adapter selects presentation by lifecycle state. Before a final result (argument streaming, actual execution, or any partial result), use the compact `edit <path>` summary and its shared execution-only spinner when `path` is a nonempty string, without inspecting any other argument. Otherwise use generic argument formatting. Both follow the [compact preview budgets](tool-summary-spec.md#3-values-budgets-masking-and-sanitization), not the diff-card rules. Expanded pending details show string fields already received from each streaming edit entry; a missing `oldText` or `newText` is not itself reported as truncated content. The omission note is reserved for source-unit, row or entry limits that actually cut the bounded view. A final `isError` uses the same compact summary with every visible segment in the active `error` role, never a stale/proposed diff or result-body preview. Its explicit expanded details remain an owned, funded presentation. They show all saved text error content, not proposed `args.edits[]` or legacy `oldText`/`newText`. Submitted edits are not applied source and remain unchanged in session data. The expanded failure uses the [shared file-error panel](read-card-spec.md#expanded-file-errors). Final-error details do not use the pending excerpt limit: construction and measured geometry must obtain ordinary funding before the complete body is retained; refusal shows a bounded unavailable-details message without retaining partial text. This is saved data only: it does not re-read files or parse proposed edits as a successful diff. A failed summary may be expanded by an in-panel primary click; a still-pending call requires Ctrl+O and ignores mouse expansion. Pending and collapsed failed file owners use this owned compact presentation, preserving the shared spinner and error styling without constructing full card details or invoking the verified stock file renderers. A compatible third-party self-shell callback may still run at the actual width when native visibility must be established. Results carrying image content remain native even when marked failed. The image decision is weakly cached by result identity and invalidated at Pi's `updateResult` notification boundary, so warm paint and predecessor-spacing checks do not reread result content. Only a final result without `isError` can enter the edit-card presenter. This policy is shared by rendering, predecessor spacing and mouse handling; final updates stop summary animation immediately.

Do not infer success from output or derive a proposed patch from input edits. Do not reread a file that might have changed since the tool completed. For successful full views, empty supported diff metadata still gives a titled block; missing metadata retains the inline success title and unsupported metadata delegates to native. A valid full view refused before logical-display construction is funded remains owned and shows a bounded limitation message; unadopted partial work is released without invoking native preparation. A later width-dependent geometry-only refusal drops that scene but retains the accepted logical display and measurements for an ordinary geometry retry. This differs from an accepted full-to-preview demotion, which adopts a newly funded bounded display and releases the prior full representation. Bounded preview stays owned and shows an unavailable summary when its selected saved metadata cannot be validated. The adapter never inspects partial/failure diff metadata as a successful custom diff.

Image results and intentionally hidden native components remain native. Before custom rendering/spacing/input, the adapter may skip native row construction only for the verified Pi `ToolExecutionComponent` with the exact stock edit call/result function pair from public `createEditToolDefinition` and its current plain call `Box` using stock `render`/`clear`/`addChild`. The native factory can reuse an earlier custom Box even after switching renderers, so the function pair alone is insufficient. Proof is rechecked on every visit without traversing rows; an edit name, schema or execution identity is not proof. Missing getters/component, custom/mixed/replaced renderers, reused custom Boxes and other component implementations remain outside the lazy-owner optimization and retain native width-dependent visibility checks. Compatible third-party saved edit data still uses the same prepared card, but its callbacks and state are not wrapped, retired or cleared; no native-work savings are claimed for it. `--tidy-ui-card edit` explicitly restores native presentation; `--tidy-ui-compact edit` uses ordinary compact rules and takes precedence. Supported expanded edit calls use the owned prepared full view; unsupported/missing full saved metadata delegates through the existing renderer. If valid full metadata cannot be funded for preparation or geometry, the owned full state shows its bounded limitation message and retries on the next eligible render without invoking the stock native preparation. A bounded preview remains owned even when its selected metadata cannot produce a validated preview. Bash, user cards, [write cards](write-card-spec.md), other tools and noninteractive modes retain their existing policy.

### Accepted saved formats

**Numbered diff.** Each source row has one leading kind character (` `, `+` or `-`), optional spaces, a positive safe-integer line number, one mandatory space, then source text. A row of one or more spaces followed by exactly `...` marks an unavailable gap. Context numbers are old-file positions; the running addition/removal delta supplies their new-file positions. Invalid original or corrected positions reject the metadata. Source rows need not be contiguous: unavailable positions form separate logical syntax sources rather than guessed intervening text.

**Unified patch.** Hunk headers have `@@ -start[,count] +start[,count] @@` with an optional trailing label. An omitted count means one. Starts/counts and nonempty-range endpoints must be nonnegative safe integers; nonempty ranges start at one or greater. Context consumes both counts, removal only the old count, and addition only the new count. Counts must be exhausted before another hunk and at end of input. Skip the exact `\ No newline at end of file` annotation. Preamble/file-header rows before the first hunk are not display content; their filenames are not checked against the argument path. The parser validates supplied ranges, not file identity or current filesystem contents.

Empty string is accepted as empty metadata. Normalize CRLF and standalone CR to LF. Unified input tolerates one final newline; numbered input does not discard a final empty row and rejects a terminal newline. `patch` always selects the unified parser. For string `diff`, a matching unified hunk header selects unified parsing; otherwise use numbered parsing. Unsupported input is never repaired or interpreted as proposed edits: the explicit full view stays native, while bounded preview shows an owned unavailable summary.

The bounded live source prefix is normalized and selected only when the host supplies a new argument/result or the user changes preview/full mode; same-content hidden-suffix replacements update the weak input snapshot without replacing the source token, and warm paints/width changes reuse it. The separate live bounded preview first normalizes line endings inside the 8,192-UTF-16-unit window, then cleans and selects at most ten physical input rows, including file/hunk headers. The shared painter clips wrapped content to ten visual rows and adds its funded overflow marker independently of the explanatory note. It keeps a generic `Edit` label instead of deriving a change kind from prefix rows, because later omitted rows can change the full diff classification. A physically cut hunk may expose its accepted prefix, but a fully inspected malformed hunk remains unavailable. The ordinary full view still validates and presents the complete saved representation. Bounded edit previews remain unified at every width so the prefix cannot imply a complete old/new pairing. Pending input stays on this bounded path when either global or per-card expansion is requested; final success can enter the full validated edit view, while failures expose their saved error rather than treating proposed arguments as an applied diff.

## Syntax-colored diff

The syntax language comes from the edited file's path, **not** from a language named `diff`. For example `.ts`, `.py`, `.json` and `.rs` use TypeScript, Python, JSON and Rust highlighting. Highlight removed and resulting source streams separately so removed strings/comments cannot incorrectly color new code. Prepare logical source before tab expansion/wrapping, reset parser context at unavailable gaps and borrow exact ready semantic ranges/styles or permitted flat Pi fallback. Completed Pi ANSI is converted once outside render, not reparsed during layout. Preserve code indentation, whitespace, joined Unicode graphemes and syntax spans. Unknown extensions remain unclassified in the selected palette's neutral code color, without guessed language classification; permitted whole-card Follow Pi fallback follows the syntax contract.

- Keep native syntax foregrounds for keywords, strings, numbers, comments, function/type names and other supported tokens in both removed and added code.
- Under Follow Pi, use `toolOutput` for ordinary code, `dim` for line numbers and `toolDiffAdded`/`toolDiffRemoved` for signs. An independent theme supplies every corresponding card role from its authored TUI data, never from Pi.
- Follow Pi keeps the neutral `toolPendingBg` panel and ordinary `borderMuted` stripe. Locally selected owned palettes provide their own panel/frame/diff palette. Follow Pi derives subdued code and separate number/sign backgrounds; owned TUI themes use their authored context/added/removed surfaces without correction, as specified below. Do not multiply by the bright sign foregrounds. Preserve syntax/sign foregrounds, unchanged rows and exterior frame paint; no global theme edits or OpenCode palette constants.
- Empty split counterparts, wrap-alignment blanks and the final internal right padding retain the effective neutral panel (`toolPendingBg` under Follow Pi), even after a changed cell closes its own background. The common prepared painter explicitly emits those neutral cells; its measured frame does not reopen paint after child resets; do not extend change tint into the exterior margin or alter pane widths.
- Title: muted `← Edited <path>` at the shared frame content origin, exactly like Bash's `# <description>`, without an additional inset. Inline titles use that same absolute content origin and reserve the current exterior right margin before wrapping; only the display label changes, not the tool name or status rules. All file titles, including bounded `Edit` previews, use [shared fragment wrapping](rendering.md#shared-fragment-wrapping): an oversized path starts beside the label rather than moving to a row it cannot fit. Diff starts at that content origin without an extra inset: the shared frame supplies one neutral padding cell on each side. The gutter's own leading space/right-aligned number and code indentation remain part of the diff.
- Addition-only or removal-only diffs use full-width unified view at every component width. Decide from parsed source-row kinds across the entire supplied diff, not proposal arguments, file/header text, code punctuation, a single hunk or wrapped rows. Context/gap rows do not count as changes; context-only metadata also stays unified. For a complete full view, mixed diffs use unified view at component widths up to 120 and split above 120, even when additions and removals belong to different hunks. A bounded preview stays unified at every width, so its visible prefix does not imply complete old/new pairing. Classification happens only during full body construction and requires no file read. Split shows old/new context and pairs runs of removals/additions within each patch hunk, never across unrelated hunks. Independently wrap the panes and insert blank counterparts so the next logical pair stays aligned.
- Display all changed rows, without a Bash-like preview limit. `const DIFF_CONTEXT_LINES = 3` in `src/file-card.ts` limits unchanged logical source rows to at most three before and after each change block, within supplied hunk boundaries. Overlapping windows are merged without duplicates; zero hides all unchanged rows. This is a display-only cap: larger values cannot recover context absent from persisted metadata (Pi's default producer supplies four). Do not reread files or modify result/model/session bytes.
- Prepare all supplied logical regions before projecting display context. Within the admitted classification prefix, a display-hidden opening comment/string still determines visible syntax; unavailable regions reset parser context. The [highlighting volume policy](syntax/work.md#highlighting-volume-policy) limits each continuous old/new logical source to a cumulative 64 KiB UTF-8 / 8,192-line native prefix, with a smaller 8 KiB Pi fallback. The whole SOURCE batch also obeys its aggregate limit. Remaining text stays fully visible in the ready palette's neutral code color; it is not parsed by continuing after a skipped suffix. The internal per-line window does not grant another allowance on each line. Preserve original old/new positions and hunk IDs. Hunk headers/file headers/no-newline annotations are not rendered as source. Remove generated omitted-context rows only at the beginning/end of the projected diff; keep interior omission markers, including when reducing a long unchanged run, and never strip literal ellipsis from source code.
- Unified context uses new-file numbers; removals use old-file numbers and additions use new-file numbers. The numbered format's insertion/removal delta corrects context numbers. Unified patches supply their own hunk starts.
- Tiny widths prioritize code over decorations; omit gutters when no code column would fit. A wide grapheme impossible in a one-column content area uses a safe replacement cell; source/model/session bytes remain unchanged.
- Flattened diagnostics must be an array. Display only object members with exact `severity: "error"` and a string `message`, using the ready palette's `diagnostic` role below the diff: Pi `error` under Follow Pi, the selected TUI palette's authored error color. A positive safe-integer `line` produces `Error [N]: message`; otherwise show `Error: message` without a location. Sanitize and flatten the message. Other severities, numeric LSP severities, range maps and extra fields are not interpreted; columns are not displayed. This is compatible AFT shape coverage, not producer identification, actual AFT execution or an LSP subscription. Pi's built-in edit has no such metadata.
- File tabs expand at four-column stops measured from the original logical-line origin; a soft wrap does not restart those stops. Bash instead uses eight-column display stops. Sanitized logical source retains tabs until measured layout, and source offsets never refer to expanded-tab cells.

### Prepared diff backgrounds

The [color model](color-model.md#derived-diff-backgrounds) owns Follow Pi's four derived changed-code/gutter backgrounds and the separate authored TUI policy. Owned themes also retain independent unchanged-diff code/gutter styles, including diff-number ink distinct from ordinary source numbers. Surfaces are width-independent and do not modify semantic foregrounds. Plain source cards use ordinary `code`/`numbers`; empty split counterparts and exterior padding remain neutral.

## Interaction and retention

Skipping native row construction can leave native self-render height stale while custom output is active. Custom hit testing uses custom row counts and frame geometry; before delegating mouse handling to native, the adapter first renders the native component at the event width to refresh its geometry.

A selection-safe fullscreen primary click inside a completed framed edit toggles its owned bounded/full view; pending details expose a bounded saved excerpt, while failed summaries expose complete available saved details only after funding succeeds. Exterior margins, selection, wheel and secondary events are not new click targets. Ctrl+O remains Pi's global flag but supported completed edit cards use Tidy UI's prepared full view rather than invoking stock work; unsupported saved metadata and missing-path success preserve the native renderer path. A valid supported full edit refused during initial preparation remains owned with the bounded limitation message; if only later width-dependent scene/geometry funding refuses after its logical display is accepted, the failed scene is dropped while the display and measurements remain available for ordinary retry. The automatic full window is a rolling set of the latest ten successful attached write/edit owners in component first-seen order across turns, independent of completion order. During an active turn, an observed owner remains in preview until its matching completion token is finalized for that owner; only then may it enter the current full window. Each `turn_end` folds in the eligible batch and demotes older automatic owners together, while an empty or non-file turn leaves the window unchanged. Filter actual final-success candidates before applying the ten-owner ceiling; removing a recent owner does not promote an older demoted card. Restored cards start bounded and explicit per-owner choices remain separate. No hover behavior.

Retain only the latest rendered rows and frame/native classification in weak component-owned state, without byte/count eviction. Native argument/result updates, expansion, invalidation, width, Output padding, theme and `cwd` changes rebuild the affected custom layout. Warm frames perform no additional custom syntax highlighting or wrapping. Explicit layout-cache clear, off, shutdown and reload release custom retention; lifecycle teardown restores only owned hooks. Same-owner renderer transfer follows the exception below.

Computational performance: prepare logical diff pairing once, retain color-free glyph measurements, and reflow using numeric coordinates. One painter walks ready flat ranges and rows monotonically; it does not parse/slice ANSI or search the whole source/group for each row/range. Palette changes reuse measurements, pairing and reflow; resize retains measurements and semantic/style results. Preserve every space, grapheme, token foreground and multiline state. Resolve owned-palette surfaces outside render once per palette generation, not per row/symbol. Stream source validation and diff emission; avoid argument-spread limits on large changed blocks. Final failures reject stale diff metadata before parsing it, and source without tabs needs no tab-expansion segmentation.

Successful framed diff layouts belong to the `cards` accounting group with Bash and successful write cards. Compact edit lifecycle states, metadata-free headings and native fallback rows belong to `ordinary`. A weak tool state owns just one current layout/group/entry; lifecycle/kind/width invalidation releases its old entry before replacement. Neither group imposes admission, count, byte or recency limits. Ordinary detached removal/nested clear or owner collection releases the component's presentation. Current-renderer clear preserves synchronous same-owner transfer under the [shared lifecycle rule](render-cache-spec.md#invalidation-and-ownership), rather than discarding ready data before the final transcript. No duplicate widths or extra height/visibility cache is introduced in presentation; logical source/colors use the separate shared bounded syntax pool; see the [cache contract](render-cache-spec.md).

Neighbor spacing and rejected mouse events read the already prepared file display. An exact retained scene supplies its row count; otherwise a framed mode needs only its multiline classification, while an inline heading temporarily reflows its existing measured text and immediately releases that reflow. This path neither reparses saved metadata nor constructs/highlights/paints an unretained source body. The standalone `measureFileCard` metadata helper is not the live spacing path; see [prepared-file measurement](rendering.md#neighbor-spacing-without-another-body-build). Pending/failed details share measured summary heights. Detail text is prepared at input/result/expansion transitions rather than during render: collapsed views do not traverse result text, pending full details retain only a bounded excerpt, and final-error result text is retained complete only after ordinary construction funding succeeds and its geometry is measured. Warm rendering and spacing read the retained measured detail; refusal retains no copied body and never invokes stock write/edit preparation. Malformed metadata in an owned bounded preview is represented by a bounded refusal summary; explicitly requested unsupported full metadata uses native rendering. Return existing body rows directly when no outside separator is required. Unknown self-render visibility remains native; the verified stock edit pair needs no native visibility render in any custom lifecycle state or predecessor query. Explicit native presentation, expansion, images, hidden guards and malformed fallback still render natively. Completed compact summaries return retained rows directly when neither animation nor a separator requires composition. No extra height/visibility cache, owner references or invalidation rule is added. Width changes rebuild required presentation but reuse exact classification; a changed code theme resolves only missing styles/palette, never reparses retained source. The presentation cache retains only the latest rendered layout.

See [card validation](testing.md#cards-and-native-data) for metadata, physical-terminal and native live/replay controls.
