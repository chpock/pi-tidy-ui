# Edit card specification

This specification defines the interactive presentation of the exact tool name `edit`. Tool execution, arguments, result bodies and saved session data remain unchanged.

## Authoritative reference

Freshly inspected OpenCode commit `907b3bc518fa48e90e8ec24dd327d13eee71c36c`:

- `packages/tui/src/routes/session/index.tsx`, `Edit` (2390–2441): `← Edit <path>`, block when diff metadata exists, inline otherwise; filename-derived filetype, language syntax inside the diff, line numbers, automatic split above 120 columns, unified otherwise.
- The same file's `BlockTool` (1994–2044): left-only stripe, title inset, padding and neutral panel. pi-tidy-ui retains its already accepted [shared-frame geometry](card-frame-spec.md), including Pi Output padding as exterior margins, fixed one-column inner gaps and no hover.
- Palette cross-check against OpenCode 1.18.33 (`51ef4be1d3c122f18fefb510dca8d778571f4f18`): `packages/tui/src/theme/assets/gruvbox.json` supplies separate, opaque code and number/sign backgrounds. `theme/index.ts` resolves those authored colors; `tint` belongs to generated system-theme colors, not built-in Gruvbox. Under Follow Pi, pi-tidy-ui derives its own surfaces from Pi roles rather than copying these values; an independent theme supplies the native inputs.

OpenCode pins `@opentui/core` 0.4.5. Its published npm `gitHead` is `0c8c4f7cff2927e3df63a9757a45eff9a343611c`; inspected source:

- `packages/core/src/renderables/Diff.ts`, unified/split builders: old/new line numbers, signs **after** the number, unchanged context, paired replacements, blank counterparts and wrap alignment. Code receives a filetype and syntax style; added/deleted backgrounds do not replace token foregrounds. Hunk headers are not code rows.
- `packages/core/src/renderables/LineNumberRenderable.ts`: one gutter space before the right-aligned number, ` +`/` -` after it, one space before code; wrapped continuations have blank gutters.

This is a source-grounded transfer of the display format, not a pixel-perfect OpenCode screenshot or parser-grammar equivalence claim. OpenCode uses Tree-sitter. pi-tidy-ui uses Pi's public filename/language resolver and the [syntax pipeline](syntax-highlighting-spec.md): asynchronous Syntect/two-face classification when Occipital is usable, with native-neutral or explicit whole-card Follow Pi fallback under that contract. Pi palette is the default; an independently selected daemon theme owns the complete card palette without changing diff/frame geometry. No OpenTUI dependency or grammar-equivalence claim is introduced.

## Metadata and scope

`src/file-card.ts` validates saved metadata, prepares logical display/source regions and supplies validation-only measurement; it neither classifies syntax nor paints the card. `src/syntax/cards.ts` owns prepared text and ready paint, `src/syntax/work.ts` applies classification/fallback authority, and `src/syntax/card-layout.ts` supplies the shared layout/painter path. `src/index.ts` remains the sole host adapter. See the [common pipeline and ownership map](architecture.md#syntax-pipeline-and-ownership). Reuse the existing frame, mouse routing, lifecycle hooks and component-owned rendered-layout retention. Diff presentation introduces no source-file read, execution interception or dedicated render timer; native provider lifecycle is separate. Existing native renderer methods, including Pi's own asynchronous preflight preview, still execute unchanged.

Recognize `path`, `file_path` or `filePath`. Format absolute paths relative to the component's native `cwd`, without changing source arguments. Use persisted result metadata only:

1. A present `details.patch` takes precedence and must be a string single-file unified patch; malformed/present unsupported values delegate to native.
2. Otherwise accept string `details.diff` as a unified patch or Pi/AFT's numbered diff.
3. Validate patch hunk counts and numbers; unsupported/malformed formats delegate to native rendering rather than inventing edits.

The host adapter selects presentation by lifecycle state. Before a final result (argument streaming, actual execution, or any partial result), use the compact `edit <path>` summary and its shared execution-only spinner when `path` is a nonempty string, without inspecting any other argument. Otherwise use generic argument formatting. Both follow the [compact preview budgets](tool-summary-spec.md#3-values-budgets-masking-and-sanitization), not the diff-card rules. A final `isError` uses the same summary with every visible segment in the active `error` role, never a stale/proposed diff or result-body preview; native expansion shows the complete available error. Only a final result without `isError` can enter the edit-card presenter. This policy is shared by rendering, predecessor spacing and mouse handling; final updates stop summary animation immediately.

Do not infer success from output or derive a proposed patch from input edits. Do not reread a file that might have changed since the tool completed. For successful results, empty supported diff metadata still gives a titled block; missing metadata retains the inline success title and unsupported metadata delegates to native. The adapter never inspects partial/failure diff metadata for custom presentation.

Image results and intentionally hidden native components remain native. Before custom rendering/spacing/input, the adapter may skip native row construction only for the verified Pi `ToolExecutionComponent` with the exact stock edit call/result function pair from public `createEditToolDefinition` and its current plain call `Box` using stock `render`/`clear`/`addChild`. The native factory can reuse an earlier custom Box even after switching renderers, so the function pair alone is insufficient. Proof is rechecked on every visit without traversing rows; an edit name, schema or execution identity is not proof. Missing getters/component, custom/mixed/replaced renderers, reused custom Boxes and other component implementations retain native width-dependent visibility checks. `--tidy-ui-card edit` explicitly restores native presentation; `--tidy-ui-compact edit` uses ordinary compact rules and takes precedence. Expanded edit calls remain native. Bash, user cards, [write cards](write-card-spec.md), other tools and noninteractive modes retain their existing policy.

## Syntax-colored diff

The syntax language comes from the edited file's path, **not** from a language named `diff`. For example `.ts`, `.py`, `.json` and `.rs` use TypeScript, Python, JSON and Rust highlighting. Highlight removed and resulting source streams separately so removed strings/comments cannot incorrectly color new code. Prepare logical source before tab expansion/wrapping, reset parser context at unavailable gaps and borrow exact ready semantic ranges/styles or permitted flat Pi fallback. Completed Pi ANSI is converted once outside render, not reparsed during layout. Preserve code indentation, whitespace, joined Unicode graphemes and syntax spans. Unknown extensions remain unclassified in the selected palette's neutral code color, without guessed language classification; permitted whole-card Follow Pi fallback follows the syntax contract.

- Keep native syntax foregrounds for keywords, strings, numbers, comments, function/type names and other supported tokens in both removed and added code.
- Under Follow Pi, use `toolOutput` for ordinary code, `dim` for line numbers and `toolDiffAdded`/`toolDiffRemoved` for signs. An independent theme supplies or derives every corresponding card role from native data, never from Pi.
- Follow Pi keeps the neutral `toolPendingBg` panel and ordinary `borderMuted` stripe. Independent themes provide their own panel/frame/diff palette. Derive subdued code and separate number/sign backgrounds from the effective palette, as specified below. Do not multiply by the bright sign foregrounds. Preserve syntax/sign foregrounds, unchanged rows and exterior frame paint; no global theme edits or OpenCode palette constants.
- Empty split counterparts, wrap-alignment blanks and the final internal right padding retain the effective neutral panel (`toolPendingBg` under Follow Pi), even after a changed cell closes its own background. The shared frame restores panel paint after native background/full resets; do not extend change tint into the exterior margin or alter pane widths.
- Title: muted `← Edited <path>` at the shared frame content origin, exactly like Bash's `# <description>`, without an additional inset. Inline titles use that same absolute content origin and reserve the current exterior right margin before wrapping; only the display label changes, not the tool name or status rules. Diff starts at that content origin without an extra inset: the shared frame supplies one neutral padding cell on each side. The gutter's own leading space/right-aligned number and code indentation remain part of the diff.
- Addition-only or removal-only diffs use full-width unified view at every component width. Decide from parsed source-row kinds across the entire supplied diff, not proposal arguments, file/header text, code punctuation, a single hunk or wrapped rows. Context/gap rows do not count as changes; context-only metadata also stays unified. Mixed diffs use unified view at component widths up to 120 and split above 120, even when additions and removals belong to different hunks. Classification happens only during body construction and requires no retained metadata, new cache key or file read. Split shows old/new context and pairs runs of removals/additions within each patch hunk, never across unrelated hunks. Independently wrap the panes and insert blank counterparts so the next logical pair stays aligned.
- Display all changed rows, without a Bash-like preview limit. `const DIFF_CONTEXT_LINES = 3` in `src/file-card.ts` limits unchanged logical source rows to at most three before and after each change block, within supplied hunk boundaries. Overlapping windows are merged without duplicates; zero hides all unchanged rows. This is a display-only cap: larger values cannot recover context absent from persisted metadata (Pi's default producer supplies four). Do not reread files or modify result/model/session bytes.
- Prepare all supplied logical regions before projecting display context. Within the admitted classification prefix, a display-hidden opening comment/string still determines visible syntax; unavailable regions reset parser context. The [highlighting volume policy](syntax-highlighting-spec.md#highlighting-volume-policy) limits each continuous old/new logical source to a cumulative 64 KiB UTF-8 / 8,192-line native prefix, with a smaller 8 KiB Pi fallback. The whole SOURCE batch also obeys its aggregate limit. Remaining text stays fully visible in the ready palette's neutral code color; it is not parsed by continuing after a skipped suffix. The internal per-line window does not grant another allowance on each line. Preserve original old/new positions and hunk IDs. Hunk headers/file headers/no-newline annotations are not rendered as source. Remove generated omitted-context rows only at the beginning/end of the projected diff; keep interior omission markers, including when reducing a long unchanged run, and never strip literal ellipsis from source code.
- Unified context uses new-file numbers; removals use old-file numbers and additions use new-file numbers. The numbered format's insertion/removal delta corrects context numbers. Unified patches supply their own hunk starts.
- Tiny widths prioritize code over decorations; omit gutters when no code column would fit. A wide grapheme impossible in a one-column content area uses a safe replacement cell; source/model/session bytes remain unchanged.
- If supplied, flattened AFT error diagnostics are displayed below the diff with their one-based line and error color. This is shape coverage, not actual AFT execution or an LSP subscription. Pi's built-in edit has no such diagnostics metadata.

### Derived diff backgrounds

The ready palette contains four prepared diff backgrounds, independent of terminal width. **Follow Pi** builds them in `src/diff-palette.ts` from the exact public panel/hints and directly bound syntax inks. Those surfaces are frozen before optional role-derived marker inks are selected; marker candidates are checked against the finished surfaces and never cause them to be refit. The following algorithm describes that adapter. **Independent themes** use the Rust palette derivation over native base/gutter colors, genuinely authored inserted/deleted hints and the native syntax inks actually painted. Missing hints derive from native data only; an unsafe tint falls back to the native neutral base. Per-token syntax backgrounds never overwrite diff surfaces.

1. `toolPendingBg` is the neutral base. `toolSuccessBg` and `toolErrorBg` supply author-selected semantic hints for added/removed code. A neutral hint stays neutral; missing hints use the base. Missing concrete base/style support leaves existing neutral rendering intact.
2. Convert to OKLab (lightness and two Cartesian color axes). Limit semantic displacement to 0.025 lightness and 0.018 chromatic-vector length. This retains a theme's warmth without inventing a green/red minimum saturation. Gamut conversion and RGB rounding are checked too: actual displacement may exceed those bounds only by quantization allowances of 0.002 lightness/0.003 chromatic length.
3. Check final concrete RGB relative-luminance contrast against `toolOutput` and Pi's directly bound syntax foregrounds. Each must retain at least the lesser of 4.5:1 and its original neutral-panel contrast. Optional role-derived marker inks are not constraints at this stage; they are checked against the already-frozen surfaces. Correct lightness within the same bounded interval while retaining chromatic intent; if no checked candidate is safe, use the exact neutral base. The bounded search never returns an unchecked color.
4. Start the number/sign area from its code surface and consider a 0.025 lightness shift in either direction. Prefer the direction with better worst normalized number/sign contrast: darker for ordinary dark palettes, lighter for ordinary light palettes. Check `dim` against the lesser of 3:1/original contrast and the sign against the lesser of 4.5:1/original contrast. Use the neutral fallback when needed rather than forcing separation.

This is OpenCode-style visual hierarchy, not literal reproduction of a hand-authored OpenCode theme. Foregrounds remain unchanged. Already-low-contrast themes, terminal font/faint rendering, 256-color quantization/custom ANSI palettes, and separately selected Occipital foreground themes do not acquire a universal accessibility guarantee. Plain `Created`/`Wrote` source has no diff surfaces.

## Interaction, retention and verification

Completed successful framed edits use the existing selection-safe panel click bounds to reveal native content; completed failed summaries expand through ordinary compact-summary click routing. Exterior margins, pending calls, selection, wheel and secondary events are not new click targets. Ctrl+O remains Pi's own global toggle. No hover behavior.

Retain only the latest rendered rows and frame/native classification in weak component-owned state, without byte/count eviction. Native argument/result updates, expansion, invalidation, width, Output padding, theme and `cwd` changes rebuild the affected custom layout. Warm frames perform no additional custom syntax highlighting or wrapping. Explicit layout-cache clear, off, shutdown and reload release custom retention; lifecycle teardown restores only owned hooks. Same-owner renderer transfer follows the exception below.

Computational performance: prepare logical diff pairing once, retain color-free glyph measurements, and reflow using numeric coordinates. One painter walks ready flat ranges and rows monotonically; it does not parse/slice ANSI or search the whole source/group for each row/range. Theme changes reuse measurements, pairing and reflow; resize retains measurements and semantic/style results. Preserve every space, grapheme, token foreground and multiline state. Resolve palette surfaces outside render once per palette generation, not per row/symbol. Stream source validation and diff emission; avoid argument-spread limits on large changed blocks. Final failures reject stale diff metadata before parsing it, and source without tabs needs no tab-expansion segmentation.

Successful framed diff layouts belong to the `cards` accounting group with Bash and successful write cards. Compact edit lifecycle states, metadata-free headings and native fallback rows belong to `ordinary`. A weak tool state owns just one current layout/group/entry; lifecycle/kind/width invalidation releases its old entry before replacement. Neither group imposes admission, count, byte or recency limits. Ordinary detached removal/nested clear or owner collection releases the component's presentation. Current-renderer clear preserves synchronous same-owner transfer under the [shared lifecycle rule](render-cache-spec.md#invalidation-and-ownership), rather than discarding ready data before the final transcript. No duplicate widths or extra height/visibility cache is introduced in presentation; logical source/colors use the separate shared bounded syntax pool; see the [cache contract](render-cache-spec.md).

Neighbor spacing and rejected mouse events may read an exact existing retained layout, using the same signature as rendering. On a miss, validate/classify metadata without materializing source, highlighting, painting, retaining a layout or retaining an additional summary. Successful framed spacing needs only the multiline class; successful metadata-free headings require their exact wrapped height. Pending/failed edits use ordinary summary heights instead. Malformed metadata still delegates to native. Return existing body rows directly when no outside separator is required. Unknown self-render visibility remains native; the verified stock edit pair needs no native visibility render in any custom lifecycle state or predecessor query. Explicit native presentation, expansion, images, hidden guards and malformed fallback still render natively. Completed compact summaries return retained rows directly when neither animation nor a separator requires composition. No extra height/visibility cache, owner references or invalidation rule is added. Width changes rebuild required presentation but reuse exact classification; a changed code theme resolves only missing styles/palette, never reparses retained source. The presentation cache retains only the latest rendered layout.

Follow the shared [testing and coverage guide](testing.md). Required edit-specific checks:

- Regression-first unit tests for title alignment, configurable context limits/overlap, edge/internal markers, metadata formats, line numbers, unified/split threshold, one-sided changes in numbered/unified metadata, multi-hunk/global classification, metadata transitions and warm-cache reuse, wrapped alignment, syntax foreground preservation (including tokens opened in hidden context), semantic neutral/hue behavior, bounded actual-RGB displacement and contrast (including black/white, saturated and indexed inputs), file-type dispatch, cache reuse, terminal controls, Unicode, widths and policy/lifecycle safeguards. Cover argument streaming, execution, partial errors/proposed metadata, final success/failure transitions, whole-summary failure colors, shared clock stop and native visibility/override/expansion safeguards. Count grapheme work and bounded color identities, assert linear ANSI-output growth, uncached spacing/rejected-event work, final-error metadata bypass, measurement/render equivalence and changed blocks above argument-spread limits.
- Real Pi CLI with actual built-in edit execution and native controls: physical syntax-colored screen cells, builtin dark/light and the Gruvbox fixture, widths 24/100/140, errors, mouse/keyboard expansion, off/on/reload, warm-cache counters and fullscreen/regular same-session replay.
- Exact call/result/model-context and persisted metadata equality; session bytes unchanged after UI operations. Native overrides use **same-session native replay** as their control: Pi's live native call can have an async preflight error preview inside its header, while replay lacks that preview and renders the persisted error in its result region. Do not normalize away that native distinction.
- Independent fresh-file review against this contract and the authoritative source references. Record source-bound evidence, findings and remaining limits under gitignored `.test-artifacts/`.
