# Source and style work

`SourceExecution` is the canonical authority for source work and fallback permission. `CardSources` supplies useful weak owner registrations; transport disappearance, retained paint and source execution evidence are not interchangeable. See [providers](providers.md), [request settlement](requests.md), [storage](storage.md), and [prepared cards](prepared-cards.md).

Useful card preparation either refreshes existing paint or evaluates a batch of fragments under one funded scratch hold. The card owner admits each key and records its attempted slot before calling `requestSyntax`. That API asks execution for actual native/Pi permission; the slot and chosen palette cannot grant it. After each request and its diagnostic observation the owner rechecks registration, pause and mutation before asking for the next fragment. Abandoning a traversal does not remove keys from a still-registered incarnation or cancel already admitted physical work. Only a finished traversal installs the attempted slot set and reports completed preparation; this is not a claim that its SOURCE/STYLE RPCs finished.

## Execution and registry boundaries

`SourceExecution` owns source incarnations, parser leases, all physical SOURCE/STYLE/CLOSE jobs, execution evidence, the shared retention pool, chronological visit policy and fallback permission. Its one private `StylePublication` owns desired style selection, STYLE attempts/refusals and expression-cache metadata, source display receipts/coverage, group seals/ready publications and reader validity. Physical cancellation, logical removal, lease obligations and credit refunds remain together in execution, including receiver-free cleanup after collection. Publication neither acquires a provider nor creates a scheduler, timer, credit pool or second source owner.

The owners share the existing flat source records and registry nodes through type-only views in `execution-records.ts`: publication can read presentation-relevant SOURCE facts and write display fields, but cannot change source identity, pending/turn metadata or physical reservations. The same cleanup sets and counters are shared; no per-source/job/group wrapper or duplicate readiness state is introduced. There is one additional fixed private collaborator with dependency references per execution root; this is not a claim of lower JS heap or RSS.

The stable `pi` capability is the `PiFallbackCoordinator` in `src/highlighting/pi-fallback.ts`: that coordinator owns Pi source/generation maps, cached projection/failure/refusal state and the funded classifier-to-flat-payload transaction, while using the same root charge, wire-key, receipt and change-notice authority. It does not own native execution facts or decide when classification is permitted. `src/highlighting/work-registry.ts` owns the one chronological map, links, cursor, pass/refresh revisions, pending/pause state and host-turn quota. The registry uses the execution owner's existing weak token and completion lifetime; it has no second source ledger, physical credit pool or queue. Execution owns the complete visit policy and reads current source facts rather than copying fallback permission into scheduling flags. The registry exposes mechanical membership, cursor, pending, pass and quota operations; its only retained weak continuation capability requests an ordinary work turn or the host-turn preparation continuation.

`src/highlighting/source-ports.ts` defines the card, source-work, lifecycle, pump and statistics views; `PiFallbackPort` in `src/highlighting/pi-fallback.ts` defines the separate Pi capability. Application composition exposes these stable views from the same execution object; custom internal wiring must preserve that identity rather than inject independent source owners. Card and fallback consumers do not import the application client or gain a second source owner. Local-only presentation uses the same execution model with an unavailable provider, not a separate scheduler or budget.

Execution chooses useful preparation in the registry's chronological order and keeps the current-group window open through both `prepare()` and membership sealing, then clears it in `finally`. The registry never calls source dispatch, style preparation, provider reconciliation or publication policy. Execution alone associates source incarnations and decides fallback permission. It invokes complete publication operations at the existing synchronous receipt, source-adoption and lifecycle boundaries; publication owns the display writes and validity predicates, rather than returning fields for execution to repair. `card-publication.ts` supplies seal/ready shapes and drop/weak-borrow lifetime operations, not another live publication authority. Each registration supplies one domain-metadata object; the registry adds its link/pass fields to that same object, so the scheduling node is not wrapped or duplicated. Registry alone changes linkage, pass and pending metadata. Removal reports withdrawal, clears pending work, releases funded group state and retires bound STYLE payloads before unlinking. SOURCE/CLOSE settlement removes its logical job membership, then supplies the current logical-key entry and whether source/style execution is still owed to the registry's revisit operation. The registry checks its own visited-pass and pending/refresh metadata, including for a replacement incarnation; STYLE settlement retains its unconditional registry rewind.

## Demand, execution and display advance independently

The execution root and its private publication owner expose three independently advancing kinds of information, never one readiness flag:

- **Current demand:** the owner’s requested text version, syntax hint, completion state and desired presentation.
- **Execution evidence:** queued work, physically held SOURCE jobs, validated outcomes and unresolved earlier execution.
- **Ready display:** a retained semantic view and its complete concrete palette/styles.

A source can have newer demand, an older request in flight and an even older ready display at the same time. Bash may reuse matching-prefix colors from that display; files require exact compatible coverage. Neither display path changes execution evidence.

`observe` records demand outside rendering. Demand normalization, existing-input inspection, initial admission and replacement are separate operations in the execution owner. The pure `classifySourceInput` projection in `source-state.ts` identifies equality, syntax/formation changes and rewrites from the already borrowed snapshot; execution asks publication to apply the display alias before changing the source version and retains the admission/receipt sequence. Source versions must be monotonic, and a version cannot silently acquire different text. Same-version warm observations can therefore return without another source-prefix check or source-text byte measurement. New source text is admitted to the retention root before becoming dispatchable. Useful preparation may admit a funded empty target before provider readiness too; that record is neither a parser acknowledgement nor useful acquisition/parsing demand. Empty input alone sends no SOURCE request and sustains no recovery wake. Its locally installed zero-byte ranges can be exact for display, but do not supply `acknowledgedVersion`, even after replacing previously parsed text on the same provider. That version comes from retained native ranges for the ready parser namespace. A final append with an empty suffix still acknowledges nonempty total source.

Native demand and Pi capture share the pure `sourceIdentifier` validator in `src/highlighting/controller-limits.ts`: logical keys are nonempty strings of at most 64 UTF-8 bytes, language hints at most 128 bytes, and native path hints at most 4096 bytes. Bounds are inclusive; control characters and unpaired surrogates are rejected, while valid supplementary Unicode and format characters remain permitted. Inputs are neither coerced nor truncated. Native demand treats an empty language hint as absent; Pi capture rejects an explicitly empty hint.

`src/highlighting/source-state.ts` defines flat SOURCE facts and pure, purpose-specific projections. The execution aggregate alone writes admitted input revision, captured attempt outcome/cause, scoped local refusal, intentional ready-namespace priority, one-use eviction entitlement and absolute retry deadline; there is no writable SOURCE `dirty`, `blocked` or `uncertain` summary. Execution also remembers which pool generation has already received credit for a dispatch wait in the [eviction order](storage.md); that number is not permission to parse or proof of execution. Stored progress, actual held operations and the separate owned/shared history qualify each decision. To decide whether the current text still needs parsing, the queue observes its snapshot version and retained range progress together, without building a storage accounting report or changing which source will be evicted under pressure. In a single dispatch visit on an unchanged route, execution checks the physical key and the available text once. Without current text there is no retry or parse to schedule, so this check precedes collecting the deadline and parser compatibility. These observations do not survive a route reconciliation, which can retire work and replace or lose the source generation. Each new decision checks the current facts; a previously ready display is not parser evidence. The provider field identifies the pool's parser-route namespace. First funded admission uses the current broker generation provisionally, including before readiness; actual ready namespace and negotiated limits are reconciled before dispatch. A later unavailable broker epoch does not rebase an existing source's execution evidence. `styleDirty` remains the explicit STYLE reconciliation token, not a SOURCE or display-readiness flag.

The existing continuation slot distinguishes no continuation (`undefined`), a usable lease token (string), and correlated parser-state loss (`null`). A loss is qualified by source incarnation, parser generation and ready provider, not the latest input token: compatible growth or finalization cannot make that continuation usable. Its known lease moves to ordinary funded CLOSE handling immediately; replacement pool admission waits for the paced useful dispatch. The lost value survives same-formation reconstruction allocation, credit waits and storage eviction without admitting a replacement snapshot merely to wait. A proven incompatible rewrite or changed syntax starts ordinary fresh work; the node's reconstruction-start deadline remains for later losses. A newly reconciled provider namespace also has no continuation from its predecessor. These values reuse one source field, not an additional flag, lease ledger or timer.

Equal text can acquire a newer logical version without invalidating its semantic content. `contentVersion` records the beginning of that equal-content interval. It permits local coverage reuse; it does not rewrite the remote acknowledgement version or pretend that a completion request has already settled.

The syntax identity includes the selected explicit `language` (when present), `path` and source version. A changed first-line interpreter changes the explicit language and therefore invalidates source reuse even if the displayed body is unchanged. The bounded alias detector, per-side hint propagation and split/unified painting contract are described in [shebang-derived hints](shebang-hints.md). A style or palette change alone never changes this parser identity.

## One chronological registry, two separate admission questions

A card registers a `SourcePreparation` before expensive demand construction. Its registration contains a weak preparation reference and the existing set of source keys. A standalone source registers on first admission. Both occupy the same linked chronological registry.

The newest registration is visited first: **last registered, first considered**. Updates, retries and palette changes rewind the scan but do not move an older owner to the front. There is no sorted palette queue and no list of strong card/text subscribers.

Two different limits apply during a pass:

- The **host-turn preparation quota** bounds how many owners are reconsidered before yielding to the event loop.
- The **physical job/byte authority** bounds operations whose settlement is still outstanding.

Reaching one is not proof of reaching the other. One execution-owned credit-deferral operation records retry interest and restores the current cursor only when no cheaper local or style work can continue; standalone SOURCE, preparation admission and grouped SOURCE visits use that same rule. The execution owner's physical-key query reads the same weak lifetime jobs with an explicit purpose: fallback counts held SOURCE without matching stop proof; native serialization counts SOURCE and CLOSE even after such proof; all-kind occupancy includes STYLE too. No predicate callback, secondary index or copied permission is retained. Source, style and queued lease-close operations use the controller’s physical DATA jobs. Transport admission and the provider’s negotiated per-route limit remain additional checks. The module-level `flight` counters cover simultaneously living controllers from that module incarnation; they are not a cross-reload ownership registry. SOURCE, STYLE and CLOSE have separate typed operation data; CLOSE needs no source incarnation. Logical job removal and physical credit return are separate steps of [terminal settlement](requests.md#a-request-carries-a-captured-expectation), so local transient bytes remain authoritative until the receiver-free completion callback finishes.

A normal `flush` enters the execution owner's single visit driver without draining deferred render-pressure retirements; the weak asynchronous continuation drains those retirements first. Both use the same registry pump and host-turn quota, so neither synchronous flushes nor microtasks create a new allowance. A visit proceeds as follows:

1. Reconcile the published provider generation and discard obsolete remote-lease bookkeeping.
2. Dispatch eligible queued lease closes within the same physical capacity, avoiding a source that is still busy.
3. Resume the existing registry cursor from the newest unvisited work.
4. For each entry, try applicable style progress. Cached local progress must not wait merely because unrelated native jobs occupy both slots.
5. For a preparation entry, check its weak owner, pause state, pending flag and metadata-refresh revision. Ask `needsRefresh` lazily rather than eagerly traversing all cards when metadata changes.
6. Run `prepare` only if it is useful and its required admission is available. Source ownership that is still physically busy can be skipped while another owner uses available capacity.
7. Update the group’s membership seal, reconsider styles produced by the preparation, then dispatch eligible member sources.
8. Yield after the preparation quota. `setImmediate` resets that quota on a later host turn; synchronous flushes and promise microtasks cannot reset it.

A native-capacity failure records the need for another scan. Local-only pending work can continue past blocked native entries. Actual physical credit release wakes weak controller waiters and rewinds where necessary. This preserves progress for cached palette restoration without turning every warm frame into an admission attempt.

## Coalescing source updates and completing a stream

While a SOURCE request is outstanding, newer observations replace the latest admitted snapshot rather than creating parallel appends for that source. The request retains its own captured input and expected acknowledgement. When it settles, ordinary registry work considers the newest demand, not a stored queue of intermediate append packets.

`prepare` chooses the operation from current parser authority:

- No lease and complete input: finite `highlight`.
- No lease and growing input: `stream.open`.
- Validated lease: `stream.append` against its acknowledged revision and full-input byte count.

Append replies replace the provisional suffix beginning at the last committed boundary. A validated result advances the acknowledged basis, committed offset and lease state. It does not necessarily satisfy newer demand already observed while it was running.

Completion is a real authority transition even when no characters were added. A final append may carry an empty added string while closing the incremental parser state. Range adoption compares actual coverage/effects separately from revision metadata, so this acknowledgement need not rebuild identical geometry or paint.

The source's continuation field records only a validated live lease, its correlated loss awaiting reconstruction, or absence of a continuation. Validated SOURCE settlement supplies the lease; retirement, incompatible input, provider replacement and data eviction withdraw it. Re-observation may preserve a known loss marker but cannot recreate a lease. The separate eviction entitlement is granted explicitly, advances to dispatch only after full source re-observation, and is consumed once on dispatch; equal frames cannot grant another entitlement. Neither field is historical paint or Pi-permission proof.

A rewrite, changed syntax identity or resumed growing formation cannot reuse a lease merely because a display exists. Restart logic selects a fresh parser basis while preserving an independently owned display where allowed. Complete semantic coverage can survive compatible provider recovery only when its vocabulary and source identity still match; asset identity is already represented by the vocabulary fingerprint. An incomplete parser state does not acquire a portable lease across providers.

The [prefix policy](#highlighting-volume-policy) applies before this process. Saturating the useful prefix makes the submitted source finite even if the complete displayed Bash command is still growing. Completion, offsets and revisions describe that prefix only.

## Refusals and held outcomes

When `workStatus` computes fallback permission, it first checks physical SOURCE jobs by logical key, including jobs whose payload or old state has been retired. A state without retained ranges can still have held native work. It also considers ready queued demand, frozen state, current uncertainty and earlier owned/shared unknown guards.

An observation-time SOURCE input-limit refusal leaves no current pool snapshot and records the broker generation that evaluated the input. It remains protective for that input without rebasing an older parser namespace; identical observations on the evaluated provider neither rescan text nor request another frame. A different provider permits reevaluation against its negotiated limit. By contrast, a negotiated byte-limit refusal during dispatch retains its funded snapshot and parser-provider qualifier: a later reconciled ready namespace can retry that snapshot against its own limit without a new observation. Local pool-admission refusal instead applies to the current input regardless of parser namespace: a failed snapshot replacement can retain older text in the same allocated generation. Every observation-side storage writer, including Bash target restart, records the evaluating broker generation for the cheap observation guard without rebasing the parser namespace. Changed-provider observation may reevaluate admission once; identical observations on that evaluated route repeat neither scanning nor pool admission. Parser-specific request, encoding and adoption refusals retain their own namespace/generation qualification. Re-observation under new input or negotiated limits can reevaluate admission. A local pre-dispatch refusal or a validated remote no-start fault can establish the disposition of that attempt. An arbitrary rejection or malformed response cannot. A later successful request does not erase an earlier shared unknown outcome. A no-start receipt suppresses future work only while its input qualifies the current live SOURCE interest. A retired operation still records its truthful outcome, provider and cause, but omits that forward input qualifier; unchanged live refusal remains scoped normally. This keeps native dispatch and queued-native priority consistent without changing input identity. Refused current input without usable payload contributes no queued SOURCE priority. On an active ready route, once independent held, uncertain, frozen, withdrawal and missing-STYLE barriers permit file Pi fallback, `requestSyntax` reports `refused` rather than waiting for nonexistent SOURCE work. A native result usable through the card's current borrowing and display predicates needs no Pi fallback. Bash never gains Pi classification.

Native queueing, next-work decisions and provider reconciliation require a pooled latest version within the current content-version interval, not merely an allocated generation. This constant-time check preserves proved equal-content aliases and completion but excludes older text left after refused growth. If a later observation proves equality with that still-owned snapshot after an intervening refusal, it restores the earliest applicable content version from the snapshot even when allocating the new logical-version alias fails. This reuses the matching classification without fabricating an exact-version `borrowSource()` alias; a successfully funded intervening different text still requires ordinary parser replacement. Explicit retry permission cannot supply missing current input or create queued-native re-entry priority at intentional retirement. An actual older held request retains its separate withdrawal/physical evidence even when the newer target was refused. Warm observation likewise cannot report current payload acceptance from an older allocated snapshot. Older in-flight operations still settle and may adopt their qualified prefix normally; their evidence and retained display do not authorize a new old-input request for the refused target.

Retirement requests cancellation but does not refund physical credit. Normal settlement releases the job’s reservation. Actual owned-helper cleanup can additionally supply generation-qualified stop evidence; it cannot clear an earlier shared attempt. STYLE success and retained colors never supply that proof.

Validated SOURCE success remains useful execution evidence even if local storage pressure refuses its colors. In that case the controller closes any returned live lease as needed, blocks the unfunded demand and retains the established display policy. It does not reinterpret a storage refusal as “native parsing never happened.”

Recovery permissions are explicit rather than frame-driven. Applicable typed temporary SOURCE refusals and unusable resolved individual replies retain a per-target absolute minute deadline. An unclassified request-promise rejection before response decoding, without a recorded retirement origin and on a still-current ready route, preserves unknown execution with the bounded `other` disposition, not an inferred temporary cause or a new deadline; the same applicable input waits for actual new input/provider facts. It does not establish permanent input invalidity or retire an otherwise healthy route. Meaningful funded input changes or an applicable success clear it; equal/unproved readmission and provider replacement do not. Effective Native Off clears that individual delay without resetting the broker service deadline. An individual SOURCE deadline paces data dispatch, not useful restoration of a missing connection: deterministically refused targets cannot request acquisition, but a useful delayed target can reconnect before its original SOURCE deadline. `restart_required` instead uses the surviving work node's independent reconstruction-start deadline: first immediately, later starts at least a minute apart across success, without lifetime exhaustion. On the same evaluated route, evicted unchanged demand needs explicit retry permission followed by full current observation; an actual changed-provider observation retains its separate admission-reevaluation opportunity. Neither opportunity erases execution history, supplies missing storage funding or bypasses independent deadlines. Provider/source recovery never depends on palette metadata; local palette asset failures have their own bounded issue and recovery lifecycle. See [provider recovery](providers.md).

Execution and its broker share the composition-selected monotonic clock. Each useful positive visit immediately arms an earlier strictly future SOURCE/service deadline on the single weak unref'd wake, without waiting for older owners or whole-pass exhaustion. Visits also retain one minimum across host turns of the actual registry pass; a quota yield, credit break or rewind is not proof that earlier delayed need vanished. Only exhaustion of a still-current pass may cancel an absent minimum or replace the wake with that pass's future minimum. If a pause crosses an already-armed deadline, an older continuation must leave its due delivery intact. Firing clears its own handle and requests an ordinary rewound visit, without doing work directly, resetting the host-turn quota or returning credit. Stop, Native Off, disposal and execution finalization cancel the handle. Its complete bounded control lifetime is covered by the existing prepaid128-byte execution allowance, not a failure-time reservation; broker timers remain separate legitimate clock users.

Native Off releases native payloads and ready groups but preserves records needed for held, frozen or uncertain source authority. It ends any old no-start forward qualifier on those retained records, just as deleting an unneeded record would; a late retired no-start cannot restore it. Fresh useful On admission therefore does not depend on whether the old metadata survived for another obligation. Truthful execution, independent uncertainty, deliberate-withdrawal receipts and held physical credit remain intact. Complete owner removal is a different boundary; its accepted reinstall exception is described in the provider chapter.

## STYLE work uses scopes, not another parse

Style selection is prepared separately from source observation. `setStyleSelection` installs a funded immutable generic rule definition and local bindings/roles, then advances style work; changing rules or palette input is not a reason to rewrite source text or reopen a parser lease.

A missing-context STYLE request may be shared by multiple card owners. One bounded outcome records its provider, terminal cause and any absolute retry deadline; both the dispatched owner and coalescers keep their qualified reference. The operation retains this primitive outcome after released captures/payloads, so actual settlement can record withdrawal without retaining contexts. Deterministic generic denial and pre-installation local refusal remain shared. Invalid native replies, temporary no-start admission failures and started `data_limit` instead permit useful retries60 seconds after the actual failure, without a lifetime cap or healthy-route replacement. Late coalescer visits and local bindings do not move that deadline. After valid expressions are installed, later cache-metadata, local funding or presentation-publication refusal belongs only to the owner whose local publication failed; it must not mark a coalesced peer's generic STYLE attempt failed. That owner keeps its prior complete paint and may retry local materialization after a relevant palette or binding change without another STYLE request. A peer with sufficient local credit can still publish the expressions already installed for the shared rules and contexts.

`src/highlighting/style-state.ts` supplies pure cause/opportunity projections; it neither schedules nor reads owners. `src/highlighting/style-preparation.ts` only collects unique/missing context handles and estimates encoded/captured representation sizes. `StylePublication` owns selection and STYLE/display mutations, reserves scratch through the same retention pool before collection, and counts visits even if traversal refuses or throws. Every resulting release receipt is consumed synchronously by execution before publication continues. Local cached publication, full-credit, overlap and descriptor gates precede representation probes; real capacity admission precedes retained capture and encoding. The helper holds no selection, jobs or charges between calls.

For each eligible registry entry, `StylePublication.prepare` qualifies the subject and any recorded failure, validates member coverage/current display, then runs the funded context-preparation operation. Without a matching failure, a current or locally satisfiable subject needs no remote-request decision. A known failure may need its retry decision before repeating an unchanged negative check. After the selection predicate and before deciding whether to request missing contexts, publication checks that the same active node, selection and subject revision still own the visit. A callback that reseals the group cannot turn the old subject's cleared retry record into permission to request styles for withdrawn members. The membership revision alone cannot identify a Bash source rewrite under the same key. Member qualification, context collection and the final handoff require the current source identity and generation (the retained display generation for a frozen source). A superseded parser generation cannot dispatch STYLE simply because its scopes are still retained. Qualification reads the member’s current range facts again after the selection callback and after installing local empty coverage; it does not carry a storage report across either boundary. A current missing-context request reads eligibility after preparation, not a decision saved across callbacks. Its outer refusal handler encloses those operations; scratch and pending captures have their own inner `finally`. It determines the vocabulary from its actual semantic data. Frozen owners use their retained display view. It obtains unique live context handles through the incremental context index, then subtracts expressions already present for that vocabulary/rule identity. Subject revision changes with accepted new SOURCE semantics or membership, not appearance or compatible pool/provider rebinding. A neutral-role rebind preserves an already qualified generic attempt and its negative cache observation, whether it occurs before or after settlement; it still schedules local rematerialization from available expressions. A valid held STYLE success can therefore complete an unchanged compatible subject across a provider-identity change without another request or a new SOURCE acknowledgement. Local completeness is checked before requesting unavailable-provider recovery: only actual missing expressions sustain that recovery, and compatible complete scopes keep their original pool generation without SOURCE replay or mechanical re-admission. A newly ready parser namespace is reconciled only when actual SOURCE work is needed; compatible cached scopes are not a new parser acknowledgement. The ready-route full-DATA shortcut cannot replace that check merely because an unavailable route has zero negotiated dispatch slots.

If all expressions and required roles from the current local palette input are available, publication is local. Follow Pi binding changes can materialize the same expressions with new public colors. Cached owned-palette roles permit equivalent local restoration. These paths can proceed while native DATA capacity is full. Local rematerialization may increment `stylePublications` while `styleRequests` stays unchanged; publication is not evidence of a new generic STYLE operation. Deferred Pi-palette invalidation compares the configured public input's projected color object and output mode, not a second native theme object. The initial projected identity is recorded even when an external owner declines input; unchanged warm frames do not requeue palette preparation. Refreshing colors never makes a zero-width or hidden owner useful: paused owners resume only at the normal visible/useful boundary.

A local materialization or publication refusal is recorded against the current palette and binding revision as well as the existing rule/cache and source-work identities. Replacing that palette input may therefore retry already cached generic expressions without another STYLE request. A deterministic denied STYLE request for genuinely missing contexts stays suppressed for the same rules and source work even when only bindings or card roles change. A retryable result keeps its original absolute deadline across those changes. Local color changes supply neither new generic permission nor a new delay; cached local publication remains independent. If a changed expression cache still lacks the required contexts, remember that new cache revision even while native retry remains deferred. Unchanged visits then reuse the negative observation without repeating preparation or context traversal; actual later cache progress permits local completion before the native retry deadline.

Otherwise publication asks execution for a readonly overlap view of existing physical STYLE jobs with the same vocabulary/rules and intersecting missing handles. Those few jobs are the overlap index: there is no separate subscriber queue. A coalesced owner can retain a primitive outcome receipt, while an ordinary credit wake revisits its registry entry. This prevents duplicate matching without retaining the waiting card through another owner list.

Before encoding missing descriptors, publication funds the full incremental peak through the shared pool, while execution alone admits the physical job and credit: encoding, captured semantic views, decoded result and complete materialization workspace. Materialization needs all captured contexts, not just the missing subset, because parser progress can occur before the reply arrives. Before handoff, preparation owns its temporary capture and can release it. After handoff, publication receives a read-only TypeScript view of the attached payload, capture group/members and measured reply size, plus the intentionally writable STYLE outcome. Execution retains the release and refund operations; the view uses the original objects and adds no runtime wrapper.

A valid obsolete reply may still install immutable expressions into the accounted cache. Publication has stricter checks: current selection, vocabulary, owner, membership revision and pause state must still agree. A paused card cannot receive the old dispatched STYLE as new ready paint, though accepted expressions may later be reused on resume. A frozen card can recolor its retained view without reviving SOURCE.

Positive coverage witnesses avoid repeatedly enumerating a group already known to have all required expressions. They identify the semantic source/view and arena invalidation revision. Actual expression loss invalidates that witness; merely changing metadata does not.

## Sealing and publishing one card

A **group seal** is the controller’s funded record of a preparation’s ordered source keys and their current owner incarnations. Its data shape and the ready-group records live in `src/highlighting/card-publication.ts`; `SourceExecution.updatePreparation` delegates seal creation/reuse to `StylePublication` after logical preparation within the same current-group window, and registration alone does not establish useful membership. An explicit membership edit outside `prepare` must update it as well.

Style work checks the seal before capturing candidates and again before publication. Reusing a key for another source incarnation cannot make an old reply a member of the new card.

`StylePublication.publishStyles` constructs complete concrete roles and context styles for every member. After the retention root funds the aggregate old/new peak, `SemanticRetentionPool.publishDisplays` delegates the synchronous plan, stage, abort and commit lifecycle to `ReadyDisplayPublication` in `src/highlighting/storage/ready-display-publication.ts`. The pool remains the sole index, pressure, reaccounting and release-receipt authority. `card-publication.ts` handles ready-record replacement and weak synchronous reader holds only; publication validates the live group and owns the ordering between pool publication, source stamps/coverage and group adoption. Only after successful grouped adoption does it ask execution to release a superseded SOURCE basis. All members must agree on vocabulary, rules, palette and binding identity; captured members must belong to the expected capture group. No user callback runs during the commit.

Publication installs per-source display receipts and asks execution for key notices before attempting card-group adoption. The whole sequence is not a rollback transaction: a refused group can leave those source displays and notices committed, without a new group notice. Superseded source bases are released only after successful group adoption. Publication installs the card group's semantic roles and member readers. Card preparation captures accepted display spans and styles under its own charge. This display data can survive parser-entry eviction but does not convey SOURCE, STYLE or Pi-classifier permission. A successful outer synchronous borrow validates ordered membership once before visiting and once at its final boundary; nested reads reuse the held publication while retaining their immediate invalidation guards. The publication helper owns the hold/unwind and single final boundary check, delegating validity to `StylePublication` through the existing weak-root delivery rather than repeating full group scans in each visitor. Its reader-validity stamp can advance while its paint stamp remains unchanged if visible roles and member effects are equal. Different cards can publish independently; this atomicity does not impose ordered network completion or a transcript-wide palette barrier.

A card with no source members can still require a selected local palette input. It follows the same registry and group-notification path without inventing a SOURCE acknowledgement. Similarly, locally prepared empty semantic coverage is not a parser checkpoint: arrival of real text must begin a genuine parser generation.

## Surfaces and source text

- Native classification applies only to pi-tidy-ui's Bash command and successful read/edit/write source bodies, including Markdown files. Read contributes saved returned text only while explicitly expanded; compact read has no body demand. Bash output and opaque host image rows are not classified. Ordinary summaries, user-message Markdown, the editor and native delegated cards remain outside this highlighter and its card palette.
- Bash argument updates prepare the latest command outside `render`. Pi's `setArgsComplete` finalizes the input independently of tool execution: a still-running Bash process does not require an unfinished syntax lease. Persisted completed calls use one-shot classification.
- A final live formation error retires native work and attempts lease closure outside `render`, without pretending that arguments completed or a tool executed. One already validated, budgeted display basis remains while its card owner lives. Obsolete replies cannot replace it; valid already-requested STYLE may advance it under the [current ownership and per-card publication rules](#sealing-and-publishing-one-card), without reopening SOURCE work. Warm frames cannot reopen retired work. A new restored terminal card, including an interrupted call, admits one finite native classification of its available saved text; source finiteness does not mean complete Bash arguments or tool execution. Public current-assistant tool-call IDs identify live ownership without history scans or retained messages, including abort before a useful frame; unknown embedding origin stays conservative. Warm/repeated/geometry-only visits reuse that static result. Positive execution/persisted `toolResult` evidence takes precedence over reconstructed incomplete flags. Partial error output and execution errors do not abandon the source.
- Edit/write use validated supplied source/diff data. Old/new sides are separate logical sources; a missing diff region starts a new parser context. No file reread or invented continuity across omitted context is permitted.
- Logical preparation first normalizes line endings and removes display-forbidden terminal/bidi controls. Parsing sees that normalized source before tab expansion, wrapping or paint; source offsets do not refer to raw streamed JSON, prompts or expanded-tab cells. Painting projects structured ranges onto existing display text, with unchanged glyphs, wrapping, gutters, context, tint, padding and mouse bounds. Existing ANSI style isolation remains authoritative.
- Classification does not modify tool arguments/results, execute tools, send model requests or alter saved conversation entries.

## Scheduling contract

One chronological `SourceExecution` work registry selects both preparation and native dispatch newest-first (LIFO). Cards register their existing weak tickets before heavy preparation; all native segments of an edit share that entry. Standalone sources register once on first admission. Updates/retries do not change registration order. Card preparation no longer has a separate sorted queue, and no numeric priority is passed between layers. A group awaiting fresh preparation cannot dispatch obsolete queued work. Busy/protected sources are skipped; accepted results publish independently, without an ordered-completion barrier. Already dispatched native jobs retain their physical reservations. It processes at most two owners per batch, using the existing job limit, and yields to the event loop before more work. The continuation holds only the weak controller; synchronous or asynchronously queued demand cannot schedule an unbounded preparation microtask chain. The host-turn barrier survives a momentarily empty pending set after dispatch; the one-shot stops without rescheduling if no work arrives. Existing controller/provider/global job and byte credits still govern native dispatch. A resumable cursor walks this same linked registry without copying/reversing the entire registry for each batch. Selected-palette metadata advances one local revision in O(1); weak tickets check usefulness lazily. Actual DATA-credit exhaustion stops new source/style preparation until real settlement; it does not defer live text changes or unrelated permitted local input work. Local-only pending work can pass DATA-blocked entries in the same registry; actual credit release reconsiders the skipped native work. File layout stamps track the actual resolved rules and selected-palette display identity, not a requested menu value or work-state notice; resuming a temporarily unavailable projection replaces its plain cached layout without repeating classification. Palette-only supersession does not abort already dispatched work: let its bounded physical jobs settle, reject obsolete presentation, then dispatch the latest generic STYLE demand. Genuine lifecycle cancellation still reaches every pending generation of the same source incarnation. Canonical source owners receive validated terminal transport replies even after other local cancellations; malformed, lost and started/unknown outcomes retain their existing protective meaning. No polling, new payload queue or time budget; one large preparation is not preemptible.

## Observing completed work

`SourceExecution.whenSettled(): Promise<boolean>` observes the controller's already-admitted work. It waits for the scheduled pump, host-turn preparation continuation, physical SOURCE/STYLE/lease-close jobs, queued closes, credit wakes and actual coalesced notification delivery. The delivery callback is inside the boundary: work it queues must drain too. Zero native jobs alone is insufficient; a held source notification can still owe the first Bash-prefix adoption.

Observation never calls `flush`, resumes a held continuation, starts a request, invokes rendering or reconstructs readiness from cards, source text or desired style state. Recorded demand that has not been scheduled is not implicitly admitted. Work first admitted by a later normal render remains that render's responsibility; this method is not a terminal-frame receipt. A source controller also does not own startup or provider recovery; the [client composition](providers.md#observing-client-completion) includes those producers.

`true` means the observed queue and delivery drained, not that highlighting succeeded, fallback was permitted or the requested colors became available. Assertions must check those outcomes separately. Suspension, Native Off or disposal cancel the **current** observation with `false` without refunding held physical reservations. A subsequent observation is independent; native-disabled controllers can still await local Pi preparation. Existing controller finalization cancels an abandoned observation without retaining the controller.

Each controller stores at most one pending completion Promise/resolver in its existing lifetime record, shared by concurrent callers and cleared on completion/cancellation. Checks use existing queue/job/credit/notification lifecycle state rather than a per-card completion graph or a polling loop. The regular newest-first ordering, host-turn quota, physical budgets, refusal authority and cancellation policy are unchanged.

[Terminal result tests](../testing.md#cli-isolation-and-evidence) compose client completion with actual action completion, normal rendering and the existing parser receipt. They sample natural-frame counters before any separately requested component-render diagnostics; assertions of successful colors, semantic replies and unchanged work follow completion rather than deciding when to stop waiting. Counter-only observations use the same boundary without copying/persisting cells. Deliberately held owned work remains pending, so its intermediate frame cannot claim whole-owner completion. Disposed-client cancellation is not successful teardown: resource diagnostics follow the actual release action, without asking an absent owner for a successful highlighting observation.

Weak credit-wait membership is conservative scheduler interest, not a count of current queued work. After an actual pause/removal, SOURCE freeze or `observe` retiring a formerly queued SOURCE demand or replacing its owned generation, or clearing/replacing an existing desired STYLE selection, a controller already in that set removes its membership and calls the existing `wake()`. A STYLE replacement changes its effective rules, palette or binding revision; identical effective identities retain the existing installation behavior but add no withdrawal wake. The ordinary queue then determines whether any interest remains: an idle sibling does not block completion, while genuinely queued SOURCE/STYLE/preparation or closes remain authoritative. A parsed, clean source can owe only STYLE; replacing its generation with empty text must reconcile credit even if SOURCE stays clean. Client styles for empty coverage may publish locally, whereas a missing local palette input still re-registers native credit interest when a compatible provider is ready. Group release reconciles after removing its member sources, not during their intermediate mutation. Repeated no-op withdrawal is inert; Native Off keeps its existing membership clear and flush. No new per-entry readiness accounting or generic ownership-transfer hook is added.

Retention receipts are another real withdrawal transaction: funding for one card can evict another source's current generation or frozen previous basis within the same controller. The receipt consumer records those existing native ownership detachments and reconciles once after all recursive releases. Empty receipts and Pi-only releases do not withdraw native queue interest. Remaining preparation, STYLE and lease-close work is still discovered by the normal queue, not inferred from the presence or absence of retained payloads.

An enabled controller also withdraws stale credit interest when its existing pump observes an actual ready-to-not-ready provider transition. The prior readiness is captured before updating the current provider state; repeated non-ready publications add no withdrawal wake. Native Off and suspension retain their explicit lifecycle handling. This covers terminal failure and temporary recovery without cancelling observations or retiring retained sources.

Generic STYLE credit interest uses the same ready-description, vocabulary and current-provider predicate as dispatch. The first full-credit guard still avoids uncached enumeration/encoding, and both existing full-credit exits return without registering impossible interest. The late dispatch guard evaluates the predicate again after local preparation; an earlier snapshot is not permission to send. Cached scopes/styles and local binding changes can still publish offline or under a provider with an incompatible vocabulary, without sending old context IDs to that provider. Drained local/fallback work can complete the source boundary while an actual broker recovery operation still holds the [client boundary](providers.md#observing-client-completion).

A local materialization refusal is recorded against the selected palette identity and binding revision, as well as the existing rules/vocabulary/cache refusal receipt. This lets a later palette-only or binding-only selection retry publication from already cached semantic expressions after funding recovers, without repeating SOURCE or STYLE. The unchanged refused identity is warm-suppressed. A generic STYLE denial with still-missing contexts remains suppressed: changing only palette or binding can reconsider local work but does not resend the denied request. Successful publication clears the refusal receipt.

These production withdrawal transitions are a narrow scheduling exception, not work started by `whenSettled()`: they schedule ordinary reconciliation and its normal quota-bound host-turn continuations. This can bring permitted local/cached progress forward. It neither forces a synchronous flush/render nor frees physical reservations, changes ordering/admission, or cancels the entire observation because one card was withdrawn.

## Rendering and fallback

Preparation, encoding, requests and classification occur outside terminal rendering. Rendering borrows already validated ranges or an exact prepared fallback; it never waits for a daemon. Keyed coalesced notices carry source keys **and primitive card-group IDs**, independently of display effects. Group notices also make source-less cards ready when only their complete palette was missing; existing weak ticket lookup reaches them without a transcript scan. A Bash card is invalidated only when its compatible display stamp changes, without traversing transcript history. Waiting/no-coverage preparation and equal-text finalization with identical styles do not rebuild or request a redraw.

The canonical `SourceExecution.workStatus` determines whether a new Pi classification is allowed. `requestSyntax` keeps prefix shaping, cached projection/failure/refusal reuse and the permission/stale checks in that order; only after those checks does it invoke the stable `client.pi` coordinator for the funded transaction. Thus a valid cached projection can be reused while fallback permission is false, but `PiFallbackCoordinator` never infers permission itself. Queued, running or uncertain source work blocks a duplicate Pi parser within the same installed adapter. Style responses, cancellation, timeouts and provider absence do not prove that source parsing never started or has physically finished.

| Situation | Presentation |
|---|---|
| Validated semantic ranges and ready styles | Use the ready card's coherent palette and style table |
| Another palette selected, not ready or refused | Keep the last complete paint; it is not proof that the requested palette input or STYLE generation is ready |
| Growing/corrected Bash command with a compatible display basis | Reuse colors of the matching scalar prefix, including provisional styles; display every current character |
| Native work not started or unavailable, Bash | Whole command in the ready palette's command-neutral role (`toolTitle` in Follow Pi); **never call Pi's highlighter** |
| Native work not started or unavailable, file source | Reuse compatible exact display. Missing syntax uses the selected palette's neutral role. Native Off keeps local preparation of visible successful files useful even while their first replacement paint is pending. A failed owned asset uses one complete Follow Pi input rather than partial owned colors; permitted exact Pi classification remains governed by SOURCE authority |
| Source/style work pending | Compatible historical Bash prefix or exact selected file-view fallback; otherwise selected display text in the ready palette's neutral color. Styles never authorize a duplicate parser |
| Source/style data cannot be retained or admitted | Keep the selected logical display: complete Bash/full-file text or the bounded file preview. Missing syntax uses the selected palette's neutral role; it never authorizes duplicate classification |
| Valid file display/geometry funding is refused | Keep the requested view owned and show its bounded limitation row; do not reveal a hidden preview suffix or invoke native preparation. The ordinary next eligible render may retry funding |

The [Bash streaming contract](../bash-streaming-contract.md) supersedes the former complete-line-only Bash display rule. Historical colors are presentation data, not proof of current parsing, current parser state or permission for a second classifier. Scalar-prefix verification runs outside render when the prepared command or validated basis changes. Its cached eligible-byte proof is guarded by source revision and basis geometry identity; rendering and width/palette changes reuse it without rescanning text. New glyphs after the mismatch use the ready command-neutral role, with the explicit whole-grapheme first-scalar exception. No source normalization, range copying, verification walk or work scheduling is added to a warm body hit. File exact-fallback and parser incrementality rules are unchanged.

Completed Pi fallback ANSI is converted once by `preparePiFlat` in `src/highlighting/pi-flat.ts` into accounted flat ranges and immutable styles; the stored representation does not keep a second ANSI copy. It preserves public foregrounds and bold/faint/italic/underline/strikethrough, including SGR `22` clearing only bold/faint, SGR `29` clearing strike, and SGR `0` restoring the supplied neutral foreground and attributes. That neutral code role can itself carry supported typography (for example faint); SGR `0` does not unconditionally erase it. This differs from public-prefix sampling, whose reset starts from no attributes. Both inputs use one literal-style painter with explicit RGB/indexed/terminal-default colors and attribute resets. Per-token backgrounds are suppressed: the ready card palette owns code/diff-row surfaces.

Unlike semantic contexts, Pi fallback contains literal colors, not reversible scope/role annotations. A genuinely changed effective fallback palette may therefore require one newly permitted classification for that exact source/palette. Width changes, warm visits, an unchanged fallback palette and an independent owned-palette change do not justify it. Failure/refusal caches are palette-qualified too; changing a palette never clears unresolved native-work barriers. A selected owned palette must not trigger a Pi classification whose colors would then be discarded.

Execution exposes readonly card-work activity from its existing suspension/disposal facts, independently of Native On/Off. The Pi coordinator uses that authority before source/ticket admission, immediately after the classifier returns or throws, and at final projection acceptance. A stopped classifier transaction is stale interest, not a permanent input failure: release its tickets/candidates without processing returned rows or caching a failure. Previously accepted projections remain readable; Native Off still permits Pi while work is active. The activity callback is receiver-free and captures only the execution owner's existing weak reference. Operation-scoped geometry funding and grants also reject inactive execution; already-funded retained read capabilities keep their separate lifetime. Both local STYLE reconciliation and successful-reply acceptance revalidate execution activity and the selected input after a supplied selection predicate, before materialization or refusal caching. Stopping work or replacing selection is lifecycle/currentness invalidation, not local funding failure; already installed generic expressions remain available for ordinary useful reconciliation.

There is no millisecond budget, cold/warm timing gate, cooldown, sampling heuristic or per-frame classifier retry. A synchronous Pi fallback remains synchronous; moving it outside `render` does not make it an asynchronous parser. Exact source/palette reuse prevents ordinary repeated fallback work.

Pi fallback, semantic snapshots, contexts, styles and prepared geometry share the existing bounded logical-data authority. Charges follow actual storage lifetime, including captures and borrowed data after removal; existing cache cleanup returns geometry quota without another GC handler. Contexts are vocabulary-qualified. Styles are shared by live context and rule identity, and released with their owners; one ready display is retained, not a history of rendered palette selections.

## Highlighting volume policy

Native admission, client semantic decoding and classification-prefix selection enforce these bounds. The client workload ceilings and Occipital carrier ceilings are separate policies. They cover classification and its data exchange, not preparation, normalization, wrapping, painting or virtualization of the complete card.

| Boundary | Default | Unit and scope |
|---|---:|---|
| Client native-SOURCE cap | **64 KiB** | UTF-8 bytes of the prefix of one logical source; not per line or update |
| Native classified lines | **8,192** | Logical lines in that prefix; stop at the first byte or line boundary |
| Finite SOURCE batch | **64 KiB / 8,192 lines** | Sum over all sources, still at most eight sources; do not multiply the allowance by eight |
| Public Pi fallback source | **8 KiB** | UTF-8 prefix, using the same bounded selection and line-count rules; file sources only |
| DATA request or reply | **512 KiB** | Complete serialized application JSON body, including envelope, all sources/contexts, rules and palette; request and reply each have their own bound |
| Expanded context descriptions | **65,536** | Total numeric scope IDs after expanding front-coded contexts across the entire SOURCE/STYLE job, not encoded suffix words |
| Decoded result | **2 MiB** | Existing controlled-allocation policy charge of the complete decoded SOURCE/STYLE message, inside the existing data authority |

All limits are inclusive. Empty text has zero logical lines; count each LF plus one for a nonempty unterminated tail. A final LF does not invent another empty tail. Blank lines count. CR in CRLF does not introduce another line. Prefix selection respects complete Unicode scalar boundaries and counts UTF-8 bytes, not JavaScript UTF-16 units, terminal columns or JSON-escaped bytes. JSON escaping is independently included in the 512 KiB message check. Smaller negotiated existing limits remain authoritative. A provider advertising DATA `reply_bytes` above 512 KiB is not suitable for this consumer and is rejected before SOURCE/STYLE work: a local post-decode cap cannot protect Node from a shared SDK that has already parsed an oversized reply. Use the existing descriptor field, not a new protocol negotiation mode. A more generous input allowance alone does not require rejection because the client can send a smaller request; `line_bytes` remains the classified-per-line window, not a maximum accepted line-length constraint.

The controller's explicit `SemanticDecodeLimits` policy caps source coverage, expanded context words and the controlled decoded-byte charge. Each decoder checks this policy in addition to the negotiated descriptor and its separately funded `availableBytes`; none is inferred from a generic wire integer maximum. The 512 KiB DATA body is an Occipital transport limit, not a highlight-decoding budget.

### Coverage, streaming and refusal

For a saved file preview, select its raw bounded view before normalizing rows or allocating the UTF-8/JSON source payload; the hidden suffix is not a display/source allocation. Then select the classification prefix before invoking either classifier. Scan only as far as needed to decide a prefix; do not encode an enormous unselected/full source merely to reject it. Bash retains the complete latest normalized display separately from its classification source. A file card retains exactly its selected preview or full display; a preview does not promise the hidden original suffix. Native `source_bytes`, committed offsets, ranges, revisions and completion refer to the prefix actually submitted, never to an invented parse of its neutral remainder. See the [edit](../edit-card-spec.md#metadata-and-scope) and [write](../write-card-spec.md#saved-source-and-classification) view rules.

The prefix budget belongs to the logical source, not to an append RPC: streaming does not grant another 64 KiB or 8,192 lines on every update. Once the admitted prefix is finite, settle/close its parser lease even if real Bash arguments continue to grow. Further changes solely after that boundary do not send more SOURCE/STYLE or re-encode the classified prefix. Corrections inside covered text use normal versioned replacement/recovery; they cannot keep obsolete file styles as current proof. Prefix completion does not mean Bash arguments completed or a tool executed. Historical Bash first-scalar/grapheme projection, frozen/paused ownership and unresolved-native fallback authority remain unchanged.

The raw daemon/client data boundary refuses an over-policy source or aggregate batch; it does not silently truncate wire text while acknowledging full coverage. The UI selects the useful prefix explicitly. Native production rejects excess context/result growth before excessive owned expansion/serialization; the client checks before typed context/range allocation and retained interning. A small wire dictionary can still exceed the expanded-context limit, and many empty context rows can exceed the decoded-charge limit without exceeding the word limit. The three result guards are intentionally independent. Wire-size refusal is based on actual encoded size, not a pessimistic source-size multiplier.

The transport passes the admitted size to the client in call-local, out-of-band ticket/byte metadata: stdio uses the actual JSON frame-body length, shared ingress uses its existing bounded canonical-JSON count. The semantic decoder checks that size against the current negotiated cap without repeating the full payload traversal, then still validates identity, shape, ranges, contexts and allocation limits. This metadata owns no response payload and is not a cache or a wire field. Raw unknown-object decoder calls without matching transport metadata retain the complete accessor-safe byte check.

A refusal retains the established current/last-ready or neutral presentation and physical-settlement semantics. It is not permission to run unlimited Pi fallback, reparse SOURCE because STYLE failed, or retry the same rejected work on every warm frame. Pi fallback has the smaller prefix allowance and still obeys canonical native-work permission; Bash never calls it. A ready selected palette keeps the unclassified suffix palette-neutral rather than mixing in Pi syntax. Classification limits do not truncate tool/session data or add a second painter.

### Why these values

The bounds protect different costs rather than treating source size as a proxy for all work:

- **64 KiB native prefix:** useful asynchronous syntax coverage without admitting a very large synchronous JSON decode/adoption on Pi's thread. Parsing is native, but client decoding, validation and retention still cost UI-thread work.
- **8,192 logical lines:** many blank or short lines can cause many parser calls while producing a tiny reply; byte/frame caps alone miss that cost.
- **8 KiB Pi fallback:** public Pi classification is synchronous in the UI process, so its coverage allowance is smaller than the native asynchronous allowance. It is not a latency guarantee.
- **512 KiB DATA body:** envelopes, multiple sources, contexts and style tables make a reply larger than its source. The same bound covers SOURCE and STYLE; source-free control caps remain **4 KiB request / 32 KiB reply**.
- **65,536 expanded IDs:** front coding can represent a large scope stack expansion compactly. This bounds the expanded numeric scope storage independently of encoded JSON size.
- **2 MiB decoded charge:** rows, indexes, ranges and styles also consume controlled storage. This per-message ceiling uses the existing data authority; it is not another cache, a per-card cap or a measurement of allocator bytes.

No separately tunable range-count or nesting-depth policy is added merely to duplicate these bounds. Positive-byte ranges within 64 KiB already have a finite count; context/result guards cover distinct expansion costs. Existing exceptional engine-safety checks remain. No new wall-clock timeout, worker, queue, scheduler, hidden reclassification timer or arbitrary-language deadline is introduced.

### Existing authority and guarantees

The **1 GiB client logical-data authority**, shared **1 GiB controlled application ledger**, **two unsettled physical client DATA calls** and at most one append per source remain. Shared service limits remain sixteen outstanding DATA jobs across eight routes and 4,096 leases globally/512 per route. Leases expire after five minutes idle or one hour total age; no no-op heartbeat renewals. The native DATA wait deadline remains five minutes, not a claim that a regex can be interrupted. Source-free metadata stays independent; descriptor-wait cancellation does not destroy unrelated highlighting. The outer emergency framing ceiling remains separate from the much smaller DATA policy. Native admission failures must not leave uncharged persistent engine/binding capacity: surviving capacity is reconciled against the already admitted credit before reducing a failed job to its error envelope. The physical slot still belongs to that job through reply handoff or confirmed cleanup. Native lease/binding pruning merges the existing tables in monotonic incarnation order, avoiding a full slot search for every binding or an additional retained index.

Bounds on bytes/lines/expansion are not hard time or whole-process memory guarantees. A Syntect regex call and synchronous Pi `highlightCode` cannot be preempted by a JavaScript timer. Two valid replies may settle close together. A per-source coverage quota is not a cumulative CPU allowance for a whole event-loop turn or many independent Pi classifications; the existing useful-work scheduling remains separate. Parser heaps, Node/V8 transients and private SDK buffers are not application charges. In particular the public shared SDK can copy/decode before the application's validator; producer-side bounded replies matter, and a hostile unrelated peer is not made safe by post-decode validation. Public Rust SDK pre-handler body retention remains outside this application's admission claim. No hard RSS/OOM guarantee, infinite-input display protection or all-language latency promise follows from these values.

### Configuration authority

The extension workload defaults are in `src/highlighting/limits.ts` (`HIGHLIGHT_LIMITS`); matching native classification values remain in `crates/occipital/src/limits.rs`. The DATA carrier ceiling is owned separately by `src/occipital/limits.ts` (`OCCIPITAL_LIMITS.dataWireBytes`). The unchanged six-field `HIGHLIGHT_LIMITS` aggregate references that native constant rather than defining another carrier value. It exactly matches `protocol/syntax-v4/highlighting-limits.json`; client conformance also checks the native carrier owner directly. No user-preference/menu/environment override or runtime file watcher is introduced. Increasing a coverage limit is not sufficient by itself: DATA size, expanded contexts, decoded charge and existing physical credits must still admit the corresponding work.

See [volume-policy validation](../testing.md#syntax-and-palette-validation) for conformance, boundary and real-transport controls.

Execution status reports established captured attempts for the source incarnation, independently of current-target exactness. Observing a newer unparsed target, pausing its preparation or refusing local adoption does not rewrite an older validated acknowledgement as `not_started`. `acknowledgedVersion`, stored classification and `exact` separately describe usable current parser progress. Held physical jobs still project `unsettled`; ordinary unresolved execution continues to veto Pi independently of any later successful native attempt.
