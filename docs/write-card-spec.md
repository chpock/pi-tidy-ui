# Write card specification

This specification defines the interactive presentation of the exact, case-sensitive tool name `write`. pi-tidy-ui supports stock Pi and compatible third-party result shapes without identifying the producer or changing execution, arguments, results or session data. Compatible data shapes remain eligible for file-card presentation regardless of renderer-pair identity. Third-party callbacks and producer state are not wrapped, retired or cleared; native self-shell visibility and native fallback may still invoke the original callback at the actual width, so foreign renderers carry no zero-native-work guarantee. A mixed pair can include one deferred stock half, but custom presentation does not evict its already-materialized component. Only the exact deferred stock pair qualifies for lazy-renderer ownership, cache retirement and its native-work savings. [Architecture](architecture.md) owns the host boundary; the [edit contract](edit-card-spec.md) owns the shared diff layout.

## Lifecycle and routing

Before final success, use the ordinary compact presentation: `write <path>` when `path` is a nonempty primitive string, ignoring every other argument without reading it. Otherwise use generic argument formatting. The [compact text budgets](tool-summary-spec.md) apply; long paths wrap rather than acquiring a one-row hard cut. Argument streaming uses the compact left-arrow glyph (`←`), as for edit; actual execution and partial results use the existing shared spinner. Final failure keeps the compact view with every visible segment colored `error`. Never inspect partial/failure diff metadata or paint proposed content as a successful card.

Only a final non-error result enters the successful write-source presenter. Pending and failed calls stay compact until the owner deliberately expands its detail view. Expanded pending content is bounded; expanded final-error details use all available saved request/error text only after ordinary construction funding and successful funded measurement, otherwise they show a bounded unavailable-details message. Rendering, predecessor spacing, mouse and animation teardown share these state conditions. Images and intentional native hiding remain authoritative. `--tidy-ui-card write` restores native rendering; `--tidy-ui-compact write` takes precedence and keeps every state compact. Unknown self-shell renderers retain actual-width native visibility checks; the stock-edit visibility exception is not extended to write by name or schema.

Card paths follow the shared nullish selection `path ?? file_path ?? filePath`, then require a nonempty primitive string; an empty or wrong-type earlier non-nullish alias does not fall through. Display absolute paths relative to the native component `cwd`. The exact compact shortcut uses only `path`, as for edit. Missing usable card paths or unavailable required source delegate to native.

## Saved source and classification

Use only the saved result and call arguments, never filesystem checks, file rereads, backup inspection or input-derived proposed diffs. Pi 1.0.1 write returns a success message without diff/old-content/creation metadata; the input `content` remains available. Compatible AFT results can retain numbered `details.diff`; other producers can supply a supported single-file unified `details.patch` or `details.diff`.

A live bounded preview is a separate prepared view, not a smaller full card. It normalizes line endings inside the bounded 8,192-UTF-16-unit source window before control-sequence cleaning, then selects at most ten physical input rows. Unified-patch preambles and hunk headers consume those rows. The common painter also clips wrapped output to ten visual rows and supplies its funded overflow marker alongside the preview note. Unified patch preambles and hunk headers consume that same prefix, so a preview may contain fewer than ten source rows. It validates all supplied metadata when the complete representation fits; only a known byte/row cut can permit an incomplete hunk at the end. A malformed fully inspected source remains unavailable rather than being guessed valid. Preview headings stay generic (`Write`) because a prefix cannot establish the change class hidden in the suffix. Hidden saved text is neither segmented nor classified; `omitted` and the separate bounded-prefix note identify incompleteness only when the prepared view actually omits source. A complete short preview has no false truncation notice. Full mode retains the complete existing validation and presentation rules below.

First check the explicit truncation override: for a final successful write, `details.truncated === true` requires string `args.content` and displays Wrote source with the truncation notice, even if patch/diff metadata is malformed or null. If required content is unavailable, delegate to native. Only otherwise apply the shared [saved-format and precedence rules](edit-card-spec.md#metadata-and-scope): `patch !== undefined` selects a supported string patch before `diff`; null/other unsupported selected values stay native, and empty string is supported empty metadata. Use the shared parser's number/hunk validation. Inspect source-row kinds across the entire parsed metadata **before context projection**. Headers, hunk markers, omission markers, literal code punctuation and no-newline annotations do not count as source change signs.

| Available data | Title | Body |
| --- | --- | --- |
| Supported complete diff with any removals, including removals only | `← Replaced <path>` | Shared edit-style diff |
| Supported complete diff with additions and unchanged context, no removals | `← Edited <path>` | Shared edit-style diff |
| Supported complete diff with at least one addition and no removals or unchanged context | `← Created <path>` | Resulting diff source with original new-line numbers and syntax, without diff signs/backgrounds |
| No diff, empty supported diff, or context-only metadata without changes | `← Wrote <path>` | Supplied `args.content` with numbers and syntax |
| Explicit `details.truncated === true`, even if some diff rows survived | `← Wrote <path>` | Supplied `args.content` plus `Diff truncated by tool; showing supplied content.` |
| Present malformed/unsupported diff without the explicit truncation override | Native | Native available information |

`Created` is the agreed display classification **content added from zero**, including filling an existing empty file. It is not proof that the file did not previously exist. `Edited` and `Replaced` describe the supplied change pattern, not distinct tool implementations. Do not infer these labels from message text, tool identity, addition/deletion counters or current file existence.

Without a usable diff, the old source and changed positions are unknown. Show the supplied input, not a fabricated comparison. It describes the content the agent submitted; it is not a guarantee of final bytes after producer-side formatting. Where trustworthy `details.noOp === true` accompanies absent/empty/context-only metadata, add `No changes.`. Never infer no-op solely from absent metadata. The truncated warning takes precedence over no-op. Unsupported metadata does not become a no-op merely because it has no recognized source rows.

## Body and completeness

Full cards keep all available changed rows visible: no Bash-like preview, compact 256/1024-grapheme cap, body ellipsis or hidden changed-line tail. “Complete” means all available changes, not reconstruction of the whole final file. Producer omissions/truncation cannot be repaired by pi-tidy-ui; the explicit truncated fallback states that limitation. No diff fallback can identify which submitted lines were already unchanged, so it displays all supplied content. The separate bounded preview above is explicitly incomplete and never replaces the full view.

Plain `Created`/`Wrote` bodies are always one full-width pane. Use right-aligned new-line numbers in the ready palette's number role (`dim` under Follow Pi, native-owned under an independent theme), one gutter space before the number and one space before code; continuation gutters are blank. Do not reserve a sign column or use added/removed tint. Preserve logical blank lines, trailing spaces and available source positions. A terminal newline in nonempty supplied content creates its final empty logical source row; empty content creates no invented row. Normalize CRLF/CR before constructing rows. File tabs use the shared four-column logical-line stops, not Bash's eight-column display stops. Omission markers already supplied inside an additions-only diff remain visible rather than pretending missing source exists.

Syntax uses Pi's public filename language resolver and the [syntax pipeline](syntax-highlighting-spec.md), borrowing asynchronous Occipital ranges or permitted exact cached Pi fallback before wrapping. Preserve multiline state within supplied logical regions; unavailable diff gaps reset it. The [highlighting volume policy](syntax/work.md#highlighting-volume-policy) selects a cumulative scalar-safe prefix of each continuous logical source: native 64 KiB UTF-8 / 8,192 lines, or 8 KiB for permitted Pi fallback, with aggregate SOURCE-batch admission as well. All text remains visible; uncovered text uses the ready palette's neutral code color. The internal native per-line window does not reset that whole-source allowance. Pi palette is default and independent daemon themes are selectable. Unknown extensions use the ordinary code fallback. Sanitization/tab expansion, grapheme-safe wrapping, tiny-width gutter omission and impossible-wide-grapheme replacement follow the shared file presenter, without changing source/model/session bytes.

`Edited`/`Replaced` reuse edit numbering, signs, [derived semantic backgrounds](edit-card-spec.md#derived-diff-backgrounds), neutral empty counterparts, hunk pairing, interior omission markers and `DIFF_CONTEXT_LINES = 3`. Additions-only/removals-only diffs are unified at every width; mixed changes split only above 120 columns. Context reduction never removes changed rows. The title uses the shared Bash/edit content origin and the ready palette's muted foreground (`muted` under Follow Pi). All card-interior colors follow the same complete native/Follow Pi palette as the source; missing native colors are not borrowed from Pi. Shared frame geometry follows Pi's Output padding for exterior margins with one fixed internal cell per side; the neutral panel uses the ready palette (`toolPendingBg` under Follow Pi), while the stripe and exterior margins keep terminal-default background and the same reset-restoration rules. Supplied flattened error diagnostics use the same display rules as edit.

## Classification execution

Write uses the same full logical-row representation and source/display split as [edit preparation](edit-card-spec.md#internal-flow), but chooses the view before projecting context:

1. Reject partial/final-error data as a completed write-card candidate.
2. If metadata explicitly says the diff is truncated, do not use its surviving row kinds as proof of the change class. Use supplied `args.content` with the completeness note, or delegate when that source is unavailable.
3. Otherwise validate the selected saved diff completely while collecting supplied row kinds. Malformed/present unsupported metadata remains native; it is not silently treated as absent.
4. Absent diff or a validated diff with no additions/removals uses supplied content as Wrote. Any removal selects Replaced diff. Additions with context select Edited diff. Additions without context/removals select plain Created.
5. Keep the chosen full logical view. Only a diff view projects display context; plain code preserves all its supplied rows. Build source-fragment coordinates before useful syntax work and keep title/note/diagnostics as separate prepared service regions.

This is why Created does not prove that a path was previously nonexistent, and why an incomplete diff cannot establish Replaced from one surviving deletion. The labels describe evidence in the supplied result, not filesystem inspection or a reconstructed post-format file.

## Integration and retention

`src/file-card.ts` validates metadata, selects the saved-source/display kind and prepares logical plain/diff data plus context projection. The host caches the selected bounded source snapshot across ordinary renders, including same-prefix argument/result object replacements; preview identity ignores hidden suffixes, while full write identity also tracks the possible `args.content` fallback for context-only metadata. Expanded error text remains source-backed until geometry funding succeeds. Its construction grant covers the actual joined-text peak: a 4 KiB fixed allowance, six logical bytes per source unit for normalization/cleaning/part assembly, and 64 bytes per source part; the retained joined string has a separate UTF-16 charge. Physical newlines create no file-row descriptors here, so reservation does not scan or charge per line. Once joined, temporary parts are cleared and unused construction credit is returned before ordinary `GeometryFunding` grants fund numeric measurement. Pending full details are already bounded before measurement and charge their retained text independently. Pending/error detail text is prepared on expansion/input changes, not while painting; same-prefix hidden updates retain the bounded pending text/measurement while replacing old args/result references, and collapsed previews do not traverse result text. For failed edits, `args.edits[]` takes precedence over legacy top-level text fields; final-error details enumerate all available edit fragments and text error results without the pending row/unit cap. Ordinary construction funding is reserved before joining, and measured geometry uses the existing budget; refusal retains neither partial body nor measurement, leaves the requested mode owned, and a later cold visit can retry without native full preparation. An expanded pending/error detail refused by its own funding displays a bounded file-details-unavailable marker, distinct from refusal of a successfully prepared full file card. A detached weak-owner receipt releases both text and measurement charges, without retaining the owner or scanning every error record at turn end. Its exported validation-only `measureFileCard` helper is not the production spacing path: the live adapter uses the prepared display described in [shared rendering](rendering.md#neighbor-spacing-without-another-body-build). Syntax classification/fallback authority belongs to `src/syntax/work.ts` and the source controller, prepared text/ready paint to `src/syntax/cards.ts`, and common layout/painting to `src/syntax/card-layout.ts`; see the [pipeline and ownership map](syntax-highlighting-spec.md#syntax-pipeline-and-ownership). `src/index.ts` remains the sole host adapter. No tool definition override, execution interception, dedicated write-render timer, producer patch or presenter registry is introduced; native provider lifecycle is separate.

Successful write frames belong to the `cards` accounting group with Bash and edit diffs. Compact lifecycle/forced-compact views and native fallback belong to `ordinary`. Each component owns one latest layout/group/width with no admission or eviction limits; ordinary detached removal/nested clear or owner collection releases its representation. Current-renderer clear instead follows the [same-owner transfer exception](render-cache-spec.md#invalidation-and-ownership), retaining ready presentation across synchronous reattachment. Native updates, expansion, invalidation, width/Output-padding/theme and `cwd` guards apply unchanged. Warm retained frames do no custom source preparation/highlighting/wrapping. Spacing and rejected clicks use an exact retained scene or the prepared display's framed/inline classification; inline headings alone receive a temporary measured-text reflow. They do not reparse metadata or construct an unretained source body. Bounded pending-detail rows and funded final-error detail rows are measured through the funded card preparation budget. Detail text and measurement receipts are released on collapse, semantically changed input, explicit native takeover and owner teardown; failed construction releases partial charges immediately, while a geometry-only reflow refusal keeps an already-funded detail for ordinary retry. Hidden-only pending updates keep the same bounded detail and measurement, while replacing references to superseded argument/result objects. Plain source keeps syntax foregrounds over the already-prepared neutral code surface and uses the palette's number role, without added/removed tint. Shared palette preparation may still derive diff backgrounds independently of card kind; palette generation is outside render, not a per-row plain-source operation. See the [cache contract](render-cache-spec.md).

A selection-safe fullscreen primary click inside a completed file panel toggles its owned bounded/full view; Pi's regular-mode TUI does not dispatch SGR mouse events, so that control is fullscreen-only. A still-pending call requires Ctrl+O and ignores mouse expansion; its detail excerpt is bounded. A failed summary opens all available saved error details only after ordinary construction funding and successful measurement; a refusal shows the bounded unavailable-details message. Exterior margins, separators, selection, wheel and secondary events remain non-targets. Ctrl+O keeps Pi's global flag but selects the same owned full view rather than constructing a stock write renderer when saved data is supported. The automatic full window is the rolling set of the latest ten successful attached write/edit owners across turns, ordered by first-seen host component order rather than completion order. At `turn_end` the whole current batch is folded in and older automatic owners are demoted together; empty and non-file turns leave the window unchanged. The ten-owner ceiling is applied only after filtering actual final-success candidates; it does not backfill an older demoted card when a recent owner disappears. Only actual final successes participate in the ten-owner ceiling. Restored history starts bounded; explicit per-owner choices remain scoped to the live component owner. Pending/error details stay compact unless deliberately expanded. Expanded pending details use a bounded submitted-source prefix; expanded final-error details reveal saved arguments and error text only when their geometry funding and measurement succeed. Fixed service rows (including omission, unavailable and click-hint messages) fit the actual content width after Output padding and produce no overwide row in Pi's regular renderer. Unsupported selected full metadata and missing-path success delegate to the native full presenter. A valid full view refused during source preparation remains owned, preserves the requested full mode, releases partial work and shows a bounded limitation message without invoking native preparation; the ordinary next eligible render retries preparation cold. If its logical display was already accepted and only width-dependent scene/geometry funding refuses, the adapter drops the failed scene but retains the funded logical file view and measurements. Repeated ordinary frames retry geometry from that accepted display without re-running source preparation or measurement; recovery uses the same retained view. A refused bounded preview remains an owned bounded summary, and a geometry refusal does not erase an already-retained bounded view. Native image/hidden behavior and explicit native overrides remain authoritative. Off/shutdown/failure/reload release retained layouts and restore owned hooks.
