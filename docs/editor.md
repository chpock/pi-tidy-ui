# Editor and below-input presentation

The native editor remains the editing engine. Toolview projects its rendered rows and adds a separately owned metadata widget; it does not transfer the draft into another editor. [Host integration](host-integration.md) owns attachment, descriptors and lifecycle; [frame geometry](card-frame-spec.md) supplies the common dimensions.

## Projection execution

`renderEditorCard` in `src/editor-card.ts` receives a callback into the **existing** native editor, not the draft string. Its execution is:

1. Compute exterior margins and the content width from actual width/native Editor padding. Invalid or impossible geometry delegates before requesting an oversized native layout.
2. Request a paired native width: content width plus twice nonzero native padding, or one native cursor-reservation column when padding is zero. Native wrapping/navigation therefore use the intended content width.
3. During this call only, top/bottom border hooks return distinct zero-column sentinels. Partition the returned top, text, bottom and following menu rows by those sentinels; do not search input for border glyphs.
4. Slice known native padding by terminal columns, permitting one extra internal-right-padding cell for the end cursor. Append an explicit attribute reset after each slice; a slice can otherwise end before the native inverse-cursor reset.
5. Verify that no source glyph overflows the content budget and that the number of `CURSOR_MARKER` occurrences is unchanged. An impossible projection delegates to the original at the real width rather than clipping the cursor or widening the component.
6. Frame the input/top/bottom projection. Keep autocomplete outside the panel, preserving native rows, selection and y order but aligning its text with the projected input origin.
7. Return rows together with `nativeWidth`, `offsetX` and geometry. The host translates normalized mouse coordinates using that same result and any actual upper-widget separator, not a separately guessed layout.

For width **100** and padding **1**, content width is **95**, native render width **97**, and slice budget **96**. That extra cell is the existing internal right padding, not either exterior margin. The native editor still owns the draft, paste maps, cursor and undo history; the projection owns only the current geometric result. Replacing the editor and copying text could not preserve that full native state.

`editor-status.ts` then fits plain metadata/directory graphemes to the last valid geometry before coloring them. Its allocation and staged shortening rules below are independent of Git I/O, native activity and footer accounting. Width changes start from original values rather than shortening a previous shortened result.

## Main input editor

The plain stock `CustomEditor` uses the user-message frame paint: `customMessageLabel` stripe, `userMessageBg` panel and `userMessageText` literal input. No prompt glyph or horizontal border is added. Source indentation and literal `>` remain source. Native inverse-cursor/selection styles remain semantic; input is not Markdown. Autocomplete stays **below**, outside the input panel, aligned with its content origin. A separate public `belowEditor` widget follows the editor; both of its rows are hidden while the native autocomplete list is open. The widget precedes the footer slot; the [session-footer contract](footer-spec.md) describes pi-tidy-ui's separate footer replacement and its shared stock-input ownership gate.

Pi's **Editor padding** (`editorPaddingX`, UI values 0–3) sets the exterior horizontal margin of the **whole input panel**, not its internal text gap. Both margins equal the current native `getPaddingX()` value; keep one painted inner column after `┃` and one on the right at every value, including zero. For a fitting width W and padding P, the stripe starts at P, text at P + 2, panel width is W - 2P and text width is W - 2P - 3. Zero is flush with the component edges without joining text to the stripe; one preserves the former appearance. The below-editor metadata row and half-block edge use the exact geometry snapshot from that editor render; autocomplete shares its text origin outside the panel. Native settings changes apply on the next ordinary render without reload, text transfer or settings writes by pi-tidy-ui. Internal vertical padding, footer and transcript cards remain unchanged; the optional outside upper-widget separator is described below. If the requested margins leave fewer than two text columns, delegate to native at the actual width rather than silently reducing margins or creating an oversized native render.

Keep the same editor instance and editing engine; do not construct a replacement, transfer drafts or wrap keyboard input. pi-tidy-ui narrowly wraps public-imported stock `CustomEditor` presentation and forwards normalized mouse coordinates to stock `Editor.handleMouse`. Native activity routing additionally uses same-default public `setEditorComponent(undefined)` rebinding, not a foreign factory: the same editor must remain attached. Pi's redundant synchronous `getText()` → `setText()` self-transfer is suppressed only during that call; otherwise it would reset cursor/undo/history and turn expanded pastes into literal markers. Restore the exact setter descriptor and existing public focus in `finally`. Editing methods otherwise remain native; text, paste/image maps, cursor, undo/history, app actions and autocomplete provider are unchanged. Host-native reload/state behavior remains Pi's responsibility, not a new state-migration promise.

Eligibility requires the exact public stock prototype, its exact shared `Editor` parent, native rendering/mouse methods and pi-tidy-ui-owned border hooks, native padding/text methods and a writable border-color callback; check ownership every render/mouse visit. An explicit public editor factory, subclass, instance presentation override or preexisting renderer owner remains native. Public class identity, not a matching class name or presumed SDK shape, defines the boundary.

This is an **input and session-footer ownership boundary**, not a package-wide incompatibility rule. If another extension installs or replaces its own editor (including `pi-powerline-footer`), pi-tidy-ui leaves that editor and its appearance under the owning extension's control. Here native fallback means retaining that extension's existing presentation, not replacing it with Pi's stock editor. pi-tidy-ui does not disable the extension, take over its editing behavior or compose arbitrary editor renderers. Tool and user-message cards remain independently eligible under their existing safeguards. The session footer requires the same recognized input owner: when input ownership is lost, restore stock only if our footer is still owned, never overwrite a later foreign footer. Footer-only extensions that do not replace or override the editor are not excluded by this rule; full package compatibility and arbitrary shared-method overrides are not guaranteed.

Render the native engine at the frame content width plus native padding (or one native cursor-reservation column when padding is zero). This also sets native wrapping/navigation geometry. Project only its known padding; never rewrap draft strings or read private editor layout/scroll/paste state. Top/bottom native border hooks return internal zero-column sentinels during that single projection, establishing the autocomplete boundary without recognizing glyphs in input. Replace those rows with panel padding, retaining native upper/lower overflow labels. With the below-editor widget enabled, Pi renders activity in its separate native status container above the input; the panel retains the native base border and its overflow information. Remove `─` only from call-local stock `borderColor` **decoration fragments**, not status/source strings; restore its exact own descriptor in `finally`. Status literals use independent native indicator callbacks.

Keep native editable/menu row counts unchanged. The adapter may prefix one outside upper-widget separator without changing the native editor's text/menu counters. Translate normalized mouse x/y and width/height to the same native geometry, subtracting the actual zero/one-row prefix and leaving its empty row noninteractive. Preserve event kind/modifiers/screen coordinates and native response; do not capture raw input or add pointer/keyboard listeners. The native end cursor may consume the existing internal right-padding cell, never the exterior margin. Keep `CURSOR_MARKER` for hardware cursor/IME positioning. Column slices close native attributes explicitly so a clipped end-cursor reset cannot invert exterior margins or later rows; reapply user text/background after full resets. Width zero emits nothing; widths 1–6 stay native to avoid requesting a one-column layout from Pi's wide-glyph wrapper. Other impossible glyph/cursor projections and configured padding larger than the real component width also fall back at the real width; never materialize unbounded native padding to decorate a narrow editor. Native tiny-width limitations are not repaired.

Input/widget rows have no pi-tidy-ui rendered-layout cache, animation clock or strong editor ownership. Weak state contains last painted geometry and zero/one-row mouse offset, native status-group width/nonblank observations, upper-group width/content-height observations with weak spacer identity, restorable public flag descriptors, and call-local projection/spacer packets, never retained draft/widget rows or native indicator objects. Git metadata uses the separate event-driven source described below. The widget uses a weak reference to the recognized stock editor and requires current painted geometry before showing rows. Footer eligibility uses that same weak identity without requiring attachment during a temporary native selector. Native editor rendering/cache and working-indicator animation continue independently. Off/failure/shutdown/reload restore only still-owned prototype descriptors, including deleting originally inherited methods. New default editors are discovered through the existing attachment hook. First-installer GC must succeed while the adapter remains active.

Hardware cursor/IME positioning retains the native `CURSOR_MARKER`. This contract does not extend to OS IME candidate windows, clipboard-image callbacks or graphical image insertion.

### Upper-widget separator

For the eligible framed stock editor, prefix exactly one fully empty, unpainted row when the native **upper** widget group supplies content rows beyond its stock leading spacer. This row belongs to the editor's returned block and immediately precedes its existing painted top padding; widget insertion/update order cannot move a widget between the row and panel. Do not add a separator widget, change foreign renderers, move Pi's own leading spacer, or remove the panel's internal padding. No upper widgets, registered widgets returning zero rows, and lower-only widgets add no editor-local separator. Multiple upper widgets share one separator. A widget changing height on ordinary renders updates this decision without unregistering it, polling or timers.

The optional feature depends on a guarded host layout: seven managed public root children in document/pending/status/upper-widgets/editor/lower-widgets/footer order; plain shared containers; the stock editor alone in its input container; owned stock group/spacer render methods. Both current native modes retain these managed children, even though fullscreen paints a separate dock. Observe the group's ordinary `Container.render` result and the first stock `Spacer.render` result in that call; the spacer must supply exactly one empty row. Retain only weak-keyed width/content-height data and weak spacer identity, not foreign rows/owners. No foreign renderer is invoked again to decide spacing, and no private registry, spacer field or allocation hook is read. Width, tree shape, leading spacer identity and ownership are revalidated. Unknown layouts, replaced methods/spacers or unavailable measurements omit this optional separator without guessing or disabling the independently eligible panel/cards. Off/failure/shutdown restore only still-owned observers; transient spacer packets clear in `finally`.

Zero height means zero returned widget rows, not parent allocation/clipping at a short terminal height. The separator is an editor presentation row and follows native editor clipping; no height heuristic or allocation-aware visibility promise is added. Preserve the native cursor marker and subtract the actual prefix from normalized mouse y/height so text and autocomplete clicks still reach their native rows. Native editing state and its private visible-line/menu counters remain unchanged.

The guarded container/spacer composition is host-version-dependent. Unknown shapes omit the optional separator rather than guessing; the independently eligible editor panel and cards remain available.

### Below-editor metadata, working directory and native activity

One public `belowEditor` widget normally supplies two noninteractive rows; its public `isShowingAutocomplete()` check returns zero while the native suggestion list is open. Pending requests and empty results do not hide it. Ordinary native renders restore it after completion/Escape; no polling or menu lifecycle interception is added. Pi places the widget after the complete editor and before the existing footer. Metadata/edge clipping follows normal widget allocation, without height heuristics or private allocation hooks. Public widgets receive width, not their allocated height; terminal height alone cannot reveal how much space sibling containers leave. A height threshold would therefore guess at allocation and could hide useful content even when space is available. **Native activity is independent of this widget and remains in Pi's separate container above the input, including during autocomplete.**

- Row 1 shares the editor's current exterior margins, stripe, fixed inner gaps and panel paint. Its left block is `<model.name> (<provider id>) • <thinking level>` and, only at idle, ` • Idle`. The model uses `mdHeading`; provider uses `muted`; balanced parentheses and bullets use `dim`; thinking uses `thinkingOff/Minimal/Low/Medium/High/Xhigh/Max` (unknown levels use `thinkingOff`); Idle uses `muted`. Preserve the provider ID, with no aliases. No model uses `No model` / `—`; keep `off` explicit. Read current context each render.
- Append Idle only when `ctx.isIdle()` confirms idle and the normally rendered native status group has no nonblank output at that width. Busy/hidden activity has no suffix. The observer consumes ordinary native rows without extra renders or parsing status kinds; retain only width and visibility. Working/spinner/retry/compaction/future native messages never enter this widget.
- The right block is `<ctx.cwd>:<git branch>` with exactly one painted right-padding cell, already supplied by the shared frame. Do not add a second inset or change exterior Editor padding. Use the context directory, not a Bash `cd`, repository root or realpath substitution. Before width fitting, replace the native home directory (`os.homedir()`) by `~` only for that directory or a separator-bounded descendant (`~/…`, with the native separator on Windows); a merely matching name prefix remains unchanged. This is display-only: Git, context and saved data keep the original cwd. Strip non-root trailing separators for display. Sanitize terminal controls without altering the real directory used for Git. Parent path/separators use `dim`, the last directory uses `mdLinkUrl`, `:` uses `muted`, and branch uses `text`. An ellipsis has its omitted part's color. Filesystem/drive/UNC roots are an indivisible last element, not an empty name.
- Row 2 remains `╹` plus upper-half blocks `▀` across the panel body: stripe foreground for the corner, concrete active `userMessageBg` foreground for the blocks, terminal-default background and exterior margins. Close inherited attributes. Footer and other cards are unchanged.

#### Width allocation

Fit plain grapheme sequences by **terminal columns** before applying semantic colors. Never split a grapheme or include ANSI bytes in width. Before sanitization and column fitting, each model/provider/thinking label retains at most 256 raw graphemes and appends `…` when another grapheme exists. This differs from the compact-summary value budget, which includes its ellipsis. The bound does not apply to cwd/branch; directory/branch fitting preserves the last path element rather than applying a generic prefix cap. The two blocks have at least two spaces between them when both are present.

If the full left and right blocks fit, keep both. Otherwise reserve the idle label first (up to four columns); it is absent while busy. Reserve the two-column inter-block gap and divide the remainder equally: the left receives the odd column. The left allocation includes its metadata plus the separator before Idle. If either full block needs less than its share, give its unused allocation to the other. Shorten/drop provider, then model, then thinking within the left allocation, retaining balanced provider parentheses. If the right block disappears, recompute the left using the whole content budget; no unused inter-block gap remains. Very narrow idle-only layouts can shorten Idle using the existing ellipsis rule. Working has no reservation here because its native container is separate.

#### Ordered directory/branch reduction

Start each fit from the original sanitized path/branch, never an already-shortened result. Stop at the first stage that fits; skip transformations that save no columns. A branch already shorter than a stage's minimum is not expanded.

1. Reduce the **middle of the parent path**, retaining the root, first parent directory and full last element. The limiting form is `/home/…/name`, or `~/…/name` below the home directory (native separator for Windows). Preserve prefix/suffix around one ellipsis, approximately balanced by columns, with the extra column assigned to the prefix.
2. Reduce the branch in its middle, retaining prefix/suffix, down to **five columns including the ellipsis**: e.g. `fe…us`. Apply only enough reduction to fit if five or more columns suffice.
3. Replace the remaining parent prefix in one step by `…/`, preserving the complete last element. Do not display fragments of the former anchor.
4. Further reduce the branch in the middle. A shortened branch requires at least one real grapheme plus `…`; never show an ellipsis-only branch. When it cannot fit, remove both branch and `:`.
5. Remove the `…/` prefix, giving those columns to the complete last element.
6. Shorten the last element from the **right**, keeping its beginning plus `…`.
7. Hide the entire right block if neither the complete name nor at least one real visible grapheme plus `…` fits. A sole ellipsis is not useful directory information.

For odd budgets and wide graphemes, preserve the largest fitting prefix/suffix without breaking a grapheme, assigning spare columns to the prefix; unused columns are harmless. Repeated resizes must deterministically recover the full original value.

### Git source and refresh

Directory discovery, environment isolation, generation checks and metadata watches belong to the [host Git service](host-integration.md#directory-metadata-service). This chapter owns display fitting, not repository authority.

#### Native activity routing and ownership

Pi owns the indicator instance, text, kinds, styles, animation, visibility preferences and disposal. For the eligible default editor only, pi-tidy-ui installs a restorable accessor on the public `embedWorkingStatus` field, returning false while ownership is recognized. The supported SDK exposes this TypeScript-readonly option as an own configurable writable boolean field; immutable/unknown fields leave input native and omit metadata. Same-default public rebinding asks **Pi** to relocate an already-active object; do not disable/recreate/reparent it, read private indicator fields, copy rendered fragments, or recognize names. Preserve the complete draft state by suppressing only the redundant synchronous self-transfer described above. The native API must keep the same default editor and perform the inspected single self-transfer; actual SDK compatibility tests fail on changes to these assumptions. Rebind only a mounted recognized main editor, not an active selector; deferred normal attachment can finish routing afterward.

Foreign factories/subclasses/instance renderers remain entirely native, with no pi-tidy-ui panel/separator/metadata/edge or Git source activation. The public flag falls back to its original value when stock ownership is lost. Off/failure/shutdown restore only owned flag/method descriptors and native activity placement through the same guarded native rebinding; preserve the active object and clock. Later owners' replacements are never overwritten. The input feature adds no editor factory replacement or footer takeover (the input-dependent footer feature is specified in [its own contract](footer-spec.md)); no private operation lifecycle, indicator animation timer, raw input hook or private viewport counter is added.
