# Shared card frame specification

This specification defines the shared frame for Bash, user-message, main editor, [edit cards](edit-card-spec.md) and [write cards](write-card-spec.md). Other tool cards and native expanded results are unchanged. The common host/module boundaries are described in [architecture](architecture.md).

## Scope and architecture

One Toolview adapter owns live-host hooks, runtime lifecycle and mouse routing. The shared frame is a pure layout/painting module independent of tools, commands, results, expansion and host component classes. Callers supply already styled content rendered for its reported content width and painting callbacks. Bash, edit/write and user-message presenters supply their own content and paint; Bash toggles its custom output and completed edit/write cards expand to native content. All use the same frame and sole host adapter, without another extension or another set of container/input hooks. There is no plugin registry, new tool execution, session format, global theme modification or external shared package.

## Reference and geometry

Source reference: OpenCode `907b3bc518fa48e90e8ec24dd327d13eee71c36c`, `packages/tui/src/routes/session/index.tsx`: transcript horizontal padding at 1178 and `BlockTool` at 1994–2044; `packages/tui/src/ui/border.ts` supplies `┃`. This is inspected source, not a claimed screenshot comparison. Toolview keeps one internal column per side and follows Pi's Output padding for exterior transcript margins; this is not a claim of literal OpenCode spacing.

Transcript cards use Pi's **Output padding** (`outputPad`), whose native values are 0 and 1 (default 1), for both exterior margins P. Changing the setting applies on ordinary renders without reload. All transcript presenters read effective settings through the public API. User cards additionally retain the native component's live padding to request and strip its Markdown geometry, without changing that component. This preserves Markdown wrapping/update behavior even if Pi's `/settings` assigns user messages a selected value while a project override leaves the effective setting different. Tool layout keys and file height measurement include P; a padding change cannot reuse old-width rows or stale panel hit bounds. No settings writes, polling or settings-input interception are added. Main input and its widget still use the independent **Editor padding** setting; the session footer and native renderers are not reframed by Output padding.

For component width W >= 2P + 4:

- Leave P exterior columns on each side, outside panel painting and click targets. At P=0 the stripe is at the left edge and the last internal padding cell reaches the right edge.
- The panel occupies W - 2P columns. Only its left border exists: a one-cell `┃`, including on its top/bottom padding rows. No top/right/bottom border is drawn.
- Inside the panel leave one column after the left border and one column on the right. Content starts at zero-based column P + 2 and has width W - 2P - 3. Both internal columns belong to the painted, clickable panel; neither belongs to the content width. At default P=1 these are column 3 and W - 5; P=0 uses column 2 and W - 3.
- Add one panel padding row above and below the content. Paint the panel body, including internal padding, top/bottom content rows and the space after short content. The stripe cell and exterior columns keep terminal-default background. The stripe remains part of the logical panel/click bounds despite its separate paint.
- Transcript separation is owned by the adapter: one outside empty row when a visible preceding sibling exists; no duplicated separator, and no separator at width zero.
- Comments, command, output, hint and footer share the content origin. Do not copy OpenCode's additional title indentation, spinner, command/output truncation or content policy.

At width zero return no rows. When the normal frame cannot fit, keep at least one content column: allocate the remaining columns first to the border (up to one), then balanced internal padding (up to one per side, extra odd column on the left), then balanced exterior margins (up to P per side, extra odd column on the right). P=0 never reserves exterior columns. Never truncate commands to preserve decoration. Recompute geometry for every width and current Output padding. Callers wrap body text at the resulting content width; framing itself does not rewrap or silently clip body rows.

## Paint

Bash uses the active Pi theme at render time:

- Panel body (everything after the stripe): `toolPendingBg` for every execution state, including errors.
- Stripe background: terminal default for both ordinary and error states, not the panel color or a theme background token. Begin each frame row with an SGR background reset (`49`) so inherited background cannot leak into the stripe; render the stripe outside the body-background callback. Only its foreground changes on error.
- Ordinary border: `borderMuted` foreground.
- Final failed call (explicit user refinement): use `theme.fg("error", ...)` for the border foreground, exactly the same semantic role as the completion footer; do not use a background token as a foreground. Failure means final `isError=true` or a known nonzero persisted exit code, matching the bash footer. Partial snapshots do not signal final failure.
- No hover highlighting or hover state. Pointer motion, focus changes and moving between cards do not alter panel paint or request Toolview redraws. This is an intentional deviation from the OpenCode reference, accepted after unstable hover behavior.

Terminal-default synchronization can change the meaning of SGR 39/49 without updating Pi's cached concrete colors. Diff RGB arithmetic and the input half-block use Toolview's latest requested/reported concrete projection, while native semantic paint and Theme objects stay unchanged; local off samples released profile defaults when needed for the remaining presentation. See the [terminal-color contract](terminal-colors-spec.md).

The frame receives paint callbacks instead of selecting theme roles or inspecting execution state. The border callback styles only the stripe foreground; the panel callback receives only body/internal padding, never the stripe. The frame owns the leading terminal-default background reset. Native child styles are shallow ANSI wrappers, not a background stack: after standalone SGR `49` (background reset) or `0` (full reset), the frame reapplies the caller's panel paint to the following fragment. Preserve the original reset, child background/foreground styles and geometry. This keeps empty split counterparts and internal padding panel-colored without painting the stripe or exterior margins. The user-message presenter supplies its own paint without changing the geometry implementation. Real Pi 1.0.0 verification must check that the failed stripe foreground equals the displayed error footer, ordinary border stays `borderMuted`, stripe background is default and panel body remains neutral.

## Pointer behavior and lifecycle

An expandable card means hidden output exists, or expanded available output can be collapsed. All panel cells, including its border, internal padding, command/comments, footer and top/bottom padding rows, are click targets for that card. Exterior margins and the outside transcript separator are not. Empty/nonexpandable cards are not interactive. Neither expandable nor nonexpandable cards have hover paint.

Toggle only on a normalized primary-button click and only when Pi has no active text selection. Leave press, drag, release, wheel and secondary-button handling to the host; do not capture input. Ctrl+O and regular-mode keyboard behavior remain native. The host generates clicks separately from selection drags.

Toolview does not observe raw terminal input, add input listeners, replace `handleViewportInput`, capture the actual renderer receiver with a probe, or keep pointer state. Native input processing and mouse/focus consumption are entirely Pi's responsibility. The sole adapter patches tool `render`/`handleMouse`, user-message `render`, stock-editor presentation/normalized mouse hooks, and `Container.addChild`/`removeChild`/`clear`; owned `Container.render`/`Spacer.render` observers measure the native upper-widget group without another widget render. Tool UI `updateArgs`/`updateResult`/`setExpanded`/`invalidate`, the UI notification `markExecutionStarted`, and user UI `rebuild`/`setOutputPad`/`invalidate` retain native behavior while managing custom layout/animation lifetime. Starting execution does not itself invalidate the cached summary. Tool execution is not intercepted. See the [component-owned render-cache contract](render-cache-spec.md). Mouse events already normalized by Pi reach the card's click handler; non-click events return without modifying the card or requesting render.

Widget factories expose Pi's stable TUI reference. Public method/child access through this reference is sufficient; no descriptor writes to the TUI instance or private input-method compatibility checks are needed. The narrowly scoped stock-editor descriptor changes are documented [below](#main-input-editor). Pi may replace its renderer through native TUI-mode settings while retaining transcript components and the stable reference. Existing prototype rendering/click hooks and normal child attachment tracking continue to work without receiver migration or input-hook rebinding. Off, failure, reload and shutdown restore only Toolview's owned tool/user/container hooks, respecting later owners. There is no hover-specific cleanup path.

## User-message cards

Ordinary native `UserMessageComponent` instances use the same geometry and terminal-default stripe/exterior background as Bash. Use `customMessageLabel` for the stripe foreground and `userMessageBg` for the panel. Retain native `userMessageText` and semantic Markdown foregrounds/attributes inside; do not recolor syntax or links uniformly. No Bash command prefix, title, footer, truncation, expansion, spinner or hover behavior applies to user cards. Custom/skill/branch/compaction/assistant messages and separate image attachments remain native.

The sole adapter identifies and validates the current user-component contract, without importing private classes. The native component has one public-host `Markdown` child, numeric horizontal padding and one vertical padding row per edge. Ask its original renderer for content width plus twice its native horizontal padding: native Markdown and its registered transformers then receive exactly the frame's content width. Remove only those known geometric padding rows/columns with ANSI-aware column slicing, not whitespace trimming or source re-parsing. Keep full Markdown output, literal escapes, ordered-list numbering, syntax highlighting, links, Unicode and interior empty rows. Do not mutate the component, its children, text, native padding or Markdown options to render a card.

Move the native OSC 133 start and end/final zones to the new top/bottom padding rows, preserving their order and keeping transcript separators outside them. Empty native output stays empty; width zero paints nothing. Reuse an already supplied native blank separator; otherwise add one outside row after a visible predecessor. Cached predecessor metadata avoids recursive user-card rendering.

Native Kitty/iTerm2 image-protocol rows and native wide glyphs that cannot fit the tiny frame content allocation delegate to the original renderer at the real width, without clipping or disabling other Toolview presentations. This preserves upstream rendering, including upstream tiny-width limitations; actual graphical-terminal display is not an emulated acceptance claim.

User cards add no mouse handler, input interception, clock or stateful pointer paint. Native selection/copy and tool keyboard expansion remain native. Restore user rendering/invalidation descriptors only while still owned by Toolview. Persistent wrappers are created in a prototype-only scope, never the first user's installer scope. Weak user-component state owns its latest layout strings, without budget/count eviction; global accounting retains only numbers and weak entry references, never a user, parent, Markdown component, rendered string or callback. Native container removal/clear releases removed user layouts immediately. See the [cache contract](render-cache-spec.md).

Acceptance requires actual-SDK native Markdown comparison, tiny/zero/empty cases, native padding rebuild/invalidation, weak first-installer collection, compatibility failure/later-owner restoration and exact work counters. Real CLI controls compare full native body text and every painted glyph's foreground/attributes at equal content widths, all frame background/margin/stripe cells in dark/light, actual selection/copied text, Ctrl+O, 24/60/100-column resize, off/on/reload, fullscreen/regular replay, exact user/model/session bytes and unchanged Bash/summary behavior. Protocol fallback is a component guard test, not graphical-terminal coverage.

## Main input editor

The plain stock `CustomEditor` uses the user-message frame paint: `customMessageLabel` stripe, `userMessageBg` panel and `userMessageText` literal input. No prompt glyph or horizontal border is added. Source indentation and literal `>` remain source. Native inverse-cursor/selection styles remain semantic; input is not Markdown. Autocomplete stays **below**, outside the input panel, aligned with its content origin. A separate public `belowEditor` widget follows the editor; both of its rows are hidden while the native autocomplete list is open. The widget precedes the footer slot; the [session-footer contract](footer-spec.md) describes Toolview's separate footer replacement and its shared stock-input ownership gate.

Pi's **Editor padding** (`editorPaddingX`, UI values 0–3) sets the exterior horizontal margin of the **whole input panel**, not its internal text gap. Both margins equal the current native `getPaddingX()` value; keep one painted inner column after `┃` and one on the right at every value, including zero. For a fitting width W and padding P, the stripe starts at P, text at P + 2, panel width is W - 2P and text width is W - 2P - 3. Zero is flush with the component edges without joining text to the stripe; one preserves the former appearance. The below-editor metadata row and half-block edge use the exact geometry snapshot from that editor render; autocomplete shares its text origin outside the panel. Native settings changes apply on the next ordinary render without reload, text transfer or settings writes by Toolview. Internal vertical padding, footer and transcript cards remain unchanged; the optional outside upper-widget separator is described below. If the requested margins leave fewer than two text columns, delegate to native at the actual width rather than silently reducing margins or creating an oversized native render.

Keep the same editor instance and editing engine; do not construct a replacement, transfer drafts or wrap keyboard input. Toolview narrowly wraps public-imported stock `CustomEditor` presentation and forwards normalized mouse coordinates to stock `Editor.handleMouse`. Native activity routing additionally uses same-default public `setEditorComponent(undefined)` rebinding, not a foreign factory: the same editor must remain attached. Pi's redundant synchronous `getText()` → `setText()` self-transfer is suppressed only during that call; otherwise it would reset cursor/undo/history and turn expanded pastes into literal markers. Restore the exact setter descriptor and existing public focus in `finally`. Editing methods otherwise remain native; text, paste/image maps, cursor, undo/history, app actions and autocomplete provider are unchanged. Host-native reload/state behavior remains Pi's responsibility, not a new state-migration promise.

Eligibility requires the exact public stock prototype, its exact shared `Editor` parent, native rendering/mouse methods and Toolview-owned border hooks, native padding/text methods and a writable border-color callback; check ownership every render/mouse visit. An explicit public editor factory, subclass, instance presentation override or preexisting renderer owner remains native. Actual CLI checks establish public class identity rather than relying on class names or remembered SDK shape.

This is an **input and session-footer ownership boundary**, not a package-wide incompatibility rule. If another extension installs or replaces its own editor (including `pi-powerline-footer`), Toolview leaves that editor and its appearance under the owning extension's control. Here native fallback means retaining that extension's existing presentation, not replacing it with Pi's stock editor. Toolview does not disable the extension, take over its editing behavior or compose arbitrary editor renderers. Tool and user-message cards remain independently eligible under their existing safeguards. The session footer requires the same recognized input owner: when input ownership is lost, restore stock only if our footer is still owned, never overwrite a later foreign footer. Footer-only extensions that do not replace or override the editor are not excluded by this rule; full package compatibility and arbitrary shared-method overrides are not guaranteed.

Render the native engine at the frame content width plus native padding (or one native cursor-reservation column when padding is zero). This also sets native wrapping/navigation geometry. Project only its known padding; never rewrap draft strings or read private editor layout/scroll/paste state. Top/bottom native border hooks return internal zero-column sentinels during that single projection, establishing the autocomplete boundary without recognizing glyphs in input. Replace those rows with panel padding, retaining native upper/lower overflow labels. With the below-editor widget enabled, Pi renders activity in its separate native status container above the input; the panel retains the native base border and its overflow information. Remove `─` only from call-local stock `borderColor` **decoration fragments**, not status/source strings; restore its exact own descriptor in `finally`. Status literals use independent native indicator callbacks.

Keep native editable/menu row counts unchanged. The adapter may prefix one outside upper-widget separator without changing the native editor's text/menu counters. Translate normalized mouse x/y and width/height to the same native geometry, subtracting the actual zero/one-row prefix and leaving its empty row noninteractive. Preserve event kind/modifiers/screen coordinates and native response; do not capture raw input or add pointer/keyboard listeners. The native end cursor may consume the existing internal right-padding cell, never the exterior margin. Keep `CURSOR_MARKER` for hardware cursor/IME positioning. Column slices close native attributes explicitly so a clipped end-cursor reset cannot invert exterior margins or later rows; reapply user text/background after full resets. Width zero emits nothing; widths 1–6 stay native to avoid requesting a one-column layout from Pi's wide-glyph wrapper. Other impossible glyph/cursor projections and configured padding larger than the real component width also fall back at the real width; never materialize unbounded native padding to decorate a narrow editor. Native tiny-width limitations are not repaired.

Input/widget rows have no Toolview rendered-layout cache, animation clock or strong editor ownership. Weak state contains last painted geometry and zero/one-row mouse offset, native status-group width/nonblank observations, upper-group width/content-height observations with weak spacer identity, restorable public flag descriptors, and call-local projection/spacer packets, never retained draft/widget rows or native indicator objects. Git metadata uses the separate event-driven source described below. The widget uses a weak reference to the recognized stock editor and requires current painted geometry before showing rows. Footer eligibility uses that same weak identity without requiring attachment during a temporary native selector. Native editor rendering/cache and working-indicator animation continue independently. Off/failure/shutdown/reload restore only still-owned prototype descriptors, including deleting originally inherited methods. New default editors are discovered through the existing attachment hook. First-installer GC must succeed while the adapter remains active.

Acceptance includes real stock SDK expanded-paste maps and atomic programmatic text insertion, undo/history/app shortcut identities, full-line cursor preservation, live exterior-padding values 0–3 and impossible-margin native delegation, scroll/status literals, native-menu click routing, instance/subclass/factory/later-owner guards and exact paint/descriptor/failure restoration. Actual CLI controls cover both terminal modes, physical dark/light cells, CJK/combining text, 24/60/100-column resize, normalized input clicks, keyboard undo/completion, large-paste expansion across off/on, actual `/settings` padding changes and persistence without reload, fixed inner gaps and end cursor at every margin, stock identity, reload on empty input and unchanged submitted/model/session text. Headless verification establishes the hardware marker and painted cursor geometry, not an operating-system IME candidate-window test, clipboard-image callback test or graphical image insertion.

### Upper-widget separator

For the eligible framed stock editor, prefix exactly one fully empty, unpainted row when the native **upper** widget group supplies content rows beyond its stock leading spacer. This row belongs to the editor's returned block and immediately precedes its existing painted top padding; widget insertion/update order cannot move a widget between the row and panel. Do not add a separator widget, change foreign renderers, move Pi's own leading spacer, or remove the panel's internal padding. No upper widgets, registered widgets returning zero rows, and lower-only widgets add no editor-local separator. Multiple upper widgets share one separator. A widget changing height on ordinary renders updates this decision without unregistering it, polling or timers.

The optional feature depends on a guarded host layout: seven managed public root children in document/pending/status/upper-widgets/editor/lower-widgets/footer order; plain shared containers; the stock editor alone in its input container; owned stock group/spacer render methods. Both current native modes retain these managed children, even though fullscreen paints a separate dock. Observe the group's ordinary `Container.render` result and the first stock `Spacer.render` result in that call; the spacer must supply exactly one empty row. Retain only weak-keyed width/content-height data and weak spacer identity, not foreign rows/owners. No foreign renderer is invoked again to decide spacing, and no private registry, spacer field or allocation hook is read. Width, tree shape, leading spacer identity and ownership are revalidated. Unknown layouts, replaced methods/spacers or unavailable measurements omit this optional separator without guessing or disabling the independently eligible panel/cards. Off/failure/shutdown restore only still-owned observers; transient spacer packets clear in `finally`.

Zero height means zero returned widget rows, not parent allocation/clipping at a short terminal height. The separator is an editor presentation row and follows native editor clipping; no height heuristic or allocation-aware visibility promise is added. Preserve the native cursor marker and subtract the actual prefix from normalized mouse y/height so text and autocomplete clicks still reach their native rows. Native editing state and its private visible-line/menu counters remain unchanged.

SDK compatibility gates use the actual native widget methods and fullscreen composition, explicitly checking the stock spacer, dock order, upper-before-editor rendering and matched native widget call counts. Real CLI controls assert the separator is actually active and immediately before input in both modes and after renderer replacement; an unknown-shape production fallback must fail those supported-host tests, not silently pass an upgrade. They cover absent/zero-height/lower-only/multiple widgets, live height transitions, exact default-color empty cells, cursor/menu clicks, off/on/reload/replay and active first-editor/upper-group collection. These gates detect the inspected contract changing; they do not promise compatibility with every future Pi layout.

### Below-editor metadata, working directory and native activity

One public `belowEditor` widget normally supplies two noninteractive rows; its public `isShowingAutocomplete()` check returns zero while the native suggestion list is open. Pending requests and empty results do not hide it. Ordinary native renders restore it after completion/Escape; no polling or menu lifecycle interception is added. Pi places the widget after the complete editor and before the existing footer. Metadata/edge clipping follows normal widget allocation, without height heuristics or private allocation hooks. **Native activity is independent of this widget and remains in Pi's separate container above the input, including during autocomplete.**

- Row 1 shares the editor's current exterior margins, stripe, fixed inner gaps and panel paint. Its left block is `<model.name> (<provider id>) • <thinking level>` and, only at idle, ` • Idle`. The model uses `mdHeading`; provider uses `muted`; balanced parentheses and bullets use `dim`; thinking uses `thinkingOff/Minimal/Low/Medium/High/Xhigh/Max` (unknown levels use `thinkingOff`); Idle uses `muted`. Preserve the provider ID, with no aliases. No model uses `No model` / `—`; keep `off` explicit. Read current context each render.
- Append Idle only when `ctx.isIdle()` confirms idle and the normally rendered native status group has no nonblank output at that width. Busy/hidden activity has no suffix. The observer consumes ordinary native rows without extra renders or parsing status kinds; retain only width and visibility. Working/spinner/retry/compaction/future native messages never enter this widget.
- The right block is `<ctx.cwd>:<git branch>` with exactly one painted right-padding cell, already supplied by the shared frame. Do not add a second inset or change exterior Editor padding. Use the context directory, not a Bash `cd`, repository root or realpath substitution. Before width fitting, replace the native home directory (`os.homedir()`) by `~` only for that directory or a separator-bounded descendant (`~/…`, with the native separator on Windows); a merely matching name prefix remains unchanged. This is display-only: Git, context and saved data keep the original cwd. Strip non-root trailing separators for display. Sanitize terminal controls without altering the real directory used for Git. Parent path/separators use `dim`, the last directory uses `mdLinkUrl`, `:` uses `muted`, and branch uses `text`. An ellipsis has its omitted part's color. Filesystem/drive/UNC roots are an indivisible last element, not an empty name.
- Row 2 remains `╹` plus upper-half blocks `▀` across the panel body: stripe foreground for the corner, concrete active `userMessageBg` foreground for the blocks, terminal-default background and exterior margins. Close inherited attributes. Footer and other cards are unchanged.

#### Width allocation

Fit plain grapheme sequences by **terminal columns** before applying semantic colors. Never split a grapheme or include ANSI bytes in width. Metadata values retain their bounded sanitization; directory/branch fitting preserves the last path element rather than applying a generic prefix cap. The two blocks have at least two spaces between them when both are present.

If the full left and right blocks fit, keep both. Otherwise reserve the idle label first (up to four columns); it is absent while busy. Reserve the two-column inter-block gap and divide the remainder equally: the left receives the odd column. The left allocation includes its metadata plus the separator before Idle. If either full block needs less than its share, give its unused allocation to the other. Shorten/drop provider, then model, then thinking within the left allocation, retaining balanced provider parentheses. If the right block disappears, recompute the left using the whole content budget; no unused inter-block gap remains. Very narrow idle-only layouts can shorten Idle using the existing ellipsis rule. Working has no reservation here because its native container is separate.

#### Ordered directory/branch reduction

Start each fit from the original sanitized path/branch, never an already-shortened result. Stop at the first stage that fits; skip transformations that save no columns. A branch already shorter than a stage's minimum is not expanded.

1. Reduce the **middle of the parent path**, retaining the root, first parent directory and full last element. The limiting form is `/home/…/name`, or `~/…/name` below the home directory (native separator for Windows). Preserve prefix/suffix around one ellipsis, approximately balanced by columns, with the extra column assigned to the prefix.
2. Reduce the branch in its middle, retaining prefix/suffix, down to **five columns including the ellipsis**: e.g. `fe…us`. Apply only enough reduction to fit if five or more columns suffice.
3. Replace the remaining parent prefix in one step by `…/`, preserving the complete last element. Do not display fragments of the former anchor.
4. Further reduce the branch in the middle. A shortened branch requires at least one real grapheme plus `…`; never show an ellipsis-only branch. When it cannot fit, remove both branch and `:`.
5. Remove the `…/` prefix, giving those columns to the complete last element.
6. Shorten the last element from the **right**, keeping its beginning plus `…`.
7. Hide the entire right block if neither the complete name nor at least one real visible grapheme plus `…` fits. A sole ellipsis is not useful directory information.

For odd budgets and wide graphemes, preserve the largest fitting prefix/suffix without breaking a grapheme, assigning spare columns to the prefix; unused columns are harmless. Repeated resizes must deterministically recover the full original value.

#### Git source and refresh

Ask Git whether this directory resolves to a repository; `.git` existence is not proof. Use `git -C <cwd> symbolic-ref --quiet HEAD` and accept only a successful `refs/heads/<name>` result. Nested working directories, linked worktrees, submodules, bare repositories and unborn branches are supported by Git's own discovery. Detached HEAD, missing Git, unsafe-directory/access errors and unsupported/corrupt data omit branch and colon; do not invent a hash, `detached`, or a guessed branch. Remove Git's reported repository-local environment variables (including case-variant keys for Windows environment semantics) from subprocess environments so `GIT_DIR`, `GIT_WORK_TREE` and similar redirects cannot select another repository. Do not change process environment or global Git configuration.

Git runs asynchronously **outside render**. Retain one current cwd/branch snapshot; coalesce overlapping refreshes, cancel on cwd/lifecycle changes and ignore late replies from an older generation. Refresh on initialization/session/cwd changes, completed tool/agent operations, and filesystem changes in Git-discovered metadata directories. Directory watches cover atomic HEAD replacements and available reftable directories, not only an individual `.git/HEAD` inode. Every rediscovery closes/rearms watches against the current directories; pathname equality is not proof of inode identity after same-path `.git` replacement. Read HEAD after discovery/watch installation, so a queued event for a closed old watcher cannot leave a pre-rearm branch snapshot published. Missing/watch-failed metadata still refreshes on semantic events. For a non-repository, watch the cwd's `.git` entry; repository creation in an unobserved ancestor is discovered at the next semantic refresh, not promised immediately. No polling or permanent refresh interval. Event debounce and child deadlines are bounded one-shot timers, not animation clocks. Pause/close source resources when native input ownership is lost, Toolview is off, failed or shut down; ordinary frames and native animation must start zero Git processes.

#### Native activity routing and ownership

Pi owns the indicator instance, text, kinds, styles, animation, visibility preferences and disposal. For the eligible default editor only, Toolview installs a restorable accessor on the public `embedWorkingStatus` field, returning false while ownership is recognized. The supported SDK exposes this TypeScript-readonly option as an own configurable writable boolean field; immutable/unknown fields leave input native and omit metadata. Same-default public rebinding asks **Pi** to relocate an already-active object; do not disable/recreate/reparent it, read private indicator fields, copy rendered fragments, or recognize names. Preserve the complete draft state by suppressing only the redundant synchronous self-transfer described above. The native API must keep the same default editor and perform the inspected single self-transfer; actual SDK compatibility tests fail on changes to these assumptions. Rebind only a mounted recognized main editor, not an active selector; deferred normal attachment can finish routing afterward.

Foreign factories/subclasses/instance renderers remain entirely native, with no Toolview panel/separator/metadata/edge or Git source activation. The public flag falls back to its original value when stock ownership is lost. Off/failure/shutdown restore only owned flag/method descriptors and native activity placement through the same guarded native rebinding; preserve the active object and clock. Later owners' replacements are never overwritten. The input feature adds no editor factory replacement or footer takeover (the input-dependent footer feature is specified in [its own contract](footer-spec.md)); no private operation lifecycle, indicator animation timer, raw input hook or private viewport counter is added.

Acceptance requires pure width/color/Unicode/root/stage controls; actual SDK same-editor paste/cursor/undo/history/focus and native unknown-kind/clock on/off controls; guard/descriptor/later-owner/GC coverage; real Git repository/environment/watch/replaced-metadata/cancellation and zero-hot-frame-process counters; physical regular/fullscreen alignment, colors, spacing, menus, busy/idle/native visibility, settings/themes/resizes, off/on/reload/replay and strict traffic/session equality. Native activity clipping follows native placement, not belowEditor. Supported SDK activation tests must fail rather than accept silent fallback after host contract changes.

## Acceptance gate

Follow the shared [testing and coverage guide](testing.md). Frame geometry and integration regressions must independently verify exact exterior margins, panel bounds, content origins, wide/narrow wrapping, unpainted margins, neutral panel body in all states, terminal-default stripe background in ordinary/error states including inherited-background and tiny-width cases, failed stripe/error-footer foreground equality, steady neutral paint under motion/transfer/focus, no Toolview motion redraws or native input-method changes, whole-panel clicks, nonexpandable/selection/drag/wheel guards, resize, native fullscreen/regular renderer replacement and cleanup. Reconstruct complete long commands from actual screen cells at multiple terminal widths in fullscreen and regular mode, preserving every character and checking both internal/exterior right-side columns; manually calling a component at the viewport width is not sufficient evidence of physical-screen width. Existing summaries, native opt-out/compact override, hidden/image safeguards and strict model/result/session equality stay unchanged. Installed AFT execution remains outside the safe test profile; representative metadata tests are not claimed as installed-AFT coverage.
