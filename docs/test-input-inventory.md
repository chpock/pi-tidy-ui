## Current capability boundaries

The five execution roots are `product/`, `integration/`, `cli/`, `harness/` and `native-build/`; see the [folder guide](testing.md#test-layers). Product tests, including pure contracts under `product/native/`, need no real service (controlled subprocesses/GC remain valid). `integration/native/` and `cli/native/` require verified same-source `native`; `cli/shared/` adds `shared`; `integration/profile/` and `cli/profile/` require the locked profile (`integration`). `harness/packaging/` is Pi-sensitive ordinary Node coverage, distinct from once-per-Node inert `harness/delivery/`. The two fixed consumer scripts retain explicit interfaces: ordinary `consumer` requires `native,registry`; `published-consumer` requires extension-tag/public-network authority. Rust product commands use prepared pinned Rust; `tests/native-build/` instead uses the Pi-free `prepare-native.mjs` descriptor and native runner/bootstrap, before stamping. `test:rust-harness` and its Make counterpart require these native-build inputs, not a general Pi descriptor. Missing prerequisites are setup failures, not skips.

Source-only refresh validates the owned graph and copies no dependency files; changed manifests/lockfiles, graph bytes, Node/host or native provenance require appropriate preparation. Local feature groups/filters and the 2–3-minute feature-loop target do not define CI selection. Every ordinary main push/PR/manual runs all enabled platforms and both Nodes × minimum/once-resolved latest Pi. Nightly at 03:23 UTC is best-effort latest-only SDK compatibility and complete four-shard CLI on both Nodes, with only a Linux x64 Pi-free producer prerequisite, no native consumers/minimum profile/other-OS/delivery. See [fixed CI obligations](testing.md#fixed-ci-obligations) for tag gates, distinct results and exhaustive shard rules.
