# Render cache and UI performance

This specification defines retained layouts and per-frame work. Execution, model content, session data, native hidden/image guards and normalized input remain unchanged. This supplements the summary, Bash, edit, write and shared-frame specifications.

## Work per frame

Pi requests whole-document layout for arbitrary UI updates, including its working animation. pi-tidy-ui must not rebuild unchanged custom content in those frames. Cache custom summary/Bash/edit/write/user/queued body rows and Bash geometry/expandability separately from transcript separation. Neighbor separation uses cached content metadata; an eligible Bash card's existence/multiline classification never requires formatting its output. For edit/write cards, read an exact existing layout or perform uncached validation-only classification (exact inline heading height, multiline frame class); a retention miss must not rebuild/highlight/paint the diff merely to determine separation. This introduces no additional retained data or cache policy. Record child positions on attachment/initial traversal, with an O(1) position check and lazy repair after structural changes, instead of a fresh sibling index search per rendered call.

Each tool/user/queued component owns at most its latest custom layout width/state through weak component state. There are no byte/count limits, admission skips or recency evictions. The `ordinary` and `cards` groups provide accounting only, not globally owned layout retention. Width or Output padding changes rebuild that layout once, not on every frame. Preserve safe actual-width bounds and click coordinates rather than returning old wider rows. No width-history cache, cache-maintenance polling, debounce or suppression of host frames/streaming. The sole execution-only fallback deadline is specified below. Unknown self-render visibility continues to be checked at the actual width. One proven exception is the stock Pi edit renderer, identified each visit by exact call/result function identities from the public SDK factory, the verified component contract and a current plain call Box with stock render/clear/addChild methods: it supplies a heading, so custom edit summaries/cards and their spacing need no native row construction. A name alone never qualifies. Native overrides, expansion, images/hidden guards, custom/mixed/missing renderer getters and malformed fallback retain native behavior. No visibility/height retention layer is introduced; existing layout row counts/classification serve spacing. Completed compact rows without an outside separator are returned directly rather than copied.

Cache hits are not free whole-document frames: Pi still assembles/traverses its transcript, unknown self renderers may perform native visibility work, and separator/spinner composition may allocate arrays. Native updates, edit preflight and selection rendering also remain host work. Cold/width/theme builds prepare full required content by design; no off-screen/source-context shortcut or total-process-memory guarantee is implied. See [architecture](architecture.md#cache-separation-and-animation) for the common rendering boundaries.

### Terminal-default projection

Terminal-color synchronization has one latest requested/reported numeric snapshot and one concrete-color projection, outside transcript accounting groups. It retains no tool/editor owner or width history. Native theme revisions and explicit retries queue source work outside render; unchanged ordinary/Working frames repeat no source read/report/projection/output. Local off stops metadata/application but can sample released profile RGB for remaining cards. Automatic mode adds no feature reports. The zero-row observer and one-shot public query deadlines are not a repeating clock. See the [terminal-color contract](terminal-colors-spec.md).

### Session-footer snapshot

The footer is outside transcript accounting groups. One latest numeric/context snapshot retains at most ten primary assistant cache reports (numbers/unknown slots only); one latest width/theme/data/status layout retains prepared rows. Reports are derived from saved records during ordinary semantic refreshes, never appended by render or deduplicated by percentage. Identical CH values from separate requests advance history. Reload/replay/off-on reconstruct it without extra persistence or requests. Warm/Working frames add zero reports and repeat no usage aggregation, entry/history reads, context calculation or layout build. Theme/width/status changes fit the existing snapshot, including one-row ellipsis, without altering history. Hidden cost performs no auth reads. See the [footer contract](footer-spec.md).

### Queued-message preparation

Native pending-message `TruncatedText` items each weakly own one latest full framed plain-text layout plus at most five prepared ellipsized ending rows. These are ordinary `queued` entries, not a new queue or a height-history cache. Guards compare width, effective Output padding, theme/callback/color identities, native text and the last item's native edit-all hint. Warm renders only check the small native prefix and select/assemble already-painted rows; height-only changes rebuild no body. The global soft row budget and 5→1 first-to-last selection are specified in the [queued-card contract](card-frame-spec.md#queued-message-cards). Native queue reconstruction/removal/clear, cache clear/off and owner collection release preparation; a retained first installer or removed owner must not retain its layout. The adapter must still execute native Container rendering with its projected child rows, so Pi refreshes its own strong child-reference snapshot as well as hit geometry. GC controls include native rendering before pi-tidy-ui activation and a later nonempty queue rebuild; custom-layout release alone does not prove detached native owners collect. Saved-row statistics include all full/ellipsis rows, even when the projected block is shorter. This is display clipping, not a new memory cap, background worker or render timer.

### Main input exclusion

The stock main editor is not a transcript-layout cache consumer. Each render projects already-rendered native visible rows into the shared user frame; no draft strings, paste maps, providers or editor layouts enter transcript retained layouts. Its weak adapter metadata records only current native width/mouse offset and a call-local border packet. Native wrapping/rendering and working-status animation remain host work; no pi-tidy-ui editor timer, invalidation subscription or warm-frame zero-work claim is introduced. Off/on preserves the same edit engine rather than exchanging text with a replacement. See the [editor contract](card-frame-spec.md#main-input-editor).

## Execution spinner

Use one adapter-owned, unreferenced 100 ms **inactivity timeout**, not a periodic interval. Participation starts only when an attached, displayable compact call is rendered after actual execution starts. Argument streaming, completed/history calls, zero-width or native-zero-row calls, expanded/native/image tools, and default Bash/edit/write cards start no animation resource. There is no idle/background housekeeping timer.

### Why host-driven animation needs a fallback

Pi's native `Working` animation already requests whole-document frames, normally every 80 ms. A second periodic timer would ask Pi to traverse the same history merely to animate another glyph. Conversely, skipping the entire pi-tidy-ui tick whenever Pi is active would freeze a tick-count-based glyph. Therefore presentation phase and frame scheduling are independent:

```text
render a compact prefix -> choose the frame from elapsed monotonic time / 100 ms
successful document visit -> move the one fallback deadline 100 ms forward
100 ms without another visit -> request one ordinary host render, then await its document visit
last participant leaves -> cancel the deadline and clear animation state
```

One adapter-wide epoch starts with the first participant. Sample monotonic time once for each normal document pass so parallel prefixes agree even during a slow pass; direct tool visits use live time. Compose the first-row glyph outside the retained logical layout. Cached rows keep fixed prefix-offset metadata only, never a phase, node, timer or callback. Starting execution changes only the glyph and retains the logical summary; native `markExecutionStarted()` still executes unchanged.

Reuse the existing owned public `Container.render` observer and its normal transcript-pass boundary. Rearm only after a successful return, not on `requestRender()`, individual tool renders, unrelated containers or a throwing document pass. Arm once after a normal pass, not once per participating tool. Direct tool renders can start participation but cannot acknowledge/postpone an existing deadline. Once a fallback requests a frame, retain a pending bit and queue no further deadline until the next successful document visit: a delayed/stopped host must not cause repeated requests. The next deadline is relative to that visit, including visits requested by pi-tidy-ui itself, avoiding the approximately 200 ms fixed-interval phase problem. A generation guard rejects callbacks from cancelled/replaced deadlines or a disposed adapter. This is not a precise 100 ms physical-screen cadence; host scheduling/render delay remains host behavior.

There is no public after-present event in the supported Pi API. A successful document visit is an observable layout signal, **not proof that Pi emitted those rows to the terminal**. Direct document diagnostics can also postpone fallback, and a later host failure is not observable at this boundary. This accepted best-effort limit must not be described as exact completed-frame detection. Read no private `Working`/Loader timer, timestamp or renderer state; wrap neither `requestRender()` nor native `doRender`, add no core changes or direct terminal writes, and leave native animation/lifecycle untouched. See [architecture](architecture.md#host-driven-spinner-and-fallback).

Keep only weak references to the small set of running painted calls. Timeout wakes and successful document visits prune that set and its recorded ancestor attachment edges, never traverse the full transcript for animation. Host-driven pruning matters because `Working` may prevent the fallback from firing indefinitely. Hidden/ineligible or detached calls leave on rendering/pruning; final results, expansion and owned subtree removal/clear remove them immediately. Stop the deadline and pending/epoch state when the last call leaves. Off, failure, shutdown and reload do the same; no subsequent animation request is made, without claiming to undo a render already forwarded to Pi. Stable-reference renderer replacement uses public children, with no receiver probing or private input hooks. Timeout callbacks are constructed outside component-installer/`animate(node)` scopes so they do not retain an installer through a shared closure context.

Native `Working` frames and fallback frames rebuild no unchanged argument formatting, wrapping or neighbor metadata and globally invalidate nothing. Partial updates preserve participation; final failures retain normal error color after animation ends. Verify zero added requests under regular 80 ms host visits, live-time prefix changes without fallback wakes, one request per eligible fallback wake, no duplicate while pending, successful-return-only rearming, same-pass phase, stale callback rejection, and no idle redraws. Retain all prior hidden/image/native/zero-width, final/expansion/off/failure, detached-subtree, renderer replacement, native partial/full, cancellation/reload/replay, strict traffic/session and active-first-installer GC controls. Real CLI controls in regular/fullscreen mode must use the public one-frame `Working` configuration to stop native animation, prove physical fallback movement, then restore native animation and prove suppression again.

## Invalidation and ownership

Use weak component keys for state; that state owns the latest rendered value. Global accounting may retain only numeric metadata, a fixed presentation kind and a weak entry reference, never a component, parent tree, rendered rows, argument/result object or closure capturing those objects. Invalidate custom layout when Pi updates args/results, sets expansion or invalidates the component; mutation inside a reused argument/result object is supported through those existing host methods. Tool layout signatures include effective Output padding independently from viewport width. One plain settings value is scoped to each normal transcript-container render pass, so public effective-settings cloning is not repeated per tool or predecessor; direct component/mouse visits read the current setting. The scope clears in `finally`, not on a timer. User cards guard both effective exterior padding and native component padding: the latter still controls native Markdown width/stripping and may differ after a project-overridden setting change. Edit/write layouts retain rendered rows/frame classification only, use the same argument/result/expansion/width/Output-padding/theme/`cwd` invalidation, and perform no custom syntax highlighting or diff wrapping on warm frames. User layouts are component-owned in the ordinary accounting group, with weak user-component state and guards for width, theme/paint callbacks, text, padding, native Markdown-child identity/theme/transformers. Native `rebuild`, `setOutputPad` and `invalidate` discard their custom layouts; all native methods still execute. Warm user frames call neither the native renderer nor its Markdown transformations. Native user selection/copy may independently render Markdown, outside pi-tidy-ui's cached-frame work. Retain native method execution and restore only pi-tidy-ui-owned wrappers on off/failure/shutdown/reload. State/width/theme-identity guards also cover direct field replacement, status/expansion changes, and Bash command/description/workdir/context changes. Arbitrary silent mutation of nested JSON without a host update/invalidate is outside the renderer contract.

Retention is runtime-local. Clearing replaces weak state maps and clears every live entry's value/accounting; off/failure/shutdown do the same. Owned native `Container.removeChild` and `clear` wrappers release custom layouts throughout detached subtrees immediately, even when the host or another caller still holds removed components, and stop their compact animation. A node already moved to another attached parent is not discarded. Restore only still-owned child-lifecycle wrappers. Weak state otherwise releases an owner's representation with owner collection. A `FinalizationRegistry` removes only dead numeric/weak accounting records; it never holds rendered data or owners, and layout collection does not depend on callback timing. On-demand snapshots additionally prune already-collected records. There is no GC polling, housekeeping timer, old root retention or orphan rendered-data list.

## Memory accounting and controls

For Bash syntax, cache identity includes the canonical compatible **display-effect stamp**, not source version, job or lease status. Existing argument/result lifecycle hooks still detect actual content/phase changes; an unchanged layout signature and display stamp preserve the body. Historical-prefix projection occurs only on a cold build using the current normalized command, including the first changed frame before deferred native preparation. Waiting preparation and identical-style finalization add zero body builds and extension redraw requests; actual new text/geometry/style changes remain invalidators. See the [streaming contract](bash-streaming-contract.md).

There is no fixed retention budget. A live component keeps one latest custom body; replacing width/state/kind invalidates and releases its previous entry before storing the new body. Growing live transcripts necessarily retain more visualizations, like native `Text`/`Markdown`. Detached/collected-owner layouts and width/state history must not accumulate. A single large successful file/Bash card is retained too; no size-dependent warm-frame rebuild exception exists.

The `cards` group describes Bash frames, successful framed edit diffs and write source/diff frames. Compact lifecycle/forced-compact views, edit headings/native file fallback and user/queued layouts belong to `ordinary`. These are independent numeric accounting groups of component-owned data, not LRU pools. Classify the materialized view rather than its tool name; a component has one entry in one group at a time. `byKind` attributes layouts to fixed `summary`, `bash`, `edit`, `write`, `user` and `queued` categories in each group and their aggregate. No owner-name/source registry or logs are retained.

Estimated bytes use `512 + sum(64 + 2 * row.length)`: entry/accounting overhead plus per-row/array allowance and two bytes per retained string code unit, including ANSI. `stringBytes` and `overheadBytes` expose these two parts; `rows` counts saved visual rows and `entries` counts saved layouts. These estimates are not exact V8 allocation or unique-string ownership: native caches, raw/signature data, sharing and transient formatting are excluded. Do not copy raw output/args/results or retain multi-width history to produce statistics. Component-row retention has no whole-process-memory guarantee.

Optional commands, with no persistent settings writes:

- `/tidy-ui cache`: show transcript/queued aggregates, `ordinary`/`cards`, `byKind`, rows, estimated bytes/string/overhead, entries, hits/misses/builds, `releases` and GC-only `collected` accounting cleanups. Numeric transcript totals equal the two groups' sums. Lookup misses and body builds remain distinct: an unprepared neighbor can be measured without building a body. Footer rows are reported separately in `footerLayout`; `presentationRetainedBytes`, `presentationEntries` and `presentationRows` combine transcript/queued/footer layouts. Main-input/widget projections retain no custom rows. Process heap is sampled only on demand and explicitly labeled **whole Pi process**, not pi-tidy-ui attribution.
- `/tidy-ui cache clear`: release transcript/queued weak state/rows and the footer's latest layout; subsequent requested frames rebuild on demand. Invalidate/clear/disposal and collection cannot subtract the same entry twice; counters are finite cumulative numbers, not logs.
- Retired `/tidy-ui cache limit …` and `cache cards limit …` commands warn and change nothing. Legacy `--tidy-ui-cache-mb` / `--tidy-ui-card-cache-mb` flags are registered only for launch compatibility; any supplied value warns once per runtime and is ignored. No hidden zero/admission/count limit remains.

Keep `/tidy-ui on|off|status`, policy flags and non-TUI behavior. Memory control does not cap model/tool data or claim to free host-owned/native rendering memory. Cache clear does not itself recursively invalidate native tool contents.

Successful file cards show all available changes/source without a Bash-like preview or compact-text cap. Plain write bodies share the linear wrapping/highlighting path but calculate no Multiply colors. Validation-only write measurement checks source availability and metadata without materializing code, admitting another body or retaining classification. Missing diff uses submitted content; producer-side omissions cannot be recovered. See the [write contract](write-card-spec.md).

## Output preview

Collapsed Bash wrapping stops as soon as an eleventh visual output row proves overflow; it does not build all hidden visual rows. Use the first ten rows, then remove their trailing whitespace-only rows before the overflow hint without searching hidden rows for replacements. Preserve interior preview blanks and all expanded interior blanks, grapheme/tab/control safety and the expansion hint. The Bash spec's exact separated terminal duplicate exit-footer removal precedes wrapping/overflow and does not infer status or rewrite raw data. Expanded output is built only on demand and retained as that component's latest layout. Large layouts and changing large results can still require transient work/memory; component ownership prevents orphan/history retention, not total Pi heap growth or pathological raw tool data. Favor bounded preview work over exact hidden row counts: do not compute or display such a count.

## Verification

Follow the shared [testing and coverage guide](testing.md). Counters must prove unchanged frames do no custom body builds, updating one tool rebuilds only that tool (including reused mutable objects), cached neighbor checks do not rebuild earlier Bash output, and resize/theme/expansion/invalidate cause only necessary work. Test warm full-document scans beyond former count/byte limits, one latest width/state, oversized retained entries, exact category/group/aggregate arithmetic, clear/off/shutdown, immediate component/subtree removal while the owner remains held, rendered-value and accounting GC with an active adapter, restored/later method owners, reload and native renderer-mode replacement. Use actual SDK and real CLI captured traffic, native/off/replay controls and physical width/click/color checks; never replace strict body/model/session equality with approximate performance assertions. Optional diagnostic snapshots must have finite monotonic counters and accurately labeled estimated cache versus whole-process memory. Record observable work counts, not timing-only claims. Keep source-bound experiment/review packets under gitignored `.test-artifacts/`; do not turn historical run totals or superseded budget decisions into current guarantees.
